## 1. 产品需求

第一版是收盘后运行的命令行任务：对 20–50 只自选股计算风险等级与反弹阶段，把全部状态变化入库，按推送策略发出提醒，并生成待处置记录。它回答“发生了什么、证据是什么、收益分解如何”，不回答“为什么跌”和“会不会涨”。

### 1.1 用户与场景

| 场景 | 用户想知道 | 系统给出 |
| --- | --- | --- |
| S1 持仓股大跌 | 跌了多少（以自身波动衡量）？大盘、板块、个股相对部分各贡献多少？我的预案是什么？ | 风险升级提醒 + 触发数值 + 收益贡献分解 + 当时生效的预案动作 |
| S2 观察股止跌 | 跌势是否停下？是否满足我事先写的再买条件？ | 反弹阶段提醒（RB1/RB2/RB3），附当前锚点价与日期 |
| S3 反弹失效 | 之前的止跌信号是否作废？ | RB\_FAIL 提醒，原因为“跌破锚点”或“创新低” |
| S4 数据异常 | 今天的信号能不能信？ | 缺价、历史断点、复权回溯、代码变更提醒；受影响股票冻结并标注 |
| S5 复盘 | 我偏离预案多少次？事后如何？ | 实际操作表、提醒处置记录与季度统计 |
| S6 维护名单 | 加入/移出股票，填预案 | 命令行维护；加入前必须通过地域门（第 4.6 节） |

### 1.2 每日使用流程

1. 美东收盘后，最早在收盘 2.5 小时后（以所选数据源说明为准）启动；先做就绪检查（目标交易日存在、覆盖完整、质量通过），不满足则按第 6.5 节重试分类处理。
2. 完整重取所需历史，核对并发布新的数据版本（第 4.3 节）。
3. 计算简化大盘代理（第 2.6 节），作为第一版唯一的生产背景来源。market-risk 输出待 market-risk M3 后确认，接入方案另行批准前只作独立展示，不参与任何判定。
4. 逐股全量回放到 T，得到风险等级、反弹阶段与全部状态变化；计算风控项（止损、集中度）。
5. 所有状态变化入库；推送策略决定哪些推送（冷却、例外，第 2.8 节）；为需要处置的提醒生成待填记录。
6. 发起人按预案处置；偏离预案先写理由，次一交易日美东 09:30 后才可操作（第 3.4 节）。
7. 运行失败：当日不出信号，推送“今日未出信号：原因”；不把昨日状态当作今日结果。

### 1.3 状态变化与提醒种类

所有状态变化都入库（`t_alert`）；“是否推送”由推送策略单独决定。

| 代码 | 含义 | 默认推送 | 冷却 |
| --- | --- | --- | --- |
| RISK\_UP | 风险等级上升（可跨级） | 是 | 升到高于上次已推送等级时不受冷却 |
| RISK\_DOWN | 风险等级下降一档 | 是 | 受冷却 |
| RB\_WATCH / RB\_CONFIRM / RB\_TREND | 进入 RB1 / RB2 / RB3 | 是 | 受冷却 |
| RB\_FAIL | 反弹链失效（跌破锚点或创新低） | 是 | 不受冷却 |
| RB\_END | 风险回到正常，反弹链结束 | 否，只记录 | — |
| STOP\_HIT | 持仓股触及止损 | 是 | 不受冷却 |
| CONC\_OVER | 集中度超限 | 是 | 受冷却 |
| DATA\_ISSUE | 缺价、历史断点、复权回溯、代码变更 | 是 | 不受冷却 |
| EVENT\_SOON | 事件临近（非第一版必做） | 提示 | — |

### 1.5 明确不做的事

- 不预测、不输出胜率；不判断下跌原因（收益贡献分解只描述构成）。
- 不给买卖数量；参考股数只在发起人配置完整时作为计算结果显示，不下单、不接交易接口。
- 不做盘中、分钟线；不做 ETF 个体预警（ETF 只作参照）。
- LLM 不进入信号计算；第一版不做 LLM 功能、不做事件日历功能（只建表）。
- 第一版不开发 FastAPI 与前端。
- 不修改、不导入 market-risk，不把它当生产依赖。
- 第一版不评价“假设交易”的账户收益（R-44）。

## 2. 规则规格

风险预警由 R1（波动率归一化回撤）和 R2（跳空大跌）决定等级，R3 只做收益贡献分解；反弹链 RB1→RB2→RB3，第一版实现 RB1、RB2 与失效，RB3 定义完整、作为可选项。本节的目标是：两个独立实现者按文字写代码，离散结果逐项相同，连续数值在登记容差内相同。所有参数只给候选，待登记。

### 2.0 通用口径与数值规范（R-05）

| 项 | 规定 |
| --- | --- |
| 价格 | 一律使用所选数据版本的供应商前复权开高低收（BR OHLC），不从收盘比值重构（第 4.3 节） |
| 类型转换 | repository 把 DECIMAL 转为 Python float（IEEE-754 双精度），转换时不另做舍入 |
| 求和与均值 | 一律 `math.fsum(xs) / n`（正确舍入，与相加顺序无关） |
| 容差 | 比率类量（D、G、RS 比较、收益分解）ε\_r = 1e-10；价格类比较（收盘对均线、对锚点、对前收）ε\_p = 1e-9 美元。数值待登记 |
| 比较 | `x ≥ k` 判为 x ≥ k − ε；`x > k` 判为 x > k + ε；`x ≤ k` 判为 x ≤ k + ε；`x < k` 判为 x < k − ε。差值在 ε 内视为相等：计入 ≥/≤，不计入 >/< |
| 结果一致性 | 离散结果（等级、阶段、提醒、状态码）必须完全相同；连续量（指标值）在复算中按相对误差 ≤ 1e-9 比较（待登记） |
| 输出精度 | 入库价格 DECIMAL(18,6)；指标快照以 JSON 保存 float 的 `repr`，不舍入 |
| 时间 | T 日收盘后计算，信号日期为 T，供 T+1 参考；domain 函数只接收截断到 T 的序列（`PriceSeries.upto(T)`） |
| 交易日 | 以运行快照中固定版本的交易日历为准（第 4.5 节） |
| 窗口计数 | 窗口按“该证券有日线的交易日”计数；窗口内的短缺口处理见第 2.9 节 |
| 明确失败 | 非有限值、价格 ≤ 0、高 < 低、收盘不在 \[低, 高\]、长度不一致 → `InvalidInputError`，整次运行失败 |
| 显式状态 | `INSUFFICIENT_HISTORY`（窗口不足）、`MISSING_DATA`（T 日缺价）、`ANCHOR_UNAVAILABLE`（锚点不可得），不用空值代替 |

### 2.1 基础指标

```latex
TR_t = \max\left(H_t - L_t,\ |H_t - C_{t-1}|,\ |L_t - C_{t-1}|\right), \qquad ATR_N(t) = \frac{\mathrm{fsum}(TR_{t-N+1..t})}{N}
```

- 需要 N+1 条日线（第一条只提供 C\_{t−1}）；ATR ≤ 0 → `InvalidInputError("ATR 非正")`。
- SMA\_M(t) = fsum(最近 M 个收盘) / M，需要 M 条。
- Wilder 平滑、收益标准差作为备选，不进第一版网格。

### 2.2 R1 波动率归一化回撤

```latex
P^{max}_t = \max_{t-W+1 \le i \le t} C_i, \qquad D_t = \frac{P^{max}_t - C_t}{ATR_N(\tau)}
```

- 峰值日 p：窗口内取得 P^max 的交易日，并列取最近一天。
- τ：冻结方案 τ = p（只用 p 及以前数据）；不冻结方案 τ = T。二者作为候选登记。
- 等级：D\_t ≥ k₂ → 警戒（2）；否则 D\_t ≥ k₁ → 关注（1）；否则正常（0）。要求 k₁ < k₂。
- 最低历史：自历史起点（第 2.9 节）起至少 W + N 条，否则 `INSUFFICIENT_HISTORY`。
- 另输出百分比回撤 DD\_t = 1 − C\_t / P^max\_t，仅用于解释。

### 2.3 R2 跳空大跌（R-10）

```latex
G_t = \frac{O_t - C_{t-1}}{ATR_N(t-1)}
```

R2 的输出是一个完整结果对象，不是单个数值：

```python
@dataclass(frozen=True)
class R2Result:
    status: CalcStatus          # OK / MISSING_DATA（缺开盘价或前收）/ INSUFFICIENT_HISTORY
    gap_score: float | None     # 仅 status == OK 时有值
    close_t: float | None
    close_prev: float | None
    triggered: bool             # status == OK 且 G_t ≤ −g 且 C_t < C_{t−1}
```

- 触发时隐含等级至少为关注（1）；`status` 非 OK 时 R2 不参与判级，R1 照常。
- ATR 用 t−1 日值。财报日跳空同样触发，提醒附“财报日”标签（若事件表有记录）。

### 2.4 R3 收益贡献分解（R-03、R-11）

R3 **只描述收益构成，不判断下跌原因**。区间为 R1 的峰值日 p 到 T，r 为区间简单收益：

```latex
r_s = \underbrace{r_{mkt}}_{\text{市场}} + \underbrace{(r_{sec} - r_{mkt})}_{\text{板块相对市场}} + \underbrace{(r_s - r_{sec})}_{\text{个股相对板块}}
```

- 市场参照为 SPY；板块参照为名单中映射的美国板块 ETF。
- 主导项：只在小于 −ε\_r 的分项中选最负者；与全局最小值相差 ≤ ε\_r 的分项构成并列集合，按“市场 > 板块相对市场 > 个股相对板块”取第一个。没有负分项（含 p = T）时输出 `NO_NEGATIVE_CONTRIBUTION`。
- 未映射板块：改用两项分解（市场、个股相对市场），标注“板块未映射”。
- 参照缺价：分解输出 `UNAVAILABLE`，风险等级照常计算。
- 非美国发行人（含 ADR）的“个股相对板块”一项会混入母国市场与汇率影响，提醒和报告中注明。
- 第一版不改变状态；“相对板块走弱升级”为第二版候选。

### 2.5 风险状态机（R-09）

| 项 | 规则 |
| --- | --- |
| 状态 | 0 正常 / 1 关注 / 2 警戒 |
| 隐含等级 | L\_t = max(R1 等级, R2 等级)；R2 非 OK 时 L\_t = R1 等级 |
| 升级 | L\_t > 当前等级 → 当日升到 L\_t（可跨级），降级计数清零，产生 RISK\_UP |
| 降级 | L\_t < 当前等级的**连续有效交易日**达到 d → 降一档，计数清零，产生 RISK\_DOWN；L\_t ≥ 当前等级的那天计数清零 |
| 缺价（T 日 MISSING\_DATA） | 等级、反弹阶段、锚点冻结；**降级计数与不创新低计数清零**，数据恢复后从 0 重新累计（缺失数据回补并整体回放时除外） |
| 窗口不足 | 等级保持初始值 0，不产生任何状态变化 |
| 去重冷却 | 不在状态机内处理；所有状态变化都入库，是否推送由第 2.8 节推送策略决定 |

### 2.6 简化大盘代理（第一版唯一生产背景来源，R-12、R-13、R-14）

**这是本项目的简化代理，不等于 market-risk 状态。** market-risk 输出待 market-risk M3 后确认；接入方案另行批准前只独立展示，不参与过滤或纪律判断。

| 项 | 判定 |
| --- | --- |
| 输入 | SPY、QQQ 的 BR 收盘，同一数据版本 |
| 回撤 | 对每个资产 a：DD\_a = 1 − C\_T / max(最近 63 个收盘，含 T) |
| 等级（每日无滞后重算） | max(DD\_SPY, DD\_QQQ) ≥ θ₂ → 二级；否则 ≥ θ₁ → 一级；否则正常。要求 θ₁ < θ₂ |
| 止跌标志（只展示） | 两资产都已连续 Kₘ 个有效交易日未创 20 日收盘新低（新低定义同第 2.7 节）。不参与过滤 |
| 缺价或不足 63 条 | 背景为 `UNKNOWN` |
| 参数 | θ₁、θ₂、Kₘ 由发起人填写，SR-M1 登记，不照搬 market-risk 数值 |

**市场过滤（唯一规则）**：背景为二级时，RB\_CONFIRM、RB\_TREND 照常计算与入库，推送标为“观察”，文案为“大盘回撤处于二级”；背景为 UNKNOWN 时不降级，文案为“大盘背景未知”。一级不做任何处理。

### 2.7 反弹链（R-07、R-08）

**新低**：C\_t ≤ min(C\_{t−N\_low} … C\_{t−1})，按第 2.0 节比较（相等计入）。需要前 N\_low 条；不足时当日新低不可判定，视为 `INSUFFICIENT_HISTORY`。

**锚点 A**：当前反弹链锚点，含价格与日期，按以下规则更新：

| 事件 | 锚点与计数 |
| --- | --- |
| 风险等级由 0 升到 ≥ 1（链开始） | 在当前历史段（第 2.9 节）已加载数据中，找最近一次新低日 → A 取该日收盘与日期；since\_low = 该日之后到 T 的有效交易日数（当日不再另加一，R-06）。找不到 → `ANCHOR_UNAVAILABLE`，链不推进，直到出现新低 |
| 处于“下跌中”（阶段 NONE）且当日为新低 | A 更新为当日收盘与日期，since\_low = 0，不产生提醒 |
| 处于 RB1/RB2/RB3 且 C\_t < A，或当日为新低 | RB\_FAIL：原因 `BREAK_ANCHOR`（跌破锚点，优先）或 `NEW_LOW`；阶段回到 NONE；A 更新为当日收盘与日期，since\_low = 0 |
| 其他有效交易日 | since\_low 加一 |
| T 日缺价 | A 不变，since\_low 清零（第 2.5 节） |

**阶段推进**（每天最多推进一级）：

| 推进 | 条件 |
| --- | --- |
| NONE → RB1 | 风险 ≥ 1，A 可得，since\_low ≥ K |
| RB1 → RB2 | C\_t > SMA\_S(t) |
| RB2 → RB3 | C\_t > SMA\_M(t)，且 RS\_t ≥ SMA\_R(RS)(t)，RS = C / C\_SPY；SPY 缺价时当日不判定、不推进 |

&#91;embedded content: 反弹链 · 推进、失效回路与市场过滤\]

各阶段只能依次进入，每天最多一级；红线表示任一阶段跌破锚点或再创新低都回到“下跌中”。

**结束**：风险等级回到 0 → RB\_END（只记录、不推送），阶段与锚点清空。

**第二版候选**：以“更高的低点”替代 RB2 条件。

### 2.8 逐日步进与推送策略（R-06、R-15、R-20、R-21）

每只股票每个交易日按固定顺序：数据检查 → 指标 → 风险状态机 → 反弹链 → 市场标注。domain 只产出状态与全部状态变化，**不做冷却**。

```python
def step_symbol(prev: SymbolState, s: PriceSeries, refs: RefSeries, as_of: date,
                market: MarketBackground, p: Params) -> tuple[SymbolState, list[Transition]]:
    out: list[Transition] = []
    if not s.has_bar(as_of):                                    # T 日缺价
        return prev.frozen(as_of, reset_counters=True), [Transition("DATA_ISSUE", reason="MISSING_DATA")]
    if s.bars_in_segment(as_of) < p.w + p.n:                     # 窗口不足
        return prev.with_status(as_of, CalcStatus.INSUFFICIENT_HISTORY), []

    dd = normalized_drawdown(s, as_of, p)
    r2 = gap_result(s, as_of, p)                                 # R2Result
    lvl = implied_level(dd, r2, p)

    risk, cnt, risk_tr = step_risk(prev.risk_level, prev.downgrade_counter, lvl, p.d)
    out += risk_tr

    chain, chain_tr = step_chain(prev.chain, prev.risk_level, risk, s, refs.spy, as_of, p)
    out += chain_tr                                              # 初始化当日不对 since_low 二次累加

    out = [label_market(t, market) for t in out]                 # 只改文案与推送级别
    return SymbolState(as_of, risk, cnt, chain, CalcStatus.OK), out
```

**推送策略**（在 service 层的 `NotificationPolicy`，全系统只执行一次）：

- 冷却键：(security\_id, alert\_type, to\_state)。
- 与上次**已发送**（SENT 或 UNKNOWN，见第 6.6 节）的同键提醒相距的交易日数 < c → 抑制；= c 允许。
- 不受冷却：升到高于上次已推送等级的 RISK\_UP、RB\_FAIL、STOP\_HIT、DATA\_ISSUE。
- 计时只读推送账本（实际发送记录），不读回放产生的历史状态变化。

**交互规则**

| 编号 | 规则 |
| --- | --- |
| I1 | 链开始当日初始化锚点与 since\_low，当日不再另加一 |
| I2 | 失效优先于推进；BREAK\_ANCHOR 优先于 NEW\_LOW |
| I3 | 风险回到 0，链在任何阶段结束（RB\_END） |
| I4 | 每天最多推进一级 |
| I5 | 风险再次升级不打断反弹链；只有跌破锚点或创新低才失效 |
| I6 | T 日缺价：等级、阶段、锚点冻结；降级计数与 since\_low 清零 |
| I7 | 参照序列缺价只影响 RB3、收益分解与大盘背景，不影响风险等级 |

**确定性约定**：每日从当前历史段起点（max(`replay_start`, 最近历史断点)）全量回放到 T。与已存 T−1 状态的核对**只在数据快照、参数集、代码版本三者完全相同时进行**，不一致则停止。跨数据版本产生的历史差异写入修订审计表（`t_state_revision_audit`），不算失败，也不重发旧提醒。

**手工推导示例**（N = 2、W = 5、k₁ = 2、k₂ = 4，仅为说明，不是候选值；本例为短小不执行“历史 ≥ W + N”的要求，正式测试另写满足要求的用例）：

| 日 | 开 | 高 | 低 | 收 | TR |
| --- | --- | --- | --- | --- | --- |
| d1 | — | 10.5 | 9.5 | 10.0 | — |
| d2 | — | 11.0 | 10.0 | 10.8 | max(1.0, 1.0, 0.0) = 1.0 |
| d3 | — | 11.2 | 10.6 | 11.0 | max(0.6, 0.4, 0.2) = 0.6 |
| d4 | — | 11.0 | 10.2 | 10.4 | max(0.8, 0.0, 0.8) = 0.8 |
| d5 | — | 10.5 | 9.6 | 9.8 | max(0.9, 0.1, 0.8) = 0.9 |
| d6 | 9.2 | 9.4 | 8.9 | 9.0 | max(0.5, 0.4, 0.9) = 0.9 |

- T = d6：窗口 d2–d6 最高收盘 11.0，峰值日 d3。冻结：ATR₂(d3) = 0.8，D = 2.0 / 0.8 = 2.5 → 关注。不冻结：ATR₂(d6) = 0.9，D = 2.2222… → 关注。
- G = (9.2 − 9.8) / ATR₂(d5) = −0.6 / 0.85 = −0.70588… → g = 2 时不触发。

- I1 边界：距最近新低 2 个有效交易日、K = 3，链开始当日 since\_low = 2，不得进入 RB1。

### 2.9 历史断点与代码变更（v0.3 新增）

- **历史断点**：某证券在交易日历上连续缺价超过 G 个交易日（候选见 2.10），视为断点。断点后的第一条日线为新的历史段起点；之前的数据不参与指标；状态重置为初始；新段满 W + N 条前为 `INSUFFICIENT_HISTORY`。断点在提醒与评价中单独标注。例：NBIS 原 YNDX 于 2022-02-28 停牌、2024-10-21 复牌。【推断】
- **短缺口（≤ G 天）**：缺价当日按 MISSING\_DATA；恢复后窗口按“有日线的交易日”计数照常计算，指标快照标注 `window_has_gap`。
- **代码变更**：所有表以与代码无关的内部 `security_id` 关联；代码变更记入代码历史表（第 5 节）。数据源验收增加“代码变更前后历史能否连续取到”。

## 3. 风控与纪律

每条风控规则按“配置是否完整”独立启用：配置完整才计算，缺值显示“未配置”，非法组合显示“配置错误”，快照过期或不完整显示“不可评估”。系统从不补默认值，也不输出无意义的数字。

### 3.1 规则清单

| 规则 | 检查时点 | 系统做什么 | 发起人填写 | 第一版 |
| --- | --- | --- | --- | --- |
| 单笔风险预算（参考股数） | 每日计算 | 参考股数 = floor(权益 × 风险比例 ÷ (参考入场价 − 止损价))；分母 ≤ 0 或任一输入缺失时不输出 | 风险比例 \_\_\_%、参考入场价 | 进 |
| 止损 | 每日计算 | 持仓股收盘 ≤ 止损价（同一价格基准）→ STOP\_HIT | 止损模式与参数（3.3） | 进 |
| 集中度 | 每日计算 | 单股、单板块市值 ÷ 账户权益；超限 → CONC\_OVER | 单股 \_\_\_%、单板块 \_\_\_% | 进 |
| 不在下跌中摊平 | 操作录入后 | 风险 ≥ 1 且阶段 < RB2 时的加仓操作标记违规 `NO_AVG_DOWN` | — | 进 |
| 大盘过滤 | 操作录入后 | 背景二级时新开仓超过上限，标记违规 `MKT_L2_CAP` | 上限 \_\_\_% 或“不开” | 进 |
| 组合熔断 | 每日计算 | 权益距高点回撤 ≥ 熔断线 → CB\_HALT | 熔断线、恢复条件 | 第二版 |
| 财报前规则 | 每日计算 | 财报前 n 天提示规定动作 | n、动作 | 第二版 |

### 3.2 价格基准（R-19）

- 你录入的成交价、止损价保留**原始交易口径**和日期，不改写。
- 比较前统一换算到当前数据版本的前复权基准：P\_basis = P\_raw × f(d)，f(d) = 该版本 d 日 BR 收盘 ÷ NR 收盘（第 4.3 节）。
- ATR 止损所用的 ATR 取入场日、同一版本、同一基准。
- 验收例：拆股前买入、拆股后触发止损；ADR 比率变更前后同理。

### 3.3 风控配置（R-45、R-46）

| 配置 | 规则 |
| --- | --- |
| 止损模式 | 二选一、互斥：`FIXED`（固定止损价，原始口径 + 日期）或 `ATR`（k\_stop 倍，入场日 ATR）。两者都填或都不填 → 配置错误 / 未配置 |
| 风险比例、单股/单板块上限 | 版本化保存，生效日起使用 |
| 账户权益 | 手工录入快照（金额 + 日期） |
| 持仓 | 手工录入快照（证券、数量、成本、日期） |
| 集中度分母 | **账户权益**（发起人 2026-10-13 裁决） |
| 快照有效期 | 权益或持仓快照超过 **5 个交易日**未更新 → 不可评估（发起人裁决） |
| 板块未映射 | 该股计入“未映射”组，单板块集中度对其不可评估 |

每次计算保存分子、分母、快照日期与完整性标志。

### 3.4 执行纪律（R-48）

- **预先承诺**：加入名单或买入时填写预案（关注、警戒、反弹确认、反弹失效时的动作，以及止损配置）；没有预案的提醒显示“无预案”。
- **偏离冷静期**：偏离预案时，理由必须**早于**操作提交；最早可操作时点 = 理由提交后的下一个交易日美东 09:30（按交易日历判定，发起人裁决）。事后补写的理由标记“未满足冷静期”。系统只记录与标记，不阻止操作。
- **季度复盘**：以“实际操作”为统计单位，统计偏离次数、方向与事后 5/20 日价格变化；修订不重复计数。

### 3.5 记录模型（R-47）

| 记录 | 用途 | 关键字段 |
| --- | --- | --- |
| 预案 `t_trade_plan` | 事先承诺，版本化 | 证券、版本、各状态下动作、止损配置引用、生效日 |
| 实际操作 `t_trade_action` | 每笔真实操作一行，**可以没有对应提醒** | 操作编号、证券、类型（买/加/减/清/其他）、数量、原始成交价、成交时间、是否偏离预案、理由、理由提交时间、冷静期是否满足、违规代码 |
| 提醒处置 `t_alert_disposition` | 每条需处置的提醒一行 | 提醒、当时预案与应做动作、处置结论（已执行/决定不执行/待定）、处置时间 |
| 关联 `t_action_alert_link` | 操作与提醒多对多 | 操作编号、提醒编号 |

所有记录只追加，修订生成新版本行。

### 3.6 评价范围（R-44）

第一版只评价“触发记录”和“执行纪律”，不评价各风控规则对账户收益或回撤的影响。假设交易研究以后另行登记，执行政策（入场、出场、资金分配、价格时点、费用）由发起人提供，结论不回流为生产建议。

## 4. 数据

数据源与供应商无关：任何平台按 4.1 节标准验收，通过即可用，费用与额度不作约束。每日对全部所需证券完整重取历史，同时保存不复权与前复权开高低收，计算直接用前复权，发布前做一致性检查。

### 4.1 数据源选型标准（第一版必需 / 可选）

| 能力 | 验收方法 | 类别 |
| --- | --- | --- |
| 日线 NR 与 BR 开高低收（个股与 ETF） | 抽 5 只证券，对比两种口径各一年 | 必需 |
| 前复权是否含现金分红 | 选一只分红股，看除息日前后 BR/NR 比值是否跳变；**结论两种皆可用，但必须查清并登记** | 必需（查清即可） |
| 拆股、ADR 比率变更的复权正确 | 各选一例，复权后序列无假跌 | 必需 |
| 历史起点 | 不晚于开发期起点 2010-01-01；不足则按 Q6 备选切分 | 必需 |
| 时间戳到交易日映射 | 普通日、夏令时切换前后、提前收市日、分页交界各一例（R-53） | 必需 |
| 代码变更连续性 | YNDX→NBIS 前后能否连续取到 | 必需 |
| 授权 | 允许个人研究、本地存储 | 必需 |
| 频率限制 | 足以支撑每日完整重取（4.3），按实测估算耗时 | 必需 |
| 退市证券历史 | 抽取已退市证券样本 | 可选（影响幸存者偏差缓解，4.7） |
| 指数 K 线（如 .SPX） | — | 可选（第一版用 SPY/QQQ） |
| 公司行动与财报日接口 | — | 可选（事件功能非必做） |

### 4.2 存储与复权方案（R-16）

1. 每个数据版本同时保存供应商原始 **NR 与 BR 开高低收与成交量**。
2. 指标计算**直接使用 BR 开高低收**，不从收盘比值重构其他三个价格。
3. 隐含因子 f(d) = BR 收盘 ÷ NR 收盘只有两个用途：检测复权回溯；把原始成交价、止损价换算到当前基准（第 3.2 节）。
4. 验收时额外计算 NR × f 与 BR 在开、高、低上的差异，仅作数据质量信息登记，不作为方案前提。

### 4.3 每日完整重取与发布一致性（R-17、R-22、R-23）

- 每日对名单 ∪ SPY、QQQ、板块 ETF 去重后的全部证券，从“当前历史段起点前的预热区间”到 T 完整重取 NR 与 BR，不做增量拼接。
- 请求按数据源单次证券数与条数上限分批、分页，NR 与 BR 分别请求，共享限速（R-54）；耗时按所选数据源实测。
- 新取数据与上一已发布版本逐行比较：值不变的行保持有效；变化或新增的行写入新行，旧行在同一事务中设置 `superseded_version_id`（第 5.3 节唯一例外）。
- **发布前必须通过**：同一证券整段序列来自同一次取数（复权基准一致）；每个证券日只有一条有效行；第 4.4 节质量检查通过；版本序号严格递增且只有一个线性序列。任一不通过，该版本标记 FAILED，不可用于计算。
- 复权回溯（f 序列变化）→ 新版本 + DATA\_ISSUE 提醒 + 修订审计；不重发旧提醒（第 2.8 节）。

### 4.4 就绪、时间映射与质量检查（R-52、R-53）

- 收盘后 2.5 小时（Tiger 文档所述，其他来源按其说明）只是**最早尝试时点**；运行还须检查：目标交易日在返回数据中存在、覆盖全部证券、质量检查通过。之后供应商的修订按新版本处理，不宣称“永久定稿”。
- 登记日线查询的起止边界、返回时间戳到美东交易日的映射、重复条目去重规则；验收见 4.1。
- 质量检查：缺失（日历有、数据无）→ 该证券 MISSING\_DATA；重复 → 版本失败；非法值 → 版本失败；无复权事件的不复权大幅跳变 → 标记待人工确认（阈值待登记）。

### 4.5 交易日历

- 交易日历作为输入快照的一部分，固定版本；来源为交易所日历库（如 `exchange_calendars` 的 XNYS），与数据源日历交叉核对，不一致时人工确认后发布日历新版本。
- 临时休市日按日历版本处理；提前收市日照常是交易日。

### 4.6 证券主数据与地域门（R-02、硬约束 2）

- `t_security` 以内部 `security_id` 为主键，保存：名称、类型（个股/ETF）、上市交易所、是否 ADR、ADR 比率、发行人注册地、总部所在地、主要经营地、核验来源、核验时间。
- **地域门**：仅允许在 NYSE/Nasdaq 交易的证券；注册地、总部、主要经营地任一项为中国内地、香港或澳门 → 拒绝；在发起人手工排除名单内 → 拒绝；三项任一缺失 → 拒绝（资料补齐后再加）。
- 判定只依据已登记的核验来源（如公司年报 10-K/20-F、交易所资料），核验时间超过 1 年需复核。【推断】
- **ADR**：比率变更须体现在复权中（4.1 验收）；母国休市而美国开市的日子照常计算，评价时按“母国休市日”分层报告；收益分解注明混入母国市场与汇率影响；国家 ETF（如 EWJ、EWU）作参照列为第二版候选。

### 4.7 幸存者偏差与“当时可知”（R-18）

- 回测样本是当前自选名单，结论偏乐观；评价报告首页声明。可选：取得退市证券历史后，用历史宽基样本做稳健性复核，它只能检验稳健性，不能消除当前名单的偏差。
- 回测使用固定数据版本，称“固定版本历史复算”。复权缩放跨除息日不是常数，因此不能仅凭“按日期截断”宣称无前视；报告注明此限制。生产运行逐日保存当时版本与结果，构成真正的“当时可知记录”。

### 4.8 事件（R-56，表先设计、功能推后）

- 事件有稳定身份与修订关系；保存来源发布时间、实际获知时间、时区、发布时段（盘前/盘中/盘后/未知）。
- 运行按计算截止时间选取当时已知的最新修订；盘后事件关联下一交易日；日期或时段未知时不关联跳空。
- 宏观日历实现时附官方来源。

### 5.3 约束与读法

- **只追加**：行情数值、名单、预案、配置、操作、处置、状态历史都不覆盖。唯一例外：`t_price_daily.superseded_version_seq` 在发布新版本的同一事务内由 NULL 设置一次（R-22）。
- **线性版本**：只有 PUBLISHED 版本参与区间读取；`seq` 唯一且递增，不存在分支（R-23）。
- **可复现**：一次计算 = 输入快照（数据版本、日历、参数、名单与配置时点、快照、截止时间、代码、环境）；复算只读快照引用的不可变版本，不读“当前名单”“最新预案”（R-24）。
- **展示快照**：只读查询统一按 `attempt_id` 取 K 线、状态、指标、提醒；默认取最新已发布的 DAILY 尝试（R-27）。
- **确定性核对**：只比较输入快照相同的两次尝试；核对字段为 `t_symbol_state_history` 全部状态列（R-26）。

### 6.3 导入契约（R-31、R-32）

- **传递隔离**（`allow_indirect_imports` 不开启）：domain 不得直接或间接依赖任何其他层，以及 sqlalchemy、pymysql、各数据源 SDK、requests、httpx、fastapi、pandas、openai、anthropic。
- **直接越层禁止**（`allow_indirect_imports = true`）：service 不直接导入 api、infra、jobs、bootstrap；repository 不直接导入 service、api、jobs 及 domain 计算子包；infra 不直接导入 service、api、jobs、repository 及 domain 计算子包；jobs 不直接导入 domain、repository、infra；api 不直接导入 repository、infra 及 domain 计算子包；research 不直接导入 service、repository、api、infra、jobs、bootstrap。
- **core 底座**：core 不依赖任何业务层（传递检查）。
- **LLM 隔离**：openai、anthropic 只允许出现在 `infra.llm` 与 `service.explanation`；`service.explanation` 的输出类型不得作为 domain 任何函数的参数（类型检查 + 契约）。
- **契约自测**：`tests/architecture/contract_cases/` 为每条契约准备一个应通过和一个应失败的小样例包，以编程方式运行 import-linter，确认契约确实能拦住违规。
- **纯度检查**：AST 扫描 domain，禁止 `datetime.now`、`date.today`、`time.time`、`random`、`open`、`print`，并覆盖别名导入（如 `from datetime import datetime as dt`）。这些检查只证明所列规则，不构成完整纯度证明；禁用 pandas 是第一版工程约束。

### 6.4 每日运行时序（R-28、R-29、R-30、R-49）

| 段 | 步骤 | 失败处理 |
| --- | --- | --- |
| A 取数 | 1. 判断 as\_of 是否交易日（日历版本）。2. 新建 `t_ingest_attempt`。3. 就绪检查（第 4.4 节）。4. 完整重取 NR/BR。5. 质量与一致性检查。6. 发布 `t_data_version`（PUBLISHED） | 未就绪：按重试表再试；检查失败：版本 FAILED，当日不计算 |
| B 建快照 | 7. 校验参数集哈希与已批准登记一致。8. 生成 `t_input_snapshot`。9. 取或建 `t_compute_task`（幂等：同一任务已有 PUBLISHED 尝试则跳到 D 段）。10. 新建 `t_compute_attempt`（RUNNING） | 哈希不符或工作区有未提交改动（正式运行）：失败 |
| C 计算 | 11. 简化大盘代理。12. 逐股全量回放到 T。13. 同快照核对 T−1 状态；跨版本差异写修订审计。14. 风控计算（止损、集中度、参考股数）。15. 单事务写入状态、指标、背景、全部状态变化、风控结果；尝试置 PUBLISHED | 任一步失败：回滚，尝试置 FAILED 并记原因，推送“今日未出信号” |
| D 推送 | 16. `NotificationPolicy` 决策并写 `t_notification`。17. 逐条发送，写 `t_delivery_attempt`。18. 生成待处置记录 | 发送失败：由 `redeliver` 命令独立补发，不依赖下次计算 |

操作录入（任何时间）→ `DisciplineService.check` 写入违规代码与冷静期判定。

### 6.5 重试分类（R-50）

| 类别 | 规则 |
| --- | --- |
| 网络请求（取数） | 指数退避，最多 3 次；429 按返回的限流信息等待；超过则本次取数尝试失败 |
| 数据未就绪 | 按计划间隔再次发起新的取数尝试（候选：间隔 20 分钟、最多 3 次，待登记） |
| 日常计算 | 代码或数据错误不自动重试；修复后新建计算尝试（记录新代码版本） |
| 投递 | `redeliver` 补发；结果 UNKNOWN 的不自动补发（避免重复），由发起人确认；渠道不支持幂等时可能重复送达，文档注明 |
| 正式验证（SR-M5） | 不重试；验证期一旦解封即持久化“已消费”标记，任何重跑不得再次选参或产生新的可查看结果 |

### 6.6 推送账本口径

冷却计时把 SENT 与 UNKNOWN 都视为“已发送”；FAILED 视为未发送。历史回放产生的状态变化不进入账本。

## 7. 评价方法（SR-M1 登记，看结果前固定）

评价的是“提醒是否及时覆盖了值得注意的下跌、负担是否可接受”，不是“方向猜得准不准”。主指标是覆盖率、滞后与负担；提醒后的价格路径只作次要描述。下文数值均为候选，SR-M1 登记时固定；登记文件未包含完整选择规则与最小样本数，不得退出 SR-M1（R-59、R-60）。

### 7.1 主指标（R-33）

| 对象 | 主指标 | 估计对象与分母 |
| --- | --- | --- |
| 风险预警 | 大跌事件覆盖率 | 分母 = 7.2 定义的大跌事件数；分子 = 谷底日之前出现过 RISK\_UP 的事件数 |
|  | 滞后 | 每个被覆盖事件：峰值日 → 首次 RISK\_UP 的交易日数；首次提醒时已实现跌幅 ÷ 事件最终最大跌幅 |
|  | 负担 | 每股每年 RISK\_UP 次数（状态变化数）与实际推送数，分别报告 |
| 反弹提醒 | 链内失效率 | 分母 = RB2 次数；分子 = 同一链内此后出现 RB\_FAIL 的次数；链以 RB\_END、缺价、样本结束告终的单列，不算“未失效”（R-43） |

### 7.2 大跌事件切分（R-35，候选值待登记）

事件只用于评价，不回流信号链；用一套固定的评价口径，与候选参数无关。

| 环节 | 规则 |
| --- | --- |
| 评价口径 | D\_eval：W = 63，N = 20，SMA ATR，不冻结 |
| 开始 | 首个 D\_eval ≥ X 的交易日（X 候选 {6}）；峰值日 = 当时 63 日最高收盘日，并列取最近 |
| 谷底 | 峰值日至事件结束之间的最低收盘日 |
| 结束 | 收盘回到峰值收盘以上；或 D\_eval < X / 2 连续 10 个交易日；或开始后 252 个交易日（截尾，标记） |
| 合并 | 结束后 20 个交易日内再次开始 → 并入同一事件 |
| 删失 | 缺价、历史断点、样本末端导致无法结束的事件标记删失，单列 |

### 7.3 次要描述：提醒后路径类别（R-34）

- 从 T+1 起 H 个交易日（H 候选 {20, 60}），以收盘价判断是否先触达 C\_T ± b × ATR（b 候选 {2, 3}）。
- 结果分为：先下、先上、同日双触达（顺序未知）、H 日内都未触达、删失（缺价、退市、尾部不足 H 日）。
- 只作描述，不称“有效率”“误报率”，不参与选参。
- 反弹提醒另报告 RB2 后固定 5/20/60 日收益分位数，与链内失效率分开报告（R-43）。

### 7.4 基线（R-41）

每个基线都写成完整的提醒生成规则，并走同一套事件评价：

| 基线 | 触发日 | 状态映射 | 去重与冷却 | 可评价日期 |
| --- | --- | --- | --- | --- |
| 固定百分比回撤 | 距 63 日高点回撤首次 ≥ 10%（关注）/ 20%（警戒）的那天 | 同本系统三档，降级规则同 2.5 | 同 2.8 推送策略 | 与本系统相同（历史段内、窗口足够） |
| 均线下穿 | 收盘由 ≥ SMA50 变为 < SMA50 的当天（只在下穿日） | 关注 | 同上 | 同上 |
| 随机日期 | 从同一证券的可评价日期中无放回抽取，次数等于该证券实际 RISK\_UP 次数；重复 1000 次，种子登记 | 关注 | 无 | 同上 |
| 固定反弹 | 风险 ≥ 1 期间，收盘首次高于最近新低收盘 5% / 10% | 对应 RB2 | 同上 | 同上 |

### 7.5 期间与隔离（R-36、R-37、R-38）

| 段 | 期间 | 规则 |
| --- | --- | --- |
| 预热 | 开发期起点前 300 个交易日 | 只供指标计算 |
| 开发期 | 2010-01-01 至 2019-12-31 | 只使用标签所需价格全部落在开发期内的样本；事件或路径窗口跨过 2019-12-31 的样本剔除 |
| 验证期（保留） | 2020-01-01 至参数冻结前最后一个完整月（发起人裁决） | SR-M5 之前不读取、不生成、不展示任何结果，包括演练 |
| 前推观察期 | 参数冻结并开始真实留痕后的首个交易日起 | 真正的“当时可知记录”，不回头调参 |

若数据源历史起点晚于 2010 年，按 Q6 备选切分，比例约 2:1。

### 7.6 选参协议（R-39、R-59）

1. **阶段一（风险参数，64 组）**：主指标 = 大跌事件覆盖率；约束 = 每股每年 RISK\_UP 次数中位数 ≤ F（发起人填写）。在满足约束的候选中取覆盖率最高者；并列（差 ≤ 0.01）取滞后中位数更短者；仍并列取网格顺序靠前者。
2. **稳健性**：所选点在网格上每个只差一个参数的相邻点，覆盖率下降不超过 Δ（候选 0.05）；不满足则按顺序取下一个满足者。
3. **无合格候选**：没有任何候选满足约束 → 停止，回到设计，不放宽 F。
4. **阶段二（反弹参数，4 组）**：固定阶段一结果；主指标 = 链内失效率（越低越好），约束 = 开发期 RB2 次数 ≥ 最小样本数；规则同上。
5. **打不过基线的判据**：主指标点估计不优于最好的基线，或其 95% 置信区间下限低于该基线点估计 → 判为“打不过”，不采用该规则的复杂版本。
6. **确认性结论只有两个**（阶段一、阶段二主指标对最好基线），用 Holm 法校正；其他一切比较标为探索性。
7. 网格结果全部报告，不只报告最优。

### 7.7 统计协议（R-40、R-60）

- **同步日历块自助法**：把日历切成长度 B 的连续交易日块（B 候选 63），有放回抽块；同一块内所有证券的样本一起抽取，以保留同日多股相关与同股重叠窗口相关。重复 2000 次，种子登记，百分位法 95% 区间。
- **最小样本**（每个主指标）：独立事件 ≥ 30（合并后）、证券 ≥ 10 只、时间块 ≥ 8 个（候选）。不满足只报告描述统计，不下结论，不得放宽门槛补出结论。

### 7.8 其他

- **大盘背景分层比较**（R-42）：按背景（正常/一级/二级/未知）分层报告反弹指标，不称为“过滤的改善效果”；另报告“观察级是否推送”对推送覆盖率的影响。
- 幸存者偏差与“固定版本历史复算”的限制写在报告首页（第 4.7 节）。
- 关键统计由不 import 项目代码的独立脚本复算，离散结果须完全一致。

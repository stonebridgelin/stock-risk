## 2. 审阅顺序与原则

先盲审规格，再看起草方的理由，避免被已有结论带偏。

1. **第一遍（盲审规格）**：只读第 2 节规则规格、第 5 节库表、第 6 节模块与契约、第 7 节评价方法。先不看第 0 节修订说明和第 9 节建议。对每条规则自问：两个独立实现者按此文字写代码，能否得到逐位相同的结果？
2. **第二遍（事实核对）**：第 4 节 Tiger Open API 的每条结论都附了官方链接，请打开链接逐条核对；链接打不开或内容不符请明确说明。没有附来源的事实性陈述一律指出。
3. **第三遍（全局）**：读第 0、1、3、8、9、10 节，检查与硬约束是否一致、各节之间是否矛盾、第 9 节建议的理由是否成立。

原则：

- 区分**事实错误**、**规格缺陷**（歧义、遗漏、不可实现）和**设计偏好**；偏好不得标为阻断。
- 不确定的地方写“不确定”和原因，不要猜。
- 标注【推断】的内容是起草方的设计建议，请重点挑战。
- 不提出与硬约束冲突的方案；若你认为某条硬约束本身有问题，单列为“疑问”，交发起人决定。
- 不要因为某条做法与 market-risk 一致就默认正确；market-risk 的结论只在 SPX+QQQ 上评价过。

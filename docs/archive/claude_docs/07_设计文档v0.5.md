## 1. 预警生命周期规格

每只股票同一时间最多有一次进行中的预警。预警从触发那天起冻结基准（本次高点与 ATR），之后的加重、降级、解除都相对冻结基准和本次低点判断；降级后再次加重必须有“新恶化”，解除后再次启动必须是“新下跌”。每天先算出当日全部证据，再按固定优先级决定状态变化。

### 1.1 状态

| 状态 | 含义 |
| --- | --- |
| 正常 | 没有进行中的预警 |
| 关注（WATCH） | 预警进行中，较轻一级 |
| 警戒（ALERT） | 预警进行中，较重一级 |

预警进行中另有**恢复进度**：无 → 企稳 → 恢复确认。恢复进度每天按当日证据重算，不沿用昨日结论。

预警内部还记录：本次高点 P\_ep 及其日期 p\_ep、冻结 ATR\_ep、本次低点 L\_ep 及其日期 l\_ep、开始日 s\_ep、是否已降级过（downgraded）、降级后高点 H\_d、降级计数、解除计数、最近计数中断日。

### 1.2 当日证据（全部先算，再转移）

| 证据 | 定义（C 为当日 BR 收盘，ε 按 v0.4 第 2.0 节） |
| --- | --- |
| 受限滚动回撤 D\_T | 回撤窗口起点 = max(T − W + 1, 最近一次解除日)；P^max 为窗口内最高收盘（并列取最近），D\_T = (P^max − C) / ATR\_N(τ)，τ 按 freeze 规则。**只用于启动** |
| 跳空 R2 | 同 v0.4 第 2.3 节；只用于启动，含义为“至少关注” |
| 本次严重度 D\_ep | (P\_ep − C) / ATR\_ep |
| 今日新低 | C < L\_ep − ε\_p（严格低于；相等不算） |
| 本次低点更新 | 若今日新低：L\_ep = C，l\_ep = T |
| since\_low | 从 max(l\_ep, s\_ep, 最近计数中断日) 的次日起，到 T 为止的有效交易日数；今日新低或今日为开始日时为 0 |
| 企稳 | since\_low ≥ K |
| 恢复确认 | 企稳，且 C > SMA\_S(T) |
| 反弹幅度 U | (C − L\_ep) / ATR\_ep（用更新后的 L\_ep） |
| 降级后高点 H\_d | 仅在已降级时：H\_d = max(H\_d, C) |
| 回吐 | 仅在已降级时：(H\_d − C) / ATR\_ep ≥ k₁ |
| 长期稳定 | since\_low ≥ K\_stab（K\_stab ≥ K，数值由发起人事前批准，J-11） |

### 1.3 计数规则（R3-05、J-10 原因交替）

- **降级计数**（仅在警戒时累计）：当日“降级证据集合”E\_down = {a：D\_ep < k₂；b：恢复确认；c：长期稳定} 中任一成立 → 计数加一；全部不成立 → 清零。
- **解除计数**（仅在关注时累计）：当日“解除证据集合”E\_rel = {a′：D\_ep < k₁；b′：恢复确认且 U ≥ u\_rel} 中任一成立 → 加一；全部不成立 → 清零。
- **原因交替**：只要每天至少有一项证据成立，计数连续累计，不要求是同一项。转移时记录：转移当日成立的证据集合，以及计数段内每天的证据集合。
- **清零时点**：任何等级变化（启动、加重、降级、解除）后两种计数都清零；当日缺价清零（并记中断日）；证据集合为空的当日清零；**今日新低时，E\_down 与 E\_rel 一律视为空**（新低本身就是恶化证据；对由跳空启动、D\_ep 尚小于 k₁ 的预警尤其必要，否则可能在创新低当天解除）。
- **每天最多变化一级**；当日发生等级变化后，当日不再参与另一种计数。因此从警戒到解除至少需要两个完整的 d 日证据段。
- **长期稳定只能用于降级，不能用于解除**（J-11）。降级原因描述为观察到的事实，例如“连续 K\_stab 个有效交易日未创本次新低”，不使用“风险已兑现”之类表述。

### 1.4 启动、加重与重新触发（J-10 两个阻断）

**启动（无预警时）**：受限滚动回撤 D\_T ≥ k₁，或 R2 触发 → 开始一次预警。

- 冻结：P\_ep = 受限窗口的 P^max，p\_ep 为其日期；ATR\_ep = 启动时计算 D\_T 所用的 ATR\_N(τ)。因此启动当日 D\_ep 与 D\_T 完全相等，初始等级与后续严重度使用同一基准。
- 初始等级 = max(R1 等级（D\_T ≥ k₂ → 警戒，≥ k₁ → 关注），R2 触发 → 关注)。
- L\_ep = \[p\_ep, T\] 内最低收盘及其日期；since\_low = 0。

**加重（关注 → 警戒）**：

| 情形 | 条件 |
| --- | --- |
| 本次预警尚未降级过 | D\_ep ≥ k₂ |
| 本次预警已降级过（阻断 1） | **必须出现新恶化**：今日新低，或回吐（自降级后高点回落 ≥ k₁ × ATR\_ep）。D\_ep 仍 ≥ k₂ 本身**不**导致重新加重 |

跳空在预警进行中不单独导致加重（保持“至少关注”的含义）。

**解除后的重新触发（阻断 2）**：解除后，受限滚动回撤的窗口起点不早于解除日。只有自解除日以来的最高收盘回落达到 k₁ 个 ATR，或 R2 触发，才启动新的预警；同一轮旧跌幅不会让预警立即重启。解除日滑出 W 日窗口后，窗口自然恢复为普通的最近 W 日。这条规则不屏蔽真正的新下跌：任何自解除后高点算起达到阈值的下跌都会触发。解除后 Q 天内启动的新预警另加“再次预警”标签，标签不替代上述规则。

### 1.5 当日处理顺序（优先级）

1. **数据检查**：当日缺价 → 等级与预警内部字段冻结，两种计数清零，记中断日，只产生 DATA\_ISSUE，结束。历史断点 → 进行中的预警以原因“历史断点”结束，产生 DATA\_ISSUE，新历史段满 W + N 条前不启动。
2. **计算当日全部证据**（第 1.2 节），包括新低、企稳、恢复确认、D\_ep、U、H\_d、回吐、受限 D\_T、R2。
3. **无预警时**：判断启动；启动则写入初始等级与冻结基准，结束。
4. **有预警时**，依次：
   1. 新低处理：更新 L\_ep；若上一有效交易日处于企稳或恢复确认 → 产生“恢复失败”。
   2. 加重判断（第 1.4 节）；加重则两种计数清零，跳到第 4.4 步。
   3. 降级或解除：警戒时累计降级计数，达到 d 则降为关注（downgraded = 是，H\_d = C）；关注时累计解除计数，达到 d 则解除（预警结束，记录解除日与解除收盘）。
   4. 恢复进度事件：当日首次进入企稳 → “企稳”；首次进入恢复确认 → “恢复确认”；上一有效交易日为恢复确认、今日不是、且今日非新低 → “恢复撤销”（若因数据缺口中断，原因记“数据缺口”）。**当日解除时不发恢复进度事件。**
5. 观察标签（v0.4 第 2.6 节，只改文案）。

### 1.6 事件清单（替代 v0.4 第 1.3、7.2 节的事件列表）

| 事件 | 触发 | 原因代码示例 | 投递 |
| --- | --- | --- | --- |
| START | 启动预警（附初始等级） | R1\_GE\_K1、R1\_GE\_K2、GAP | 是 |
| ESCALATE | 关注 → 警戒 | D\_EP\_GE\_K2、NEW\_LOW、GIVEBACK | 是；升至警戒不受冷却 |
| DOWNGRADE | 警戒 → 关注 | PRICE\_RECOVERED（a）、RECOVERY\_CONFIRMED（b）、STABLE\_K\_STAB（c） | 是 |
| RELEASE | 关注 → 正常（预警结束） | NEAR\_PEAK（a′）、RECOVERY\_WITH\_REBOUND（b′） | 是 |
| STABILIZED / RECOVERY\_CONFIRMED | 恢复进度首次进入 | — | 是，受冷却 |
| RECOVERY\_REVOKED | 恢复确认今日不再成立 | BELOW\_SMA、DATA\_GAP | 是，受冷却 |
| RECOVERY\_FAIL | 企稳或恢复确认后再创本次新低 | NEW\_LOW | 是，不受冷却 |
| STATE\_CORRECTION | 历史修订导致用户已知状态改变（第 1.7 节） | DATA\_REVISION、CODE\_CHANGE | 是，不受冷却 |
| STOP\_HIT、DATA\_ISSUE | 同 v0.4 | — | 是，不受冷却 |

每个事件附依据：当日 C、D\_ep、U、since\_low、SMA\_S、H\_d 与回吐值、计数段每日证据集合。持续处于某一等级不产生事件。

### 1.7 状态修正（R3-10）

每日发布前，先把“新回放得到的 T−1 日状态”与“T−1 日已发给用户的状态”比较：

- 不同 → 先产生 STATE\_CORRECTION：说明 T−1 日状态由旧值修正为新值、修正原因（数据修订或代码修订）、关联新旧计算尝试；不伪装成当日市场触发。
- 之后，当日事件一律相对修正后的 T−1 状态产生。
- 历史上更早日期的差异只写修订审计，不逐日补发。

这样用户最后知道的状态与系统当前状态之间不会出现断层。

## 3. 单股逐日验收表

这些表是 SR-M2 的核心测试用例：给定每日输入，状态与事件必须逐日与表中一致。它们检验的是状态机的行为，不是市场表现。

### 3.0 共同设定（仅为示例，不是候选参数）

- 高点 d1 收盘 100；ATR 在所有路径中固定为 2（作为给定输入；指标函数另有单元测试）；SMA\_S 作为给定输入列出。

## 4. 评价协议修订（替代 v0.4 第 8.4、8.6、8.8–8.12 节）

评价直接对准核心目标：报警是否及时、解除是否及时、是否过早解除、是否长期挂着、负担多大。所有阈值标【待批准】，在 SR-M1、看结果前由发起人填写；候选不是生效值。样本、期间、冻结、登记纪律沿用 v0.4 第 8.1–8.3、8.13 节。

### 4.1 两套严重下跌事件（R3-09）

| 事件集 | 定义 | 用途 |
| --- | --- | --- |
| E\_atr | 沿用 v0.4 第 8.5 节（D\_eval ≥ X，合并、确认、截尾规则不变） | 主事件集 |
| E\_pct | 收盘距此前 63 日最高收盘回撤首次 ≥ X\_pct【待批准】；峰值日为该最高收盘日；谷底、结束、合并、确认、截尾规则与 E\_atr 相同，只把 “D\_eval < X/2” 换成 “回撤 < X\_pct/2” | 独立审查集，不使用 ATR，避免评价目标偏向同类算法 |

两套事件分别报告全部指标；任一套在门槛上不通过，即不通过。

### 4.2 事件与预警的关联（唯一规则）

- 一次预警关联到一个事件：若预警在事件区间 \[峰值日, 谷底日) 内的任一天处于进行中，即与该事件关联；同时与多个事件重叠时，关联峰值日最早的那个。
- 一个事件关联的预警：区间 \[峰值日, 谷底日) 内第一个处于进行中的预警（含事件开始前已在进行的预警）。
- 未关联任何事件的预警，记为“事件外预警”，计入负担并单独报告。

### 4.3 恢复参考点与各类结果（唯一处理）

- **恢复参考点 R\_E**（只用于事后评价，不进入实时计算）：谷底日之后，首个收盘 ≥ 谷底 + ρ ×（峰值收盘 − 谷底）的交易日；ρ【待批准，候选 0.5】。观察上限：谷底后 Y\_max 个交易日【待批准】。

| 结果类别 | 判定 |
| --- | --- |
| 未提醒 | \[峰值日, 谷底日) 内没有任何进行中的预警 |
| 已提醒、未恢复 | 有预警；观察上限内没有 R\_E。此时预警继续进行是合理的；单独报告其中“已解除”的占比 |
| 已提醒、已恢复、已解除 | 解除延迟 = 解除日 − R\_E（交易日，可以为负，表示早于参考点解除） |
| 长期未解除 | 已恢复，但 R\_E 之后 Y 个交易日【待批准】内仍未解除 |
| 截尾 | 缺价、历史断点、退市、成分退出或期间结束，使上述任一判定无法完成 |
| 跨界 | 开发期内所需窗口（峰值日至 R\_E + Y，或至谷底 + Y\_max）超出开发期 → 剔除并计数；验证期内 → 截尾 |

### 4.4 过早解除与严重不利变化（J-12）

每次解除（日 r，解除收盘 C\_r）之后，固定观察 Q 个交易日【待批准】，同时报告两类指标：

| 指标 | 定义 | 性质 |
| --- | --- | --- |
| 算法再次预警率 | Q 日内本系统再次启动预警的比例 | 算法自身口径，只作参考 |
| 价格路径不利率（门槛指标） | Q 日内任一日收盘满足以下**任一**严重不利变化的比例：① 较 C\_r 下跌 ≥ y\_pct【待批准】；② 较 C\_r 下跌 ≥ y\_atr × A\_r，A\_r 为第 8.7 节评价口径在 r 日的 ATR【待批准】；③ 跌破被解除预警的本次低点 L\_ep | 独立于算法的触发条件 |

严重不利变化不只看是否跌破原低点（①②）。观察期不因新预警启动或结束而提前终止。

### 4.5 主指标与门槛

| 维度 | 指标 | 用法 |
| --- | --- | --- |
| 及时预警 | 首次进行中预警时已实现跌幅 ÷ 事件最大跌幅（中位数，越小越好） | 比较项 1 |
| 不漏报 | 未提醒事件占比 | 门槛 ≤ m【待批准】 |
| 及时解除 | 解除延迟中位数（越小越好） | 比较项 2 |
| 不过早解除 | 价格路径不利率 | 门槛 ≤ p【待批准】 |
| 不长期挂着 | 长期未解除占比 | 门槛 ≤ s【待批准】 |
| 负担 | F（第 4.6 节） | 门槛 |

所有比例同时报告分子、分母；“未提醒”“未解除”“截尾”一律单列，不只对成功样本计算。

### 4.6 F 的生命周期口径（替代 v0.4 第 8.6 节的事件口径）

- 计入 F 的“向上事件”：START（含解除后新预警）与 ESCALATE（含降级后再次加重）。
- 单证券频次、有效观察期、短样本、零事件、跨证券中位数的规则不变（v0.4 第 8.6 节）。
- 必须分别报告：首次启动（距上次解除超过 Q 天或此前无预警）、解除后新预警（距解除 ≤ Q 天）、未降级前的升级、降级后的再次加重；以及解除次数。
- 统计的是信号事件，不受推送分层与冷却影响。

### 4.7 保守口径（R3-11、J-12）

- 主口径：只用结果确定的事件。
- 保守口径：全部事件；截尾事件中，截至最后可观察日已能判定的结果按实际计入（例如截尾前已回撤到阈值以上且没有任何预警 → 计为未提醒）；仍无法判定的，一律按不利方向计入（未提醒、长期未解除、过早解除）。
- 两种口径任一门槛不通过，或两种口径对“是否优于基线”的结论相反 → 不宣布通过。

### 4.8 基线（生命周期版本）

| 基线 | 规则 |
| --- | --- |
| B1 固定百分比 | 滚动回撤 ≥ 10% 关注、≥ 20% 警戒；回撤回到相应阈值以内连续 d 天降一级或解除；不冻结基准 |
| B2 均线 | 收盘 < SMA50 进入关注；连续 d 天收盘 > SMA50 解除 |
| B3 随机日期 | 只用于“及时预警”维度的健全性检查，规则同 v0.4 |

开发期结束时，按两个比较项分别冻结表现更好的基线（B1 或 B2）。

### 4.9 选参（单阶段，替代 v0.4 第 8.9 节两阶段）

生命周期参数与启动参数相互影响，改为单阶段：

1. **门槛**：F、m、p、s 全部满足（两套事件集、两种口径都满足）。
2. **排序元组**：(及时预警指标升序, 解除延迟中位数升序, 网格序号升序)；并列集合相对全局最优一次确定（容差【待批准】）。
3. **稳健性**：每个一步相邻点也满足全部门槛，且及时预警指标不比所选点差超过 Δ【待批准】；不满足则按排序取下一个。
4. **无合格候选**：停止，请发起人裁决，不放宽门槛。
5. **改进量**：Δ\_w = 基线已实现跌幅比 − 候选已实现跌幅比；Δ\_r = 基线解除延迟 − 候选解除延迟；均为越大越好，“优于基线”指 95% 区间下限 > 0。

### 4.10 确认性检验

验证期只做两次：Δ\_w 与 Δ\_r 对冻结基线；单侧，原假设改进量 ≤ 0；p 值取自第 4.11 节重采样分布中改进量 ≤ 0 的比例；两个 p 值 Holm 校正，α = 0.05。保守口径同时报告。

### 4.11 重采样：同时保留事件内与同期多股关联（R3-12）

- **记录归属**：每个严重下跌事件及其关联的全部预警、降级、解除、恢复记录，构成一个“事件簇”；事件外预警按启动日单独成簇。候选与基线在同一事件上配对，作为同一簇内的配对记录。
- **归块**：每个簇按其开始日（事件为峰值日，事件外预警为启动日）归入一个 63 个交易日的日历块；簇不拆分，即使跨越多个块。
- **抽样**：有放回抽取与原始块数相同的日历块；抽中块内的全部簇（来自所有股票）整体计入。这样同一事件内的关联（簇不拆）和同期多股的关联（同块同抽）同时保留。
- **分母为零**：某次重复中某指标分母为零，该次该指标记为缺失；缺失次数超过 1% 视为样本不足。
- **区间检验**：SR-M1 登记之前，用构造数据（不含任何真实验证期数据）做模拟，检查区间的实际覆盖率；覆盖率明显偏离 95% 时，调整块长或改用其他方法，并把模拟结果与最终方法一并登记。
- 2000 次，种子登记，百分位法。

### 4.12 最小样本

按事件集分别要求：结果确定的事件 ≥ 30 个、来自 ≥ 10 只证券、分布于 ≥ 8 个块；已恢复并已解除的事件 ≥ 30 个（解除延迟指标）；解除次数 ≥ 30 次（过早解除指标）。数值【待批准】；不足则只报告描述统计并请发起人裁决。

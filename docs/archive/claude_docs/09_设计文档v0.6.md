## 1. 预警生命周期规格（替代 v0.5 第 1 节）

### 1.1 状态与预警编号

| 状态 | 含义 |
| --- | --- |
| 正常 | 无进行中的预警 |
| 关注 / 警戒 | 预警进行中 |
| 数据中断（显示状态） | 连续缺价达到历史断点；无法评估，不等于正常或解除 |
| 不可计算（显示状态） | 历史段不足 W + N 条 |

每次启动分配**预警编号** episode\_id；该预警存续期间的全部事件与通知（含恢复观察、解除）都关联此编号。

预警字段：P\_ep、p\_ep、ATR\_ep（冻结）；L\_ep、l\_ep（本次低点）；s\_ep（开始日）；downgraded（是否降级过）；H\_d（降级后高点）；obs\_start（稳定观察起点）；cycle\_no（观察周期序号）；box\_high（企稳区间最高收盘，仅区间法）；三个计数（降级计数 dc、解除计数 rc、强恢复计数 xc）；连续缺价天数 m；最近中断日。

### 1.2 低点追踪与稳定观察（J-15、R4-04）

两者分开更新：

| 事件 | L\_ep（低点追踪） | obs\_start（稳定观察起点） | cycle\_no |
| --- | --- | --- | --- |
| 启动 | \[p\_ep, T\] 最低收盘及其日期 | T | 1 |
| 今日新低（C < L\_ep − ε\_p） | 更新为今日 | T | 加一 |
| 任何加重（关注 → 警戒） | 不变 | T | 加一 |
| 当日缺价 | 不变 | T（中断日） | 加一 |
| 其他有效交易日 | 不变 | 不变 | 不变 |

- **since\_obs** = obs\_start 之后到 T 的有效交易日数（obs\_start 当日为 0）。
- **企稳** = since\_obs ≥ K。
- **长期稳定** = since\_obs ≥ K\_stab。因 obs\_start 在任何加重时重置，新恶化前积累的天数不能支持再次降级。

### 1.3 恢复确认的两种方法（J-14，候选维度 confirm ∈ {SMA, BOX}）

| 项 | SMA 法 | 区间法（BOX） |
| --- | --- | --- |
| 当日成立 | 企稳，且 C > SMA10(T) + ε\_p | 企稳，且 T > obs\_start + K，且 C > box\_high + ε\_p |
| 比较对象 | 当日 10 日均线（含当日） | 企稳区间：obs\_start 之后的第 1 至第 K 个有效交易日的收盘；在第 K 天（首次企稳日）**冻结**，box\_high 为其最高值；比较时**不含当日**，首次企稳日当天不可能成立 |
| 撤销 | 上一有效交易日成立，今日不成立且今日非新低 → RECOVERY\_REVOKED（原因 BELOW\_SMA） | 同左，原因 BACK\_INTO\_BOX（C ≤ box\_high） |
| 重建 | 随 cycle\_no 变化（新低、加重、缺价）自动重新开始 | 同左；box 清空，新周期首次企稳时重新冻结 |
| 失效 | 新低 → RECOVERY\_FAIL（上一有效交易日企稳或确认成立时） | 同左 |

### 1.4 其他当日证据

| 证据 | 定义 |
| --- | --- |
| 受限滚动回撤 D\_T | 窗口起点 = max(T − W + 1, 最近一次解除日)；P^max 为窗口最高收盘（并列取最近）；D\_T = (P^max − C) / ATR\_N(P^max 日)。只用于启动 |
| R2 | 同 v0.4 第 2.3 节，只用于启动，含义“至少关注”（g 固定，见第 4 节） |
| D\_ep | (P\_ep − C) / ATR\_ep |
| U | (C − L\_ep) / ATR\_ep，用更新后的 L\_ep |
| 回吐比率 | 仅已降级时：(H\_d − C) / ATR\_ep，H\_d = max(H\_d, C)（含当日）。**与 k₁ 比较，两边都是 ATR 倍数**（R4-02） |
| 降级证据 E\_down | a：D\_ep < k₂；b：恢复确认成立；c：长期稳定 |
| 解除证据 E\_rel | a′：D\_ep < k₁；b′：强恢复 |
| 强恢复 | 恢复确认成立，且 U ≥ u\_rel |
| 新低日 | E\_down、E\_rel、强恢复一律视为空 |

### 1.5 计数与强恢复直接解除（J-20）

- dc：仅在警戒时累计，E\_down 非空加一、为空清零。
- rc：仅在关注时累计，E\_rel 非空加一、为空清零。
- xc：仅当候选维度 release\_path = DIRECT 且处于警戒时累计，强恢复成立加一、不成立清零。**不跨等级累计**：任何等级变化后清零。
- 原因交替：只要当日证据集合非空，计数连续累计，不要求同一项。
- 清零：任何等级变化、当日缺价、新低日、证据集合为空。
- 同日优先（警戒）：xc 达到 d → 直接解除；否则 dc 达到 d → 降级。因强恢复 ⊂ 恢复确认 ⊂ E\_down，xc ≤ dc 恒成立。
- 每天最多一次等级变化。

### 1.6 当日处理顺序

1. **数据**：当日缺价 → m 加一。若 m ≤ G：冻结等级与字段，三计数清零，obs\_start = T、cycle\_no 加一，只发 DATA\_ISSUE，结束。若 m = G + 1：历史断点确认，进行中的预警以“数据中断”结束（DATA\_BREAK），显示“数据中断”，结束。有效交易日 m 清零。
2. **计算全部证据**（第 1.2–1.4 节）。
3. **无预警**：判断启动（T4/T5），结束。
4. **有预警**，依次：
   1. 新低处理（L\_ep、obs\_start、cycle\_no；上一有效交易日企稳或确认成立 → RECOVERY\_FAIL）。
   2. 加重判断（第 2 节 T7–T9）。加重则：obs\_start = T、cycle\_no 加一、三计数清零，跳到第 4.4 步。**不加重时继续第 4.3 步**（R4-01）。
   3. 降级或解除（T10–T15）。
   4. 恢复进度事件：首次企稳 → STABILIZED；确认由不成立变为成立 → RECOVERY\_OBS；撤销 → RECOVERY\_REVOKED。**当日解除时不发**这些事件。
5. 观察标签（v0.4 第 2.6 节）。

### 1.7 事件与业务身份

| 事件 | 业务身份 key（重跑、补发不变） |
| --- | --- |
| START、ESCALATE、DOWNGRADE、RELEASE、DATA\_BREAK | (episode\_id, 类型, 信号日) |
| STABILIZED | (episode\_id, cycle\_no) |
| RECOVERY\_OBS | (episode\_id, cycle\_no, 本周期第 n 次成立) |
| RECOVERY\_REVOKED | (episode\_id, cycle\_no, 对应的第 n 次) |
| RECOVERY\_FAIL | (episode\_id, 被终止的 cycle\_no) |
| STATE\_CORRECTION、STATE\_BRIDGE | (security\_id, 比较基准日, 新计算尝试) |

恢复确认反复成立时，同一周期内每次成立都是一个新的业务事件（序号 n 递增），评价中统计每次预警的反复次数。

**通知文案只陈述事实**，例：RECOVERY\_OBS：“连续 3 个有效交易日未创本次新低，且收盘 76.00 高于企稳区间最高收盘 74.00。”RELEASE：“预警解除：登记的风险条件已缓解。依据：……”不使用“底部确认”，不给操作或仓位建议。

### 1.8 状态修正与衔接（R4-06）

比较基准为该证券**最近一次已发布结果**（日期 P，可以早于 T−1）及其投递记录：

| 情况 | 处理 |
| --- | --- |
| 回放得到的 P 日状态 ≠ 已发布的 P 日状态 | 先发 STATE\_CORRECTION（P 日旧值 → 新值，原因：数据修订或代码修订，关联新旧计算尝试） |
| P 与 T 之间有未发布的交易日 | 再发 STATE\_BRIDGE：列出 P+1 至 T−1 间的全部生命周期事件（信号日期、依据），一条消息；不逐日补发 |
| P 日结果的投递为 FAILED 或 UNKNOWN | 视为用户不知晓，改发“当前状态快照”（预警编号、等级、恢复进度、依据），不发增量 |
| 没有任何已发布结果 | 发首次状态快照 |

之后，当日事件相对回放得到的 T−1 状态产生。发布状态与是否送达分别记录。

## 3. 理论最短等待（R4-05、J-20）

**前提**：警戒状态下，在最近一次稳定观察起点日 t（新低日、加重日或缺价日）之后，每个有效交易日恢复确认都成立、强恢复也都成立（U ≥ u\_rel），且不经由 a、a′、c 证据。下表是**下限**，实际等待还受均线滞后、反弹幅度不足、撤销与缺价影响，由评价实测。

**推导**

- 企稳：since\_obs = K，即 t + K。
- 恢复确认最早日：SMA 法在企稳当日即可成立 → t + K；区间法须排除首次企稳日 → t + K + 1。记为 t + K + e，SMA 法 e = 0，区间法 e = 1。
- 两段解除：dc 自确认最早日起累计 d 天降级 → t + K + e + d − 1；次日起 rc 累计 d 天解除 → t + K + e + 2d − 1。
- 直接解除：xc 自确认最早日起累计 d 天 → t + K + e + d − 1。
- 恢复观察通知：即确认最早日 t + K + e。

**表：自起点日 t 起的有效交易日数（下限）**

| K | d | 恢复观察 SMA | 恢复观察 区间 | 两段解除 SMA | 两段解除 区间 | 直接解除 SMA | 直接解除 区间 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 3 | 3 | 3 | 4 | 8 | 9 | 5 | 6 |
| 3 | 5 | 3 | 4 | 12 | 13 | 7 | 8 |
| 5 | 3 | 5 | 6 | 10 | 11 | 7 | 8 |
| 5 | 5 | 5 | 6 | 14 | 15 | 9 | 10 |

**例外与补充**

- 若价格回升到 k₂ 以内（a 成立），降级可以早于企稳；若接近原高点（a′ 成立），解除可以不依赖恢复确认。浅跌时实际等待可能短于上表。
- SMA 法的“当日即可成立”只是规则允许的下限；暴跌后均线含暴跌前高价时，确认可能明显推迟（见第 7.2 节 F1、F5）。区间法则可能因区间内出现单日高点而推迟（见 F2）。两者的取舍由评价决定。
- 再次加重后，起点 t 重置为加重日，上表从加重日重新计算。

## 4. 候选全集（替代 v0.5 第 5.1–5.2 节）

### 4.1 全集：8 个维度，共 2⁸ = 256 组，全部评价

| N（ATR 窗口） | {14, 20} |
| k₁ | {2, 3} |
| k₂ | {4, 5} |
| K | {3, 5} |
| d | {3, 5} |
| u\_rel | {3, 5} |
| confirm（恢复确认方法） | {SMA, BOX} |
| release\_path（解除路径） | {TWO\_STAGE, DIRECT}（DIRECT 时仍保留两段路径，另加 T13） |

网格序号：按上表自上而下的字典序编号 1–256。

**不删减**。计算成本很低，没有必要在看结果前删减；删减反而需要额外理由。候选数量多会增加选参的乐观偏差：所选候选的开发期表现会高估其真实表现。这一点不能靠“控制在 64 组以内”消除，只能靠第 5 节的门槛、稳健性要求、冻结后的验证期，以及报告全部候选结果来约束。报告中会写明候选总数。

### 4.2 固定值（事前固定，不进入选参）

| 参数 | 值 | 理由 |
| --- | --- | --- |
| W | 63 | 沿用 |
| freeze | 是（ATR 取峰值日） | 预警基准冻结；启动时 D\_T 与 D\_ep 同一基准 |
| g | 3 | 跳空只影响启动；固定以控制维度 |

## 5. 评价协议修订（替代 v0.5 第 4 节）

样本、期间、冻结、两套事件集的定义（E\_atr、E\_pct）、截尾与跨界规则沿用 v0.4 第 8.1–8.5 节与 v0.5 第 4.1 节。所有阈值标【待批准】，SR-M1 前由发起人填写；Y 暂不填写（J-20）。

### 5.1 信号日期与送达日期（J-16）

算法指标一律按**信号日期**（事件的 as\_of 交易日）计算；投递另设指标（第 5.9 节），按实际送达时间计算。推送分层、冷却、渠道故障不改变算法指标。

### 5.2 覆盖关系与归属关系（R4-07、J-17）

| 关系 | 规则 |
| --- | --- |
| 覆盖（多对多） | 预警在事件 \[峰值日, 谷底日) 内任一天进行中，即“覆盖”该事件；只用于继承覆盖与占用统计 |
| 预警归属（唯一） | 预警的 START 信号日落在某事件的 \[峰值日, 谷底日) 内 → 归属该事件（若落在多个事件内，取峰值日最早者）；START 早于其覆盖的所有事件 → 归属其覆盖的最早事件，标“继承” |
| 解除归属（唯一） | 每次 RELEASE 归属其所在预警；评价只在该解除之后的固定窗口 Q 与较长窗口 Q\_L 内进行（第 5.6 节），窗口之后的新下跌**不追溯**到这次解除 |
| 两套事件集 | 分别独立建立覆盖与归属，不互相抢占 |

### 5.3 每个事件的结果类别（共同事件全集，J-18）

对每个事件、每个方法（候选或基线），先判定类别，再给出两个“事件得分”；全集包含所有类别，不取交集。

| 类别 | 判定 |
| --- | --- |
| 新通知 | 信号日落在 \[峰值日, 谷底日) 内的第一个 START 或 ESCALATE（至警戒） |
| 继承覆盖 | 区间内没有新通知，但峰值日已有进行中的预警 |
| 未提醒 | 区间内没有新通知，峰值日也没有进行中的预警 |
| 截尾 | 按 v0.4 第 8.5 节规则无法确定事件 |

**得分一：新通知及时性** S1 ∈ \[0, 1\]，越小越好：新通知 → 信号日已实现跌幅 ÷ 事件最大跌幅；继承覆盖、未提醒 → 1（长期挂着的旧预警不获得新通知及时性）。继承覆盖率另行报告。

**得分二：恢复后预警滞留** S2（交易日，越小越好）：从恢复参考点 R\_E 起，该证券处于进行中预警（任何预警）的交易日数，上限 Y\_cap【待批准，Y 确定后取 Y】。未恢复事件不计 S2。此定义对所有已恢复事件都有值：未提醒的方法 S2 为 0，其代价已在 S1 体现；早于 R\_E 解除的方法 S2 为 0，不再因“负延迟”获额外奖励，其风险由第 5.6 节的不利变化评价。

### 5.4 恢复参考点与回升幅度口径（J-20）

- R\_E：谷底日之后，首个收盘 ≥ 谷底 + ρ ×（峰值收盘 − 谷底）的交易日；ρ【待批准】。观察上限 Y\_max【待批准】。
- 对每个 RECOVERY\_OBS（每次预警的首个，以及全部次数）与每个 RELEASE，报告三个口径：
  - 距谷底的交易日数；
  - 回升占比 =（信号日收盘 − 谷底）÷（峰值收盘 − 谷底）；
  - 距低点涨幅 = 信号日收盘 ÷ 谷底 − 1。
- 发起人可据这三个口径登记及时性要求（Y 等）。

### 5.5 恢复观察的评价

每个 RECOVERY\_OBS 之后固定 Q 个交易日：是否再创本次新低（恢复失败）、是否出现第 5.6 节的严重不利变化；每次预警内恢复观察的反复次数。只报告，不设否决门槛（门槛如需设置，另行批准）。

### 5.6 解除后的不利变化（J-17）

每个 RELEASE（日 r，收盘 C\_r）之后，事前固定两个窗口：Q 与 Q\_L（Q\_L > Q）【均待批准】。严重不利变化：窗口内任一日收盘满足 ① 较 C\_r 下跌 ≥ y\_pct；② 较 C\_r 下跌 ≥ y\_atr × A\_r（A\_r 为 v0.4 第 8.7 节评价口径在 r 日的 ATR）；③ 跌破所解除预警的 L\_ep。两个窗口分别报告不利率；Q 窗口不利率为门槛指标。“解除发生在归属事件最终谷底之前”的占比**单独报告，不作为错误标签或否决条件**。

### 5.8 确认性比较（J-18）

- 只在 E\_pct 上做两项：候选对冻结基线的 S1 改进与 S2 改进。改进量 = 基线均值 − 候选均值，均为越大越好。
- 理由：减少与 ATR 算法同型的评价偏向；百分比事件集不是天然公正，也并非与算法完全无关（都基于价格回撤）。
- ATR 事件集只承担门槛与描述，不做显著性声明。
- 配对：同一事件上候选与基线的得分差；全集包括全部类别；截尾事件按保守口径另报。
- 单侧检验，原假设改进量 ≤ 0；Holm 校正，α = 0.05；重采样见第 5.11 节。

### 5.11 基线与重采样

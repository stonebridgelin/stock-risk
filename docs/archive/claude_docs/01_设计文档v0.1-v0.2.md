## 1. 产品需求

第一版是一个收盘后运行的命令行任务：对 20–50 只自选美股计算风险状态与反弹阶段，每天产出一张提醒表并推送，同时生成执行记录待填行。它只回答“发生了什么、属于哪一层、证据是什么”，不回答“会不会涨”。

### 1.1 用户与场景

| 场景 | 用户想知道 | 系统给出 |
| --- | --- | --- |
| S1 持仓股大跌 | 这是大盘、板块还是公司自己的问题？要不要按预案执行？ | 风险状态变化提醒 + 归因层（市场/板块/个股）+ 触发数值 + 我事先写的预案动作 |
| S2 观察中的股票止跌 | 跌势是否停下？是否满足我事先定的再买条件？ | 反弹阶段提醒（止跌观察 → 反弹确认 → 趋势恢复），附失效价位 |
| S3 反弹失败 | 之前的止跌信号是否作废？ | “反弹失败”提醒，状态退回下跌 |
| S4 数据异常 | 今天的信号能不能信？ | 数据缺失/停牌/异常跳变提醒；受影响股票状态冻结并标注 |
| S5 复盘 | 我有多少次没照信号做？事后看对不对？ | 执行记录表与季度统计（第一版提供表与导出，统计脚本可后做） |
| S6 维护名单 | 加入/移出观察股，填预案 | 命令行维护观察名单与预案（第一版），将来前端页面 |

### 1.2 每日使用流程

1. 美东收盘后（具体时刻【待确认】，需晚于 Tiger 日线数据定稿时间），定时任务 `daily_close_job` 启动。
2. 拉取当日日线与复权因子 → 数据核对（缺失、重复、异常跳变）→ 写入新数据版本。
3. 读取大盘背景：第一版用本项目自算的简化大盘状态（见 2.6）；market-risk 每日输出可用后改为读取【待 M3】。
4. 逐股计算指标 → 风险状态机 → 反弹阶段机 → 生成提醒（去重、冷却）。
5. 写入提醒表、状态历史、执行记录待填行；推送当日摘要。
6. 发起人阅读推送，按预案操作，在执行记录中填写“实际操作、是否一致、理由”。偏离信号的操作先写理由，次日再决定（偏离冷静期）。
7. 运行失败（缺数据、校验不过）时：不产出当日信号，推送“今日未出信号”及原因，不默认沿用昨日状态为“正常”。

### 1.3 提醒种类

| 代码 | 名称 | 触发 | 级别 |
| --- | --- | --- | --- |
| RISK\_UP | 风险升级 | 风险状态上升（可跨级） | 重要 |
| RISK\_DOWN | 风险降级 | 风险状态下降一档（需连续确认） | 一般 |
| RB\_WATCH | 止跌观察 | 进入止跌观察阶段 | 一般 |
| RB\_CONFIRM | 反弹确认 | 进入反弹确认阶段 | 重要 |
| RB\_TREND | 趋势恢复 | 进入趋势恢复阶段 | 一般 |
| RB\_FAIL | 反弹失败 | 跌破止跌观察期最低点 | 重要 |
| STOP\_HIT | 波动率止损触及 | 持仓股收盘跌破“买入价 − k×ATR”（k 由发起人填） | 重要 |
| DATA\_ISSUE | 数据异常 | 缺价、停牌、异常跳变、复权因子突变 | 重要 |
| CB\_HALT | 组合熔断 | 个股账户回撤达到发起人填写的熔断线 | 重要 |
| EVENT\_SOON | 事件临近 | 未来 5 个交易日内有财报/宏观事件（非第一版必做） | 提示 |

### 1.4 提醒内容样例

以下数值均为虚构示例，仅示格式。

```
[风险升级] NVDA  正常 → 警戒   2026-10-12 收盘（T 日），供 T+1 参考
归因：个股层
- 收盘距 63 日最高收盘回撤 14.2%，= 3.4 × ATR(20)（阈值 3.0 × ATR，冻结于下跌起点 2026-09-30）
- 相对 SMH 超额回撤 −9.8%；SMH 同期回撤 4.4%
- 大盘背景：简化版“正常”（SPX 回撤 2.1%，站上 200 日均线）；market-risk 背景：未接入
- 近 5 个交易日事件：无
你的预案：警戒时减半持仓；禁止加仓
执行记录：请在 journal 中填写（编号 J-2026-10-12-007）
```

```
[反弹确认] AMD   止跌观察 → 反弹确认   2026-10-12 收盘
- 连续 6 天未创 20 日新低（要求 ≥ 5）；收盘 152.30 站上 10 日均线 149.80
- 失效价位：止跌观察期最低收盘 141.05，收盘跌破即提醒“反弹失败”
- 大盘背景：简化版“一级”→ 本提醒降级为“观察”，标注“大盘尚未止跌”
你的预案：反弹确认后允许按风险预算重新建仓（数量由你定）
```

```
[数据异常] XYZ  2026-10-12 缺少日线
- 状态冻结：保持“关注”，不进入也不解除任何状态
- 请检查：停牌/代码变更/数据源延迟
```

### 1.5 明确不做的事

- 不预测顶部、底部、涨跌概率，不输出“胜率”。
- 不给买卖数量；风险预算倒推股数只在发起人填写比例后作为“参考计算”显示，不下单。
- 不连接交易接口、不自动下单。
- 不做盘中实时、分钟线（第一版）。
- 不覆盖中概股、A 股、港股、ETF 个体预警（ETF 只作为板块参照）。
- LLM 不进入信号计算；第一版不做 LLM 功能。
- 第一版不开发 FastAPI 与前端，只规划。
- 不修改 market-risk，不导入其内部模块，不把它当生产依赖。

## 2. 规则规格

第一版建议：风险预警 3 条规则（R1 波动率归一化回撤、R2 跳空大跌、R3 三层归因）+ 一个三档状态机；反弹三阶段全部定义，第一版实现前两阶段（止跌观察、反弹确认）与失效条件，第三阶段（趋势恢复）定义完整但可作为第一版的可选项。所有参数只给候选网格，待登记。【推断】

### 2.0 通用口径

- **价格**：全部用复权价（开、高、低、收同一复权因子），复权方式见第 4 节；每次计算绑定一个数据版本 `data_version_id`。
- **时间**：T 日收盘后计算，信号日期 = T，供 T+1 参考；所有 domain 函数接收 `as_of=T`，只用 ≤ T 的数据。
- **交易日**：以美股交易所日历为准（实现用 `exchange_calendars` 的 XNYS 或同类库【推断，待登记】），不以“数据里有的日期”为准，这样才能发现缺价。
- **浮点容差**：ε = 1e-10（沿用 market-risk 口径【初稿】）。比较“≥ 阈值”一律写成 `x ≥ k − ε`，“> 阈值”写成 `x > k + ε`，并在测试中覆盖等号边界。
- **明确失败**：输入出现非有限值（NaN/inf）、长度不一致、价格 ≤ 0 → 抛 `InvalidInputError`，不返回空值。
- **窗口不足**：所需历史条数不足 → 返回显式状态 `INSUFFICIENT_HISTORY`；状态机不进入也不解除任何状态，提醒表注明。
- **缺价/停牌**：T 日该股无日线，或窗口内任一交易日缺价 → 不插值，返回 `MISSING_DATA`；状态冻结在上一有效状态，发 DATA\_ISSUE 提醒。

### 2.1 基础指标

真实波幅与 ATR（简单平均，便于手工推导期望值；Wilder 平滑作为备选登记）：

```latex
TR_t = \max\left(H_t - L_t,\ |H_t - C_{t-1}|,\ |L_t - C_{t-1}|\right), \qquad ATR_N(t) = \frac{1}{N}\sum_{i=0}^{N-1} TR_{t-i}
```

- 输入：复权 H、L、C，需 N+1 条（第一条只提供 C\_{t−1}）。
- 边界：ATR = 0（如长期停牌后无波动）→ `InvalidInputError("ATR 非正")`，不产生信号。
- 备选（Q3 裁决）：日对数收益标准差 σ\_N；本文建议第一版用 ATR，理由见第 9 节。

简单均线：SMA\_M(t) = 最近 M 个收盘价平均，需 M 条。

### 2.2 R1 波动率归一化回撤（风险主规则）

```latex
P^{max}_t = \max_{t-W+1 \le i \le t} C_i, \qquad D_t = \frac{P^{max}_t - C_t}{ATR_N(\tau)}
```

- τ 为 ATR 取值日：**冻结**方案 τ = 峰值日（W 日最高收盘出现的那天，只用峰值日及以前数据）；**不冻结**方案 τ = T。冻结与否作为候选登记（Q3）。
- 隐含等级：D\_t ≥ k₂ − ε → 警戒（2）；否则 D\_t ≥ k₁ − ε → 关注（1）；否则正常（0）。要求 k₁ < k₂。
- 输入：W 条收盘价 + 计算 ATR 所需 N+1 条（冻结时以峰值日为终点）。所需历史 = W + N（保守取值）。
- 峰值日并列：取最近的一天（确定性规则，需测试覆盖）。
- 同时输出百分比回撤 DD\_t = 1 − C\_t / P^max\_t，仅用于解释文字，不参与判定。

### 2.3 R2 跳空大跌（个股层快速升级）

```latex
G_t = \frac{O_t - C_{t-1}}{ATR_N(t-1)}
```

- 触发：G\_t ≤ −g + ε 且 C\_t < C\_{t−1}（收盘仍低于前收，排除盘中回补的跳空）→ 隐含等级至少为关注（1）。
- ATR 用 t−1 日值，避免当日大跌抬高分母。
- 财报日跳空同样触发，但提醒中附“财报日”标签（若事件表有记录）。
- 边界：缺开盘价 → MISSING\_DATA。

### 2.4 R3 三层归因（解释用，不单独升级）

以 R1 的峰值日 p 到 T 为区间，分解个股收益（r 为区间简单收益）：

```latex
r_s = \underbrace{r_{mkt}}_{\text{市场层}} + \underbrace{(r_{sec} - r_{mkt})}_{\text{板块层}} + \underbrace{(r_s - r_{sec})}_{\text{个股层}}
```

- r\_mkt 用 SPY 复权价（是否可用 SPX 指数数据【待确认】），r\_sec 用该股映射的板块 ETF（如 XLK、SMH、XLF；映射在观察名单表中由发起人维护）。
- 归因层 = 三项中负贡献最大的一项；并列（差 ≤ ε）按 市场 > 板块 > 个股 取前者。
- 未映射板块 → 板块项并入个股项，提醒注明“板块未映射”。
- 参照 ETF 缺价 → 归因为“未知”，风险等级照常计算。
- 第一版只用于解释与统计，不改变状态；“相对板块走弱单独升级”列为第二版候选规则（R4），先在研究中评价。

### 2.5 风险状态机

| 项 | 规则 |
| --- | --- |
| 状态 | 0 正常 / 1 关注 / 2 警戒（名称待 Q1 定） |
| 隐含等级 | L\_t = max(R1 等级, R2 等级) |
| 升级 | L\_t > 当前状态 → 当日直接升到 L\_t（可跨级），发 RISK\_UP |
| 降级 | 连续 d 个交易日 L\_t < 当前状态 → 降一档，发 RISK\_DOWN；计数在 L\_t ≥ 当前状态的那天清零 |
| 冷却/去重 | 同一股票进入同一状态，c 个交易日内只提醒一次；升级到更高状态不受冷却限制 |
| 冻结 | MISSING\_DATA / INSUFFICIENT\_HISTORY 当日状态与降级计数都不变 |
| 初始化 | 新加入观察名单的股票从历史起点回放到 T，得到当日状态（不发历史提醒） |

### 2.6 简化大盘背景（market-risk 接入前的替代）

**明确标注为“本项目简化代理”，不等于 market-risk 状态，提醒中两者分开显示。**【推断】

- 输入：SPY、QQQ 复权收盘。
- 一级：任一资产距 63 日最高收盘回撤 ≥ θ₁；二级：任一资产回撤 ≥ θ₂（θ₁ < θ₂）。
- 大盘止跌：两资产都连续 K\_m 天未创 20 日收盘新低。
- 备选：发起人每日手工录入大盘状态（Q7）。
- market-risk 每日输出（H-7）可用后，提醒同时显示两者，研究中比较二者对反弹过滤的效果【待 M3】。

### 2.7 反弹三阶段

反弹链只从“风险状态 ≥ 1”开始；阶段只升不跳（RB1 → RB2 → RB3），任何阶段触发失效即回到“下跌中”。

**锚点**：A = 本轮下跌中最近一次创 N\_low 日收盘新低的收盘价（复权）。新低定义：

```latex
C_t \le \min_{t-N_{low} \le i \le t-1} C_i + \varepsilon
```

| 阶段 | 进入条件 | 输入 | 边界 |
| --- | --- | --- | --- |
| RB1 止跌观察 | 风险状态 ≥ 1，且距上次创 N\_low 日新低已连续 K 个交易日未再创新低 | 收盘价 N\_low + K 条 | 第 K 天恰好不创新低即进入（计数从新低次日起算为 1） |
| RB2 反弹确认 | 已处于 RB1，且 C\_t > SMA\_S(t) + ε | 收盘价 S 条 | 收盘恰等于均线不算站上 |
| RB3 趋势恢复 | 已处于 RB2，且 C\_t > SMA\_M(t) + ε，且相对强弱线 RS = C / C\_SPY 满足 RS\_t ≥ SMA\_R(RS)(t) − ε | 个股与 SPY 各 max(M, R) 条 | SPY 缺价 → RB3 判定暂停，不降级 |

&#91;embedded content: 反弹三阶段状态链 · 失效回路与市场过滤\]

三个阶段只能依次进入；红线表示任一阶段收盘跌破锚点都回到“下跌中”。

**失效条件**：处于 RB1/RB2/RB3 任一阶段时，C\_t < A − ε → 发 RB\_FAIL，反弹链清空，回到“下跌中”，锚点随后续新低更新。

**结束条件**：风险状态回到 0 → 反弹链结束，无论当时处于哪个阶段，记录结束原因（v0.2 修订，理由见 2.9 节 I3）。

**市场过滤**：大盘背景为二级（简化代理或 market-risk）时，RB2、RB3 照常计算与记录，但提醒降级为“观察”，标注“大盘尚未止跌”。过滤是否提高可靠性，在第 7 节评价中对比“有/无过滤”，不预设有效。

**第二版候选**：“更高的低点”作为 RB2 的替代条件（需先定义摆动低点，规则较复杂，第一版不做）。

### 2.9 逐日步进算法与两条状态链的交互（v0.2 新增）

每只股票每个交易日按固定顺序执行一次 `step_symbol`：数据检查 → 指标 → 风险状态机 → 反弹链 → 市场标注 → 去重冷却。顺序写死，同样的输入永远得到同样的状态和提醒。【推断，请审阅】

```python
def step_symbol(prev: SymbolState, s: PriceSeries, refs: RefSeries, as_of: date,
                market: MarketState, rp: RiskParams, bp: ReboundParams, eps: float
               ) -> tuple[SymbolState, list[Transition]]:
    out: list[Transition] = []

    # 0. 数据检查：缺价或窗口不足 → 整体冻结（风险等级、降级计数、反弹阶段、新低计数都不变）
    status = check_inputs(s, as_of, need=rp.w + rp.n)
    if status is not CalcStatus.OK:
        return prev.frozen(as_of, status), [Transition("DATA_ISSUE", ...)] if status is MISSING_DATA else []

    # 1. 指标（只用 <= as_of 的数据）
    dd = normalized_drawdown(s, as_of, rp)              # D_t、峰值、峰值日、ATR_ref
    g  = gap_score(s, as_of, rp.n)
    L  = implied_level(dd, g, rp, eps)

    # 2. 风险状态机
    risk, cnt = prev.risk_level, prev.downgrade_counter
    if L > risk:                                         # 升级：即时、可跨级、计数清零
        out.append(Transition("RISK_UP", risk, L, evidence(dd, g)));  risk, cnt = L, 0
    elif L < risk:                                       # 降级：连续 d 天才降一档
        cnt += 1
        if cnt >= rp.d:
            out.append(Transition("RISK_DOWN", risk, risk - 1, evidence(dd, g)));  risk, cnt = risk - 1, 0
    else:
        cnt = 0

    # 3. 反弹链（使用第 2 步之后的风险等级）
    stage, anchor, since_low = prev.rebound_stage, prev.anchor_price, prev.days_since_new_low
    c = s.close_at(as_of)
    new_low = is_new_low(s, as_of, bp.n_low, eps)

    if risk == RiskLevel.NORMAL:                         # I3：风险回到 0，链结束
        if stage is not ReboundStage.NONE or anchor is not None:
            out.append(Transition("RB_END", stage, "NONE", {"reason": "RISK_NORMAL"}))  # 只记录不推送
        stage, anchor, since_low = ReboundStage.NONE, None, 0
    else:
        if anchor is None:                               # I1：刚进入下跌，锚点初始化
            anchor, since_low = last_new_low_close(s, as_of, bp.n_low, eps)
        if stage is not ReboundStage.NONE and c < anchor - eps:      # I2：失效优先于推进
            out.append(Transition("RB_FAIL", stage, "NONE", {"anchor": anchor, "close": c}))
            stage, anchor, since_low = ReboundStage.NONE, c, 0
        else:
            if new_low:
                anchor, since_low = c, 0
            else:
                since_low += 1
            nxt = next_stage(stage, s, refs.spy, as_of, since_low, bp, eps)   # I4：每天最多推进一级
            if nxt is not stage:
                out.append(Transition(STAGE_ALERT[nxt], stage, nxt, stage_evidence(...)))
                stage = nxt

    # 4. 市场标注：大盘二级时，RB_CONFIRM / RB_TREND 标“观察”，不改变状态
    out = [label_market(t, market) for t in out]

    # 5. 去重冷却：同类提醒 c 天内只推一次；RISK_UP（升到更高级）与 RB_FAIL 不受冷却限制
    out, last_alert_on = apply_cooldown(out, prev.last_alert_on, as_of, rp.c)

    return SymbolState(risk, cnt, stage, anchor, since_low, last_alert_on), out
```

**交互规则（逐条，便于写测试）**

| 编号 | 规则 | 理由 |
| --- | --- | --- |
| I1 | 风险从 0 升到 ≥ 1 的当天初始化锚点：A = 最近一次创 N\_low 日收盘新低的收盘价，since\_low = 距那天的交易日数 | 下跌已经发生一段时间才触发预警，锚点不能从当天才开始找 |
| I2 | 同一天既满足失效又满足推进时，失效优先；失效后 A = 当日收盘、since\_low = 0 | 跌破锚点本身就是新低，必须从头观察 |
| I3 | 风险降回 0 时，反弹链在任何阶段都结束，只记录、不推送 | 修订初稿“到达 RB3 才结束”：否则风险已恢复正常但阶段停在 RB1/RB2 的股票会长期挂着状态 |
| I4 | 每天最多推进一级（NONE→RB1→RB2→RB3），即使条件同时满足 | 保证不跳级、提醒序列可预期 |
| I5 | 风险再次升级（1→2）不打断反弹链，只有价格跌破锚点才失效 | 升级与失效是不同证据；两类提醒同日可共存 |
| I6 | 冻结日（缺价、窗口不足）since\_low 与降级计数都不前进 | 计数只按有效交易日累计 |
| I7 | 参照序列（SPY、板块 ETF）缺价只影响 RB3 和归因，风险等级照常计算 | 不让参照数据问题掩盖个股信号 |

**确定性约定：每日全量回放，增量只作核对。** 每天对每只股票从登记的 `replay_start` 开始，用当日数据版本全量回放到 T，得到当日状态；数据库中保存的 T−1 状态只用来核对“回放得到的 T−1 状态 = 已存 T−1 状态”（同一数据版本、同一参数集时）。不一致即停止并登记。50 只股票、约 2500 个交易日的回放计算量很小，用回放换取“状态不漂移、复权回溯后自动一致”。`replay_start` 作为参数登记，不同起点可能得到不同的路径依赖状态。

**手工推导示例（测试期望值的写法）**：取 N = 2、W = 5、k₁ = 2、k₂ = 4（仅为示例，不是候选值；为了短小，本例暂不执行 2.2 节“历史 ≥ W + N 条”的最低要求，正式测试另写满足该要求的用例）。

| --- | --- | --- | --- | --- | --- |

| d2 | — | 11.0 | 10.0 | 10.8 | max(1.0, 1.0, 0.0) = 1.0 |

- T = d6：窗口 d2–d6 最高收盘 11.0，峰值日 d3。

- **预先承诺**：股票加入观察名单或买入时，必须在预案表填写止损位、关注/警戒时动作、反弹确认时动作；未填预案的股票，提醒中显示“无预案”。
- **执行记录**：系统每条重要提醒自动生成一行待填记录；发起人补填实际操作。
- **偏离冷静期**：选择“不一致”时必须填写理由；理由提交时间与实际操作时间至少间隔一个交易日，系统只记录与标记，不阻止操作。

### 4.3 复权方案【推断】

Tiger 只给前复权（BR）与不复权（NR），前复权会在每次新的除权事件后整段回溯改写。方案：

1. 每次取数同时拉 NR 与 BR；入库保存 **NR 原始 OHLCV** 与 **隐含复权因子** f\_t = C^BR\_t / C^NR\_t。
2. 每次取数生成一个数据版本（`t_data_version`）；因子序列与上一版本不同（差 > ε 的日期）即记录“复权变更”，并发 DATA\_ISSUE（类型：复权回溯）。
3. domain 计算用复权价 = NR × f（同一版本），开高低收共用同一因子。
4. 回测与正式运行一律指定 `data_version_id`，不读“最新”。
5. 每日增量取数时，若因子回溯变化，当日按新版本对全窗口重算，并在提醒中注明“因复权回溯，历史状态已重算”。

### 4.4 幸存者偏差【推断】

- 第一版股票池是当前自选名单，回测结果天然偏乐观（只含活下来的公司）；评价报告首页必须写明这一偏差，并不把结果称作“股票池外推”。
- 研究阶段的缓解：另建“历史宽基样本”（例如按某年当时的标普 500 成分股，含后来退市者）做稳健性检验，成分股历史来源【待确认】。
- 退市股在 Tiger 中能否取到历史 K 线【待确认】；取不到则在报告中声明。

### 4.5 财报日与事件

- 财报日作为独立事件进 `t_event_calendar`，在提醒中加标签，不改变状态机（第一版）。
- 来源优先 Tiger 公司行动/财报接口（字段待确认）；否则发起人手工录入，或第二来源【待确认】。
- 宏观事件（FOMC、CPI、非农）为固定日程，手工维护年度表即可；第一版只提示，非必做。
- 必须记录事件的“公布时间（盘前/盘后）”，以便把跳空归到正确交易日。

### 4.6 数据核对（每日）

| 检查 | 规则 | 失败处理 |
| --- | --- | --- |
| 缺失 | 交易日历中的 T 日某股无 K 线 | 该股 MISSING\_DATA，冻结状态 |
| 重复 | 同一股同一日多条 | 整次运行失败 |
| 非法值 | 价格 ≤ 0、高 < 低、收盘不在 \[低, 高\] | 整次运行失败 |
| 异常跳变 | 不复权收益 \|r\| ≥ 阈值且无对应复权事件 | 标记待人工确认，不阻断（阈值待登记） |
| 复权回溯 | 因子序列变化 | 新版本 + 重算 + 提醒 |

### 4.7 TradingView 定位

- **不作数据来源**：初稿引用第三方文章称其无面向个人的历史行情接口【初稿，未独立核实】；本项目原则上也已排除。

## 5. 库表设计（MySQL）

### 5.3 设计要点

- **可复现**：任何一次运行 = `data_version_id` + `param_set_id` + `code_commit`，三者入 `t_run`，能完全复算。
- **只追加**：行情、名单、预案、执行记录都不做 UPDATE 覆盖；更正生成新行。`t_alert.push_status` 是唯一允许原地更新的业务字段。
- **防前视**：事件表记 `known_at`，回测只用当时已知事件。
- **面向前端**：状态历史按 (symbol, as\_of\_date) 可直接画状态时间线；提醒的 `payload` 保存触发数值，前端无需重算。

## 6. 模块设计

沿用初稿第 12 节目录与分层，做两处修订：①新增 `bootstrap/`（组装根，≈ Spring 的 `@Configuration`），因为按初稿规则 jobs 不能依赖 infra、service 也不能依赖 infra，没有任何一层能把 Tiger 数据源和推送器“装配”给 service；②service 用 `Protocol` 定义端口（≈ Java 接口），infra 实现，service 不 import infra。【推断，请审阅】

### 6.1 各层职责（Spring Boot 类比）

| 层 | 类比 | 职责 | 不做什么 |
| --- | --- | --- | --- |
| domain | Domain / 纯 POJO + 算法 | 不可变实体、指标、状态机、风控计算；纯函数、确定性 | 读文件、联网、取当前时间、随机数、日志以外的副作用 |
| service | @Service | 编排：取数 → 校验 → 调 domain → 存储 → 推送；事务边界；定义端口 Protocol | 写算法、拼 SQL、直接调 SDK |
| repository | Mapper / Repository | SQLAlchemy 读写；DB 行 ↔ domain 实体转换；版本区间查询 | 业务判断 |
| infra | 外部适配器 / Feign Client | Tiger 数据源、market-risk 文件读取器、交易日历、推送、DB 引擎 | 业务规则与指标计算 |
| bootstrap | @Configuration | 读配置、构造 infra 与 repository、注入 service | 业务逻辑 |
| jobs | @Scheduled 入口 | 解析命令行参数、调用 bootstrap 拿 service、执行一次 | 直接用 domain/repository |
| api（规划） | @RestController | 路由、请求/响应模型 | 直接访问 repository/infra |
| core | 公共配置与异常 | 配置加载、日志、应用异常、Clock | 依赖任何业务层 |

### 6.5 每日运行时序（v0.2 新增）

`daily_close_job` 一次运行分两段事务：取数入库是第一段，计算结果写入是第二段。任何一步失败，第二段整体回滚，当日不出信号，只推送失败原因。推送放在事务之外，推送失败不影响入库。【推断】

1. **启动**：jobs 解析 `--as-of`（缺省为最近一个已收盘交易日）与 `--run-type`，经 bootstrap 取得 `DailyRunService`。
2. **交易日检查**：as\_of 不是交易日 → 退出，记“非交易日”，不建运行记录。
3. **幂等**：同一 (as\_of, run\_type, param\_set\_id, data\_version\_id) 已有 OK 运行 → 直接退出。
4. **登记核对**：读取 `registered_params.yaml`，计算内容哈希并与 `t_param_set` 中已批准的哈希比对；不一致 → 失败。记录代码提交哈希；工作区有未提交改动时，正式运行失败，日常运行记警告。
5. **建运行记录**：`t_run` 写入 RUNNING。
6. **取数（事务一）**：观察名单 ∪ SPY、QQQ、板块 ETF；同时取 NR 与 BR；按第 4.6 节核对；写入新数据版本与版本区间行。重复、非法值 → 失败；个别缺价 → 继续，该股冻结。
7. **大盘背景**：用当日数据版本计算简化代理并写入 `t_market_context`；market-risk 读取器存在且可用时另写一行（待 market-risk M3 后确认），缺失写 UNKNOWN。
8. **逐股计算**：对每只股票从 `replay_start` 全量回放到 as\_of（第 2.9 节），并核对回放所得 T−1 状态与已存状态；不一致 → 失败并登记差异。
9. **生成提醒**：AlertService 把 Transition 转成提醒草稿，附触发数值、归因层、大盘标注、当时生效的预案动作；执行去重冷却。
10. **写结果（事务二）**：状态历史、指标快照、提醒、执行记录待填行一次提交；`t_run` 置 OK。
11. **推送**：发送当日摘要，逐条更新 `push_status`；失败的在下次运行的第一条推送中补报。
12. **失败处理**：第 4–10 步任一步失败 → 回滚事务二，`t_run` 置 FAILED 并写原因，推送“今日未出信号：原因”。不自动续跑，修正后以新运行重跑。

**服务内部调用关系**（≈ Spring 的 Service 编排）：

```python
class DailyRunService:
    def __init__(self, ingest: DataIngestService, prices: PriceRepository, states: StateRepository,
                 alerts: AlertService, journal: JournalService, runs: RunRepository,
                 market_ctx: MarketContextService, notifier: Notifier, clock: Clock,
                 params: RegisteredParams) -> None: ...

    def run(self, as_of: date, run_type: RunType) -> RunResult:
        run = self._open_run(as_of, run_type)                     # 步骤 2–5
        try:
            version = self.ingest.ingest(as_of)                    # 步骤 6（事务一）
            market = self.market_ctx.resolve(as_of, version)       # 步骤 7
            results = [self._step_one(sym, as_of, version, market)  # 步骤 8：调 domain.replay
                       for sym in self._universe(as_of)]
            drafts = self.alerts.build(results, market)            # 步骤 9
            self._commit(run, results, drafts)                     # 步骤 10（事务二）
        except StockRiskError as e:
            return self._fail(run, e)                              # 步骤 12
        self._notify(run, drafts)                                  # 步骤 11（事务外）
        return RunResult.ok(run)
```

## 7. 评价方法（写代码前登记）

评价回答两个问题：提醒是否比简单基线更早或更准地指出“值得注意的下跌”，以及反弹确认后的表现分布是否明显好于基线和随机日期。所有定义、网格、选择规则、期间切分在看任何结果前写入 `docs/registration/evaluation.md` 并经复核；验证期只跑一次。研究报告里的条件频率只用于评价，不作为产品输出（产品不显示“胜率”）。【推断】

### 7.1 事件标注（评价用的“事后真相”）

- **双边界首次触达**：对每条提醒，以提醒日收盘 C\_T 和当时 ATR 设上下边界 C\_T ± b × ATR，观察 H 个交易日内先触达哪一边；都未触达记为“未决”。风险预警“先触下边界”记为有效，“先触上边界”记为误报；反弹确认反之。候选 b ∈ {2, 3}，H ∈ {20, 60}。
- **大跌事件**（用于漏报与滞后）：独立于提醒规则定义——收盘距 63 日高点回撤 ≥ X × ATR(20)，X ∈ {6}（待登记），以峰值日为事件起点、谷底日为终点。

### 7.2 指标

| 对象 | 指标 | 说明 |
| --- | --- | --- |
| 风险预警 | 提醒后 H 日最大回撤分布 | 分位数 10/25/50/75/90 |
|  | 有效率 / 误报率 | 按 7.1 双边界；同时报告未决占比 |
|  | 漏报率 | 大跌事件中，谷底之前未出现任何 RISK\_UP 的比例 |
|  | 滞后 | 峰值日 → 首次提醒的交易日数；提醒时已实现的跌幅 / 最终跌幅 |
|  | 频率 | 每股每年提醒次数（按状态升级计） |
| 反弹提醒 | 提醒后 5/20/60 日收益分位数 | RB1、RB2、RB3 分别统计 |
|  | 反弹失败率 | H 日内触发 RB\_FAIL 的比例 |
|  | 市场过滤对比 | 有/无过滤的上述指标差 |
| 风控规则 | 有/无规则的最大回撤与收益分布 | 第 3 节每条规则单独对比 |

所有比例附 95% 置信区间（按股票分组的块自助法，保留时间相关性）；样本少于登记的最小样本数时只报告描述统计，不下结论。

### 7.3 基线

| 基线 | 对照对象 | 做法 |
| --- | --- | --- |
| 固定百分比回撤 | R1 | 距 63 日高点回撤 ≥ {10%, 20%} 两档，同一状态机 |
| 均线下穿 | R1 | 收盘跌破 50 日均线 |
| 随机日期 | 全部 | 每股随机抽取与实际提醒同数量的日期，重复 1000 次（随机种子登记） |
| 固定反弹 | RB2 | 距最近低点反弹 ≥ {5%, 10%} |

结论口径：打不过固定百分比与均线基线，就不采用 ATR 版本的复杂度；打不过随机日期，规则作废。

### 7.4 期间切分（候选，待 Q6 裁决）

| 段 | 期间 | 用途 |
| --- | --- | --- |
| 预热 | 开发期开始前 300 个交易日 | 只供指标计算，不计入统计 |
| 开发期 | 2010-01-01 至 2019-12-31 | 网格评价与选参，可反复查看 |
| 验证期 | 2020-01-01 至 2024-12-31 | 冻结参数后只跑一次，含 2020 年急跌与 2022 年熊市 |
| 前推观察期 | 2025-01-01 起 | 正式运行开始后的日常记录，不回头调参 |

若 Tiger 日 K 起点晚于 2010 年，按可得起点顺延，切分比例保持约 2:1【待确认】。

### 7.5 防过拟合措施

1. 网格小且事先登记（第 2.8 节：风险 64 组、反弹 4 组）；报告全部网格结果，不只报告最优。
2. 选参规则事先登记，例如：在“每股每年提醒 ≤ F 次”约束下，最大化开发期有效率的置信区间下限；F 由发起人定（Q8）。
3. 稳健性：所选参数的相邻网格点表现不能明显变差，否则视为偶然。
4. 所有股票统一参数；如需分组，只允许按事先登记的波动率分组（如 ATR% 三分位），不按单股挑选。
5. 验证期只跑一次，结果称“冻结后的历史检验”，不称“通过”。
6. 幸存者偏差在报告首页声明；有条件时用历史宽基样本复核（第 4.4 节）。
7. 关键统计由独立回算脚本（不 import 项目代码）复核，差异 > ε 即停。
8. 数据版本、参数集、代码提交哈希写入每份报告。

## 10. 风险清单与第一版里程碑

### 10.1 风险清单

| # | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| 1 | 过拟合与数据窥探：反复看结果改规则 | 历史好看、实盘无效 | 先登记后运行；小网格；验证期只跑一次；全网格报告（第 7.5 节） |
| 2 | 前复权回溯改写历史 | 回测不可复现、状态无故变化 | 存原始价 + 隐含因子；数据版本；复权变更提醒（第 4.3 节） |
| 3 | Tiger 历史额度不足或历史起点短 | 无法覆盖名单或回测期 | 额度：发起人已决定购买会员（Q13）；历史起点仍需开工前实测，不足再评估第二来源 |
| 4 | 幸存者偏差 | 高估反弹可靠性 | 报告首页声明；宽基样本复核（Q4） |
| 5 | 样本少、统计功效低 | 结论不稳 | 置信区间、最小样本数、只报告描述统计（第 7.2 节） |
| 6 | 把提醒当预测，或不按预案执行 | 背离产品定位 | 提醒文案不出现“预测/胜率”；预先承诺与执行记录；季度复盘 |
| 7 | market-risk 进度延后 | 大盘背景长期只能用简化代理 | 第一版按无 market-risk 设计；接口只读、可缺省（Q7） |
| 8 | 简化代理被误读为 market-risk 状态 | 错误背景判断 | 两者分列显示，来源字段强制填写 |
| 9 | 与 market-risk 共用 Tiger 账号互相抢占 | 取数失败 | 分账号或错开时间（Q17） |
| 10 | 浮点与跨平台差异（Windows/Linux） | 复算不一致 | ε = 1e-10；清单口径写死；以 Windows 实跑为准 |
| 11 | 运行期间仓库被外部写入 | 正式运行作废 | 沿用 market-risk 纪律：运行期间不开 IDE/AI 工具，清单哈希核对 |
| 12 | 交易日历遗漏临时休市 | 误报缺价 | Tiger 日历与交易所日历库交叉核对，不一致时人工确认 |
| 13 | 推送失败未被注意 | 漏看重要提醒 | 推送状态入库；失败次日首条推送补报 |
| 14 | 范围膨胀（LLM、前端、盘中） | 第一版延期 | 第 1.5 节“不做的事”写入 README；新增范围走登记 |

### 10.2 第一版里程碑

为避免与 market-risk 的 M3 混淆，本项目里程碑记作 SR-M0 至 SR-M5，按“登记 → 构造测试 → 独立回算 → 演练 → 一次正式运行”排列，前面加一个设计批准门。日期待设计批准后排定。

| 里程碑 | 内容 | 产出 | 通过条件（门） |
| --- | --- | --- | --- |
| SR-M0 设计批准 | ChatGPT 审阅本文；逐条处理意见；发起人裁决第 9 节；Tiger 六项实测（由发起人手工确认或批准后用最小脚本确认） | 设计文档 v1.0、裁决记录 | 发起人书面批准；Q5、Q13 已有实测结论 |
| SR-M1 登记 | 写 `registered_params.yaml`、`evaluation.md`、数值口径、数据版本规范、CLAUDE.md 与 README（含开发纪律）；建仓库 | 登记文件 + 哈希 | 独立复核无阻断意见；发起人批准登记 |
| SR-M2 构造测试 | domain 每条规则正例/反例/边界例（期望值手工推导）；分层契约与纯度测试；service/repository 用替身测试 | 测试全部通过的代码 | 测试覆盖第 2 节每条规则与边界；import-linter 与纯度检查通过；审阅方独立审阅 |
| SR-M3 独立回算 | 不 import 项目代码的回算脚本，对构造数据与一段经批准读取的真实数据复算指标与状态 | 回算报告 | 全部差异 ≤ ε；差异逐项登记 |
| SR-M4 演练 | 在 Windows 上完整跑一遍正式运行流程（取数 → 版本 → 开发期选参 → 冻结 → 验证期检验 → 报告），演练结果单独登记，不作证据 | 演练记录、停止边界登记 | 全流程无未解释的停止；执行脚本与清单哈希固定 |
| SR-M5 一次正式运行 | 按登记规则在开发期选参并冻结，验证期只跑一次；通过后开始日常运行 | 冻结后的历史检验报告；日常运行上线 | 报告由审阅方盲审；发起人决定是否启用日常提醒 |

里程碑之间的任一步失败，按初稿第 11 节纪律处理：停止、登记“已执行/未执行”边界、不重试不续跑，修正后从当前里程碑重新开始。

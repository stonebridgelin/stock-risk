6. 不修改 market-risk，不把它当生产依赖；依赖处标“待 market-risk M3 后确认”。
7. 数据源不绑定供应商。开发评价可用的数据量不设上限，但**开发期与验证期边界按登记约束执行，数据不设上限不代表可以提前使用验证期**。开发数据在用于正式评价前、正式供应商在生产演练与启用前，都必须通过必需能力验收（第 4.1 节）。

## 1. 产品需求与第一版范围

stock-risk 帮发起人盯住一批股票（30–500 只，常包括波动大的成长股）：收盘后判断每只股票是否进入需要注意的下跌、是否出现止跌确认，把全部状态变化记下来，并按分层规则送达。它是跟随确认式的：股价已经跌到一定程度才报警，不在下跌开始前报警，也不判断下跌原因。

### 1.1 场景

| 场景 | 用户想知道 | 系统给出 |
| --- | --- | --- |
| S1 持仓或重点股下跌 | 跌了多少（以该股自身波动衡量）？收益分解如何？我的预案是什么？ | 风险升级事件，逐条推送；附触发数值、收益贡献分解、当时生效的预案 |
| S2 观察股止跌 | 跌势是否停下？ | RB1/RB2 事件，附当前锚点价与日期 |
| S3 反弹失效 | 之前的止跌信号是否作废？ | RB\_FAIL，原因为跌破锚点或再创新低 |
| S4 固定价止损 | 持仓股收盘是否触及我设的止损价？ | STOP\_HIT；价格可比性不足时显示“不可评估，请重新录入”（第 3.3 节） |
| S5 数据异常 | 今天的信号能不能信？ | 缺价、历史断点、复权回溯、撤回、代码变更、公司行动导致的不可评估 |
| S6 个股体检 | 买入前看看这只股票现在处于什么状态 | 第 1.4 节 |
| S7 名单维护 | 加入/移出股票、设推送层级 | 加入前通过地域门（第 4.7 节）；层级可手工调整并留痕 |
| S8 处置记录 | 我对提醒做了什么 | 第 3.2 节，只记录，不自动判违规 |

### 1.2 启用时点

日常运行与个股体检会产生当前日期的信号，而当前日期属于验证期（第 8.3 节）。因此**两者都在 SR-M5 正式运行完成、验证期解封之后才启用**；此前的演练与性能测试只用构造数据或开发期数据。

### 1.3 每日流程（启用后）

1. 美东收盘后，按数据源说明的最早可取时点开始取数；先判“供应商响应是否完整”（第 4.4 节）。
2. 完整重取，检查一致性与撤回，发布数据版本。
3. 生成输入快照（含名单、层级、主数据与地域核验状态、预案、止损配置的取值时刻）。
4. 计算简化大盘背景（第一版唯一生产背景来源）。
5. 逐股全量回放到 T：风险等级、RB1/RB2、全部状态变化；计算固定价止损。
6. 生成业务事件（第 2.8 节），按第 7 节分层投递；为需处置的事件生成处置待填行。
7. 运行失败：不出信号，推送“今日未出信号：原因”。

“即时”在全文中统一指“当日收盘后计算完成即推送”，不提供盘中提醒。

### 1.4 个股体检

- 输入任一已登记、地域门结论不是“排除”的证券（含尚未加入名单的）；地域核验未完成的，页面顶部显示“地域核验未完成，不能加入名单”。【推断】
- 用登记参数从该证券历史段起点回放到最近一个已发布数据版本的 T 日，展示：
  - 当前风险等级、反弹阶段、锚点、计算状态；
  - 当前指标值与证据数值（回撤、ATR 倍数、跳空分数、收益分解）；
  - 历史状态变化列表（日期、类型、证据）；
  - 数据质量：历史段起点、断点、缺价日、复权回溯、公司行动、撤回记录。
- **不新增**综合评分、预测、事后收益统计或另一套选参任务；只做以上事实展示。
- 体检结果按“ANALYSIS”类计算尝试保存，不进入推送。

## 2. 规则规格

R1（波动率归一化回撤）和 R2（跳空大跌）决定风险等级；R3 只做收益贡献分解；反弹链第一版只有 RB1、RB2 与失效。目标：两个独立实现者离散结果完全相同，连续数值在登记容差内相同。

### 2.0 数值规范（R2-01、R2-02、R2-03）

| 项 | 规定 |
| --- | --- |
| 入库量化 | 供应商数值一律按文本解析为 `Decimal`（若供应商只给浮点数，先取其最短十进制表示 `repr` 再解析），以 ROUND\_HALF\_EVEN 量化到 6 位小数写入 DECIMAL(18,6)。≤ 0 或超出列范围 → 该证券日判为非法值。原始响应作为文件留存，哈希记入取数尝试。domain 只使用量化后的值 |
| 类型转换 | repository 把 DECIMAL 转为 Python float，转换时不另做舍入 |
| 求和 | 统一用 `math.fsum`，输入按交易日升序传入；它用于减少求和误差，不单独保证跨平台逐位一致。跨平台一致性靠固定 Python 版本与运行环境，并以 Windows 实跑为准 |
| 规则比较容差 | 比率类 ε\_r = 1e-10；价格类 ε\_p = 1e-9 美元（待登记） |
| 比较定义 | `x ≥ k` 判为 x ≥ k − ε；`x > k` 判为 x > k + ε；`x ≤ k` 判为 x ≤ k + ε；`x < k` 判为 x < k − ε |
| 复算验收判据 | 与规则比较容差分开：\|a − b\| ≤ abs\_tol + 1e-9 × max(\|a\|, \|b\|)；比率类 abs\_tol = 1e-12，价格类 abs\_tol = 1e-9。验收例：比率 0 对 5e-13 通过、0 对 2e-12 不通过；价格 100 对 100.00000005 通过 |
| 离散结果 | 等级、阶段、事件、状态码在复算中必须完全相同 |
| 时间 | T 日收盘后计算，信号日期为 T；domain 只接收截断到 T 的序列 |
| 交易日 | 以输入快照绑定的交易日历版本为准 |
| 明确失败 | 非有限值、高 < 低、收盘不在 \[低, 高\]、长度不一致 → `InvalidInputError`，整次运行失败 |
| 显式状态 | `INSUFFICIENT_HISTORY`、`MISSING_DATA`、`ANCHOR_UNAVAILABLE`，不用空值代替 |

### 2.1 基础指标

```latex
TR_t = \max\left(H_t - L_t,\ |H_t - C_{t-1}|,\ |L_t - C_{t-1}|\right), \qquad ATR_N(t) = \frac{\mathrm{fsum}(TR_{t-N+1..t})}{N}
```

全部使用前复权（BR）开高低收。需要 N+1 条日线；ATR ≤ 0 → `InvalidInputError`。SMA\_M(t) = fsum(最近 M 个收盘) / M。

### 2.2 R1 波动率归一化回撤

```latex
P^{max}_t = \max_{t-W+1 \le i \le t} C_i, \qquad D_t = \frac{P^{max}_t - C_t}{ATR_N(\tau)}
```

- 峰值日 p：窗口内取得 P^max 的交易日，并列取最近一天。τ：冻结方案 τ = p，不冻结方案 τ = T，均为候选。
- 等级：D\_t ≥ k₂ → 警戒（2）；否则 D\_t ≥ k₁ → 关注（1）；否则正常（0）。k₁ < k₂。
- 自历史段起点（第 2.9 节）不足 W + N 条 → `INSUFFICIENT_HISTORY`。

### 2.3 R2 跳空大跌（R2-05、R2-06 最终规则）

```latex
G_t = \frac{O_t - C_{prev}}{ATR_N(prev)}
```

- **R2-05 最终规则**：一条日线只要 NR 或 BR 的开、高、低、收中任一字段缺失，整条日线视为缺失，该证券当日 `MISSING_DATA`；不完整日线不写入行情表，只记入取数质量报告（原因“字段缺失”）。理由：供应商极少只缺单个字段，出现即说明数据有问题；单一规则更不易错，也使存储契约（全部 NOT NULL）与计算一致。
- **R2-06 最终规则**：prev 必须是交易日历上 T 的**前一个交易日**。该日没有日线时，R2 返回 `MISSING_DATA`，R1 照常；不使用“上一条有效日线”的收盘。理由：跨多个交易日的价格变化不是单日跳空。
- 触发：状态 OK 且 G\_t ≤ −g 且 C\_T < C\_prev → 隐含等级至少为关注。

```python
@dataclass(frozen=True)
class R2Result:
    status: CalcStatus        # OK / MISSING_DATA（前一交易日无日线）/ INSUFFICIENT_HISTORY
    gap_score: float | None   # 仅 OK 时有值
    triggered: bool
```

### 2.4 R3 收益贡献分解（只展示）

```latex
r_s = r_{mkt} + (r_{sec} - r_{mkt}) + (r_s - r_{sec})
```

区间为 p 到 T。主导项只在小于 −ε\_r 的分项中选最负者；与全局最小值相差 ≤ ε\_r 的构成并列集合，按“市场 > 板块相对市场 > 个股相对板块”取第一个；没有负分项 → `NO_NEGATIVE_CONTRIBUTION`。未映射板块 → 两项分解；参照缺价 → `UNAVAILABLE`。非美国发行人的“个股相对板块”混入母国市场与汇率影响，提醒中注明。分解只描述收益构成，不判断原因。

### 2.5 风险状态机

| 项 | 规则 |
| --- | --- |
| 状态 | 0 正常 / 1 关注 / 2 警戒 |
| 隐含等级 | L\_t = max(R1 等级, R2 等级)；R2 非 OK 时 L\_t = R1 等级 |
| 升级 | L\_t > 当前等级 → 当日升到 L\_t（可跨级），降级计数清零，产生升级事件 |
| 降级 | L\_t < 当前等级的连续有效交易日达到 d → 降一档；L\_t ≥ 当前等级的那天计数清零 |
| T 日缺价 | 等级、阶段、锚点冻结；降级计数与 since\_low 清零，并记录“计数中断日”= T |
| 窗口不足 | 数值等级保持初始 0，但 `calc_status = INSUFFICIENT_HISTORY` |
| 不可计算状态的展示与统计（R2-39） | `calc_status` 不是 OK 时，等级一律显示“不可计算”，不显示为“正常”；汇总统计中单独计数，不计入正常（第 7.4 节） |
| 持续警戒 | 持续处于警戒不产生新事件；只有真实的等级变化才产生事件 |

### 2.6 简化大盘背景（第一版唯一生产背景来源）

| 项 | 判定 |
| --- | --- |
| 输入 | SPY、QQQ 的 BR 收盘，同一数据版本 |
| 回撤 | DD\_a = 1 − C\_T / max(最近 63 个收盘，含 T) |
| 等级（每日无滞后重算） | max(DD\_SPY, DD\_QQQ) ≥ θ₂ → 二级；否则 ≥ θ₁ → 一级；否则正常 |
| 止跌标志（只展示） | 两资产都已连续 Kₘ 个有效交易日未创 20 日收盘新低 |
| 缺价或不足 63 条 | `UNKNOWN` |
| θ₁、θ₂、Kₘ 未配置 | 背景只展示 DD 数值，等级为“未配置”，不触发任何标签 |

**观察标签（R2-20）**：背景为二级时，RB1/RB2 相关事件附“观察”标签，文案为“大盘回撤处于二级”。标签不改变状态计算，也不替代发送或抑制决定。背景 UNKNOWN 时文案为“大盘背景未知”。market-risk 输出待 market-risk M3 后确认，接入另行批准前只作独立展示。

### 2.7 反弹链（R2-04 最终规则）

**新低**：C\_t ≤ min(C\_{t−N\_low} … C\_{t−1})（相等计入），前 N\_low 条不足时不可判定。

| 事件 | 锚点 A 与 since\_low |
| --- | --- |
| 风险由 0 升到 ≥ 1（链开始） | 在当前历史段已加载数据中找最近一次新低日，A 取其收盘与日期；找不到 → `ANCHOR_UNAVAILABLE`，链不推进，直到出现新低。**R2-04 最终规则**：since\_low = 从 max(最近新低日, 最近计数中断日) 的次日起到 T 的有效交易日数；锚点可以早于缺价日，但缺价之前的天数不得计入。链开始当日不再另加一 |
| 阶段 NONE 且当日新低 | A 更新为当日收盘与日期，since\_low = 0 |
| 阶段 RB1/RB2 且 C\_T < A，或当日新低 | RB\_FAIL：原因 `BREAK_ANCHOR`（优先）或 `NEW_LOW`；阶段回到 NONE；A 更新为当日收盘与日期；since\_low = 0 |
| 其他有效交易日 | since\_low 加一 |
| T 日缺价 | A 不变；since\_low 清零；计数中断日 = T |

| 推进（每天最多一级） | 条件 |
| --- | --- |
| NONE → RB1 | 风险 ≥ 1，A 可得，since\_low ≥ K |
| RB1 → RB2 | C\_T > SMA\_S(T) |

**结束**：风险回到 0 → RB\_END（只记录、不推送），阶段与锚点清空。

**RB3 已推迟**：恢复时，RS 必须按交易日期对齐个股与 SPY，不得按数组位置配对（R2-07 意见保留，后续重审）。

R2-04 验收例：最近新低日为 d0；d1、d2 有效；d3 缺价（中断）；d4 有效且风险首次升级；K = 3。since\_low = 1（只计 d4），不得进入 RB1。

### 2.8 逐日步进与业务事件（R2-17、R2-19）

每只股票每个交易日固定顺序：数据检查 → 指标 → 风险状态机 → 反弹链 → 观察标签。domain 只产出状态与状态变化（Transition），不做冷却、不管投递。

```python
def step_symbol(prev: SymbolState, s: PriceSeries, cal: TradingCalendar, as_of: date,
                market: MarketBackground, p: Params) -> tuple[SymbolState, list[Transition]]:
    if not s.has_bar(as_of):
        return prev.frozen(as_of, interrupt_on=as_of), [Transition("DATA_ISSUE", reason="MISSING_DATA")]
    if s.bars_in_segment(as_of) < p.w + p.n:
        return prev.with_status(as_of, CalcStatus.INSUFFICIENT_HISTORY), []
    dd  = normalized_drawdown(s, as_of, p)
    r2  = gap_result(s, cal, as_of, p)               # 前一交易日缺日线 → MISSING_DATA
    lvl = implied_level(dd, r2, p)
    risk, cnt, out = step_risk(prev, lvl, p.d)
    chain, chain_out = step_chain(prev, risk, s, as_of, p)   # R2-04 初始化规则
    out += chain_out
    return SymbolState(as_of, risk, cnt, chain, CalcStatus.OK), [label(t, market) for t in out]
```

**业务事件身份**：`event_key = (security_id, as_of_date, event_type, from_state, to_state)`。

| 情况 | 处理 |
| --- | --- |
| 首次发布某日结果 | 每个状态变化生成一个业务事件 |
| 同日重新发布（新数据版本或修复代码后新任务），同 key 仍存在 | 同一业务事件，不重发；证据数值变化只记修订 |
| 新结果中出现旧结果没有的 key | 新增业务事件，正常投递，标“同日修订新增” |
| 旧结果中的 key 在新结果中消失 | 原业务事件标“已撤销”，在原投递层发送更正消息 |
| 运行重试、补发 | 不产生新业务事件 |

“升至警戒”指一个 to\_state = 2 且 from\_state < 2 的业务事件；持续处于警戒不产生事件。

**确定性**：每日从当前历史段起点全量回放到 T；与已存结果的核对只在输入快照与代码版本完全相同时进行；跨数据版本的历史差异写修订审计，不重发旧事件。

### 2.9 历史断点与代码变更

- 连续缺价超过 G 个交易日 → 历史断点；断点后第一条日线为新历史段起点；状态重置；新段满 W + N 条前为 `INSUFFICIENT_HISTORY`。例：NBIS 原 YNDX，2022-02-28 停牌、2024-10-21 复牌。
- 短缺口（≤ G 天）：缺价日为 MISSING\_DATA；恢复后窗口按有日线的交易日计数，快照标 `window_has_gap`；R2 仍须前一交易日有日线。
- 所有表以内部 `security_id` 关联，代码变更记入代码历史表。

## 3. 预案、处置记录与固定价止损

第一版只保留三样：事先写下的预案、事后录入的处置记录、固定价止损提醒。系统不计算参考股数、不算集中度、不自动判违规、不判定冷静期。

### 3.1 预案（`t_trade_plan`）

版本化保存：证券、版本、生效日、关注时动作、警戒时动作、RB2 时动作、RB\_FAIL 时动作、止损时动作（均为文本）、备注。修改即新增版本。事件推送时附“当时生效的预案版本”的动作；没有预案的显示“无预案”。

### 3.2 处置记录

| 表 | 一行代表 | 关键字段 |
| --- | --- | --- |
| `t_trade_action` | 一笔真实操作，可以没有对应事件 | 操作编号、证券、类型（买/加/减/清/其他）、数量、原始成交价、**实际操作时间**、**录入时间**、说明 |
| `t_alert_disposition` | 对一个业务事件的处置 | 业务事件、产生该事件的计算尝试、当时预案版本、处置结论（已执行/决定不执行/待定）、处置时间、录入时间、说明 |
| `t_action_alert_link` | 操作与事件多对多 | 操作编号、业务事件 |

全部只追加，修订生成新版本行。第一版不写入任何“违规”字段，季度复盘只做记录导出。

### 3.3 固定价止损（R2-09，发起人有条件同意）

| 项 | 规则 |
| --- | --- |
| 配置 | 只对名单中标为“持仓”的证券；发起人录入原始口径止损价与设定日，版本化。未录入 → 不生效 |
| 比较 | 收盘提醒，不自动交易：NR 收盘 ≤ 止损价（按第 2.0 节价格类比较） |
| 事件 | 由“未触及”变为“触及”时产生 STOP\_HIT；持续触及不产生新事件；收盘回到止损价以上，或录入新止损价，状态重置 |
| 价格可比性 | 设定日（不含）到 T（含）之间发生任一**可比性事件**，该止损标“不可评估，请重新录入”，不比较、不换算 |
| 可比性事件 | 拆股、合股、ADR 比率变更、分拆、特别分红或资本返还、证券合并或置换，以及公司行动表中除“常规现金分红”外的任何类型 |
| 资料不足 | 该区间公司行动数据未覆盖或未验收；或隐含因子 f = BR 收盘 ÷ NR 收盘在某日出现变化，且不能由当日登记的常规现金分红在容差内解释 → 同样“不可评估” |
| 常规现金分红 | 除息日原始股价通常下跌约等于每股股息；按原始价比较时，这部分下跌会计入，可能因此触及止损。触及发生在除息日时，提醒注明“除息日” |

公司行动识别是固定价止损的**必需数据能力**（第 4.1 节），不因事件日历功能延期而省略。系统不承诺不会误报或漏报；误报与漏报的来源（数据错误、公司行动遗漏、除息）在提醒和文档中说明。

## 4. 数据与证券主数据

开发评价用发起人提供的数据（数量不设上限），正式运行用通过验收的供应商；两者都必须先通过同一套必需能力验收，差异要在重叠期实测。

### 4.1 必需能力与验收时点（R2-37）

| 能力 | 开发数据（正式评价前验收） | 生产供应商（生产演练与启用前验收） |
| --- | --- | --- |
| 日线 NR 与 BR 开高低收、成交量 | 必需 | 必需 |
| 前复权是否含现金分红（查清并登记） | 必需 | 必需 |
| 拆股、合股、ADR 比率变更的复权正确 | 必需 | 必需 |
| **公司行动记录**（类型、日期、比例或金额） | 必需（固定价止损与数据核对） | 必需 |
| 代码变更连续性 | 必需 | 必需 |
| 退市证券历史 | 必需（主样本含退市） | 可选 |
| 标普 500 历史成分及生效日期 | 必需（第 8.1 节） | 不需要 |
| 历史起点不晚于 2009-01-01 | 必需 | 不需要（日常只需近年） |
| 时间戳到交易日映射、查询边界 | 必需 | 必需 |
| 授权允许研究与本地存储 | 必需 | 必需 |

“设计获批”与“数据能力验收通过”分开记录。数据门通过要求**至少一个来源满足全部必需能力**；某来源失败只表示该来源未通过。

### 4.2 存储与量化

每个数据版本保存 NR 与 BR 开高低收与成交量（量化规则见第 2.0 节）；计算用 BR；隐含因子 f 只用于复权回溯检测和第 3.3 节的可比性检查，不用于换算任何价格。

### 4.3 完整重取、撤回与一致性（R2-12、R2-13）

- 每日对全部所需证券完整重取，按单次上限分批分页，NR 与 BR 分别请求，共享限速。
- 与上一已发布版本逐行比较：不变的行保持有效；变化或新增的行写新行，旧行在发布事务内关闭有效区间。
- **撤回（R2-12）**：只有在确认该证券的请求范围**完整**（所有批次与分页成功、返回范围覆盖请求区间）之后，旧版本有、新响应没有的证券日才判为“供应商撤回”：关闭旧行有效区间，写撤回记录（版本、证据：响应文件哈希与请求参数）；新版本读到的是缺失，旧版本仍能读到原值。请求不完整时不得判撤回，该次取数失败。
- **生产一致性核验（R2-13）**：多批多页请求不构成供应商的同一快照。完整取数后，对每只证券再请求一次最早一页 BR 数据并与本次结果比对；不一致则整体重取一次，仍不一致则版本失败。各响应的时间与比对结果留存。开发数据由文件提供，文件集本身即一个快照（哈希登记），不需要此核验。
- 发布前检查：每个证券日在新版本中恰有一条有效行；版本序号严格递增且只有一个线性序列。

### 4.4 就绪（R2-08）

- **供应商响应完整**（全部请求成功、范围完整、质量检查通过）是发布数据版本的前提；不满足则不发布、不计算，按重试分类处理。
- 响应完整但个别证券 T 日无日线（停牌、未交易），照常发布，这些证券为 `MISSING_DATA`，其他证券照常计算。
- 参照证券（SPY、QQQ、板块 ETF）缺价只影响大盘背景与收益分解，不阻止发布。
- 收盘后 2.5 小时（Tiger 文档所述）只是最早尝试时点，不代表数据永久不再修订。

### 4.5 交易日历

交易日历版本化，纳入输入快照；来源为交易所日历库，与数据源日历交叉核对，不一致时人工确认后发布新版本。

### 4.6 开发数据与生产数据的差异

若开发数据与生产供应商来源不同，在**开发期内**选一段重叠区间（候选 2018–2019 年）对同一批证券比对：

| 维度 | 比对方法 | 不一致时 |
| --- | --- | --- |
| 不复权价格 | 逐日对比，按第 2.0 节复算判据 | 登记差异率；超出登记界限 → 不可直接沿用开发期结论 |
| 复权方式 | 两边是否都含现金分红；除息日因子跳变是否一致 | 口径不同 → 生产必须换成同口径来源，或在开发期用生产来源数据重新评价 |
| 交易日历 | 交易日集合对比 | 以日历版本为准，差异登记 |
| 公司行动 | 事件集合与比例对比 | 遗漏或冲突登记；影响固定价止损的可比性判断 |
| 历史修订行为 | 生产来源连续若干天重取，看是否回改历史 | 登记修订频率，供修订审计参考 |

比对只用开发期数据，不触碰验证期。

### 4.7 证券主数据与地域门（J-5、R2-14、R2-21、R2-22）

**来源优先级**：① 最近一期 SEC 年报（10-K、20-F、40-F）；② 其他 SEC 正式文件（S-1/F-1、8-K/6-K）；③ 交易所与公司投资者关系资料；④ 数据供应商字段。高优先级来源存在时，低优先级来源只用于发现冲突。

| 项 | 可执行定义 |
| --- | --- |
| 注册地 | 年报封面“注册成立地（jurisdiction of incorporation）” |
| 总部 | 年报封面“主要行政办公室（principal executive offices）”地址所在国家或地区 |
| 主要经营地（集合） | 以下各项的并集：(a) 年报地理信息披露中营收占比 ≥ τ\_ops 的国家或地区；(b) 长期资产占比 ≥ τ\_ops 的国家或地区；(c) 年报披露的主要经营子公司或可变利益实体（VIE）所在地。τ\_ops 为业务阈值【待批准，候选 25%】；未批准前，(a)(b) 不能自动判定，该项一律转人工 |
| 区域性披露 | 只披露“亚太”等区域、无法确认是否包含排除地区，且该区域达到 τ\_ops → 待核验 |

**判定**：三项全部确定、均不在排除地区、且不在手工排除名单 → 自动通过；任一项命中排除地区或在手工排除名单 → 排除；任一项缺失、来源冲突或无法确定 → 待核验（转人工）。**不得**仅凭注册地、总部或标普成分股身份自动通过。

**人工核查线索**：注册地为开曼、英属维尔京群岛、百慕大等离岸地；年报出现 VIE、中国内地或香港经营实体等表述。线索只触发人工核查，不扩展排除地区。

**留痕**：证据（文件编号、链接、页码或段落）、资料日期、核验时间、规则版本、方式（自动/人工）、人工结论与核验人；每次输入快照记录所用的核验修订。

**人工工作量**：待测。SR-M0 数据能力验收时，对一批样本实测自动通过率与转人工比例，不作事先保证。

**资格状态（每次生成输入快照时重新评估）**：

| 状态 | 信号 | 显示 |
| --- | --- | --- |
| 未核验或首次核验未完成 | 不得加入名单；不产生信号 | 体检可用，带“地域核验未完成”横幅 |
| 已通过 | 正常 | — |
| 已通过，超过 1 年未复核 | 继续产生信号 | 持续显示“核验过期，请复核” |
| 已通过，后出现实质性资料冲突（新证据与原结论矛盾但未命中排除） | 继续产生信号 | 显示“资料冲突”，生成高优先级复核任务 |
| 新证据命中排除条件，或加入手工排除名单 | 下一次快照起停止新信号，不等待年度复核 | 历史记录保留 |

### 4.8 幸存者偏差与“当时可知”

回测称“固定版本历史复算”，前复权跨除息日的缩放不是常数，不能仅凭按日期截断宣称无前视；报告首页注明。生产运行逐日保存当时版本与结果，构成“当时可知记录”。评价样本的幸存者偏差处理见第 8.1 节。

### 5.3 约束

- **只追加**，唯一例外是行情旧行有效区间在发布事务内关闭一次。
- **代码版本（R2-15）**：`t_compute_attempt.code_commit` 必须等于其任务输入快照中的代码版本；修改代码就生成新快照与新任务，并记录 `fixes_task_id`；同代码同输入的再次执行才是原任务的新尝试。
- **快照**：输入快照记录 `master_as_of` 与核验规则版本，按时刻唯一确定所用的主数据、核验、代码映射、名单、层级、预案、止损配置修订。
- **展示**：只读查询按 `attempt_id`；生产状态时间线由逐日 DAILY 尝试的 T 日行组成（即当时可知记录）；体检时间线来自 ANALYSIS 尝试。

### 6.2 每日时序（启用后）

| 段 | 步骤 | 失败处理 |
| --- | --- | --- |
| A 取数 | 交易日判断 → 新建取数尝试 → 完整重取 → 完整性、一致性、撤回、质量检查 → 发布数据版本 | 响应不完整：不发布，按 6.3 重试；个别证券缺价：照常发布 |
| B 快照 | 校验参数集哈希 → 资格评估 → 生成输入快照 → 取或建计算任务（已有发布结果则跳到 D）→ 新建计算尝试 | 哈希不符：失败 |
| C 计算 | 简化大盘背景 → 逐股全量回放 → 同快照核对 → 固定价止损 → 单事务写入状态、状态变化、背景；尝试置 PUBLISHED | 任一步失败：回滚，尝试 FAILED，发送失败通知 |
| D 事件 | 状态变化 → 业务事件（新增、相同、撤销） | — |
| E 投递 | 投递决策 → 生成消息（逐条/批次/汇总/更正）→ 每条消息先写 PENDING → 发送 → 写结果 | 发送失败：`redeliver` 补发；遗留 PENDING 在恢复时转 UNKNOWN |

### 6.3 重试分类

| 类别 | 规则 |
| --- | --- |
| 网络请求 | 指数退避，最多 3 次；429 按限流信息等待 |
| 响应不完整或数据未就绪 | 新建取数尝试再试，间隔与次数登记（候选 20 分钟、3 次） |
| 计算错误 | 不自动重试；修复代码后新建快照与任务 |
| 投递 | `redeliver` 补发 FAILED；UNKNOWN 不自动补发，由发起人确认；补发不产生新业务事件 |
| 正式验证（SR-M5） | 不重试；验证期解封后持久化“已消费”，重跑不得再次选参或产生新的可查看结果 |

## 7. 推送与投递（J-4）

两层使用相同的信号和状态机，全部状态变化都记录；分层只决定事件以什么消息、在什么时候送达。“即时”指当日收盘后计算完成即推送。任何需要投递的事件都至少出现在一条消息里，不静默丢失。

### 7.1 层级

| 层 | 默认归属 | 送达方式 |
| --- | --- | --- |
| 逐条层（INSTANT） | 名单中标为持仓或重点的证券 | 每个事件一条消息（数量过多时合并为批次消息，第 7.5 节） |
| 汇总层（DIGEST） | 其余证券 | 当日一条汇总消息 |

发起人可手工调整任一证券的层级，必须填写原因，记入名单表并留痕，自下一次输入快照起生效。持仓标记只用于名单与投递管理（以及固定价止损的适用范围），不恢复集中度等延期功能。

### 7.2 需要投递的事件

RISK\_UP、RISK\_DOWN、RB\_WATCH、RB\_CONFIRM、RB\_FAIL、STOP\_HIT、DATA\_ISSUE，以及业务事件的撤销更正。RB\_END 只记录不投递。

### 7.3 推送冷却（只作用于逐条层的单条消息，R2-19）

| 项 | 规则 |
| --- | --- |
| 冷却键 | (证券, 事件类型, 目标状态) |
| 冷却值 | c\_watch：升至关注；c\_other：RISK\_DOWN、RB\_WATCH、RB\_CONFIRM。单位为交易日，由发起人填写；**未配置则冷却不生效**，每个事件都单独发送 |
| 判定 | 与上次已送达（SENT 或 UNKNOWN）的同键单条事件相距交易日数 < c → 本事件不单独发送；= c 允许 |
| 不受冷却 | 每次真实升至警戒的事件、RB\_FAIL、STOP\_HIT、DATA\_ISSUE、更正 |
| 被冷却的事件 | 不丢失：列入当日汇总的“已抑制的逐条事件”栏 |
| 不产生事件的情况 | 持续处于警戒、运行重试、补发、同日重算出相同事件 |

### 7.4 每日汇总

**发送规则**：每个已发布的 DAILY 计算尝试发送一条汇总，在逐条消息之后发送。当天没有任何事件也发送，内容为表头加“今日无新事件”，用作运行成功的确认；运行失败的日子改发失败通知。

**内容**：

1. 表头：日期；简化大盘背景（等级或“未配置”，以及 SPY、QQQ 的回撤数值）；名单统计（名单总数、计算 OK 数、窗口不足数、缺价数、各风险等级只数，不可计算的不计入“正常”）；当日新增升至关注数、升至警戒数、RB\_FAIL 数。
2. 汇总层证券的全部当日事件。
3. 逐条层中被冷却抑制的事件。
4. 逐条层当日已单独发送的事件数（只给数量）。
5. 当日的撤销与更正。

**排序**：按严重度——升至警戒、RB\_FAIL、STOP\_HIT、DATA\_ISSUE、升至关注、RB\_CONFIRM、RB\_WATCH、RISK\_DOWN；同严重度按代码字母顺序；同一证券的多个事件放在一起，按严重度排列。每个事件一行，不合并。

**“大面积下跌”标签**：第一版默认不显示。若启用，统计对象为名单中计算状态 OK 的证券，分母为其数量，统计量为 T 日风险等级 ≥ 1 的比例，阈值 τ\_broad 由发起人批准【待批准】；未配置时只展示比例数值，不加标签。删除“市场层主导”说法。

### 7.5 容量与限流

| 项 | 规则 |
| --- | --- |
| 渠道限额 | 选定渠道后登记其每分钟、每日消息数与单条长度上限（以渠道官方文档与实测为准）【待确认】 |
| 批次合并 | 单次运行逐条层待发事件数 > M（候选 20）时，按严重度顺序打包为批次消息，每批最多 B 个事件（候选 20，且不超过单条长度上限）；不删减任何事件 |
| 节流 | 按渠道每分钟上限发送；将超出每日上限的消息进入持久化队列，额度恢复后发送；汇总中注明“X 条消息延迟发送” |
| 计数 | 每次运行分别统计事件数、消息数（按类型与层级）、送达结果 |
| 不变式检查 | 每个需要投递的业务事件至少出现在一条消息中；检查不通过则发失败通知并记录 |

示例：500 只均在逐条层、普跌日产生 300 个事件 → 15 条批次消息（每批 20 个事件）+ 1 条汇总；消息数 16，事件数 300。

### 7.6 更正

同日重新发布导致业务事件撤销或新增时（第 2.8 节），在该证券所在层发送更正消息（逐条层单独发送，汇总层并入次日汇总的“撤销与更正”栏）。

## 8. 评价方法（SR-M1 登记，看结果前固定）

### 8.1 评价样本（J-2）

| 项 | 规则 |
| --- | --- |
| 纳入区间 | 按历史成分**生效日期**：证券只在 \[纳入日, 移出日) 内计入信号、事件与负担；纳入前的历史只用于指标预热。不得用当前成分股名单回填历史 |

| SR-M5 之前 | 演练、性能测试、数据比对只用构造数据或开发期数据；不读取、生成、展示任何验证期信号、标签或评价结果；日常运行与个股体检也不启用（第 1.2 节） |

### 8.4 主指标（R2-25、R2-26 最终规则）

| 对象 | 指标 | 定义 |
| --- | --- | --- |
| 风险预警 | 大跌事件覆盖率 | 分母：结果确定（未截尾）的大跌事件数；分子：其中在匹配区间内出现 RISK\_UP 的事件数。\*\*R2-25 最终规则：匹配区间 = \[峰值日, 谷底日)，含峰值日、不含谷底日；合并事件使用合并后的峰值日与谷底日。\*\*理由：峰值日之前的提醒属于更早的下跌，不应算覆盖本事件 |
|  | 滞后 | 每个被覆盖事件：峰值日到区间内首次 RISK\_UP 的交易日数；以及首次提醒时已实现跌幅 ÷ 事件最大跌幅 |
| 反弹提醒 | 链内失效率 | \*\*R2-26 最终规则：每条 RB2 链的结果分三类——失效（链内出现 RB\_FAIL）、正常结束（RB\_END）、观察截尾（缺价、历史断点、退市、成分退出、期间结束）。失效率 = 失效 ÷ (失效 + 正常结束)；截尾数单独报告，并给出截尾全部计为失效、全部计为未失效两种情况的上下界。\*\*生产规则中缺价仍是冻结，评价中把首次缺价视为观察截尾，不称“链结束”。理由：未完成的观察既不能算成功也不能算失败 |

### 8.5 大跌事件切分（R2-24 最终规则）

事件只用于评价，不回流信号链；使用固定评价口径，与候选参数无关。

| 环节 | 规则 |
| --- | --- |
| 评价口径 | D\_eval：W = 63，N = 20，SMA ATR，不冻结，T 日计算 |
| 开始 | 首个 D\_eval ≥ X 的交易日；X【待批准，候选 6】 |
| 峰值日 | 开始日当时 63 日最高收盘日（并列取最近）；**合并后保持第一个事件的峰值日不变** |
| 谷底 | 峰值日至结束日之间最低收盘日；并列取最早 |
| 结束 | (a) 收盘回到峰值收盘以上；或 (b) D\_eval < X / 2 连续 10 个交易日，以第 10 天为结束日；或 (c) 开始后满 252 个交易日（上限从**最初开始日**算起，合并不重置），标“上限截尾” |
| 合并 | 仅当前一事件以 (b) 结束，且结束后 20 个交易日内再次满足开始条件 → 并入同一事件；结束计数在再次开始时清零重计；谷底在合并后整段重算。以 (a) 结束的事件不合并 |
| 确认 | 结束后满 20 个交易日未再次触发，事件结果才最终确认；确认窗口跨越期间边界的，按第 8.3 节跨界规则剔除 |
| 截尾 | 缺价、历史断点、退市、成分退出、期间结束导致无法确认的事件标截尾，单列 |

**唯一期望标签示例**（X = 6，仅为示例）：

| 交易日 | 情况 | 结果 |
| --- | --- | --- |
| d90 | 63 日最高收盘日 | — |
| d100 | 首次 D\_eval ≥ 6 | 事件 E 开始，峰值日 d90 |
| d108 | 目前最低收盘 | 暂定谷底 d108 |
| d120–d129 | 连续 10 日 D\_eval < 3 | 暂定结束 d129（方式 b） |
| d141 | 再次 D\_eval ≥ 6（结束后第 12 个交易日 ≤ 20） | 并入 E；峰值日仍为 d90；结束计数清零 |
| d150 | 新的最低收盘（低于 d108） | 谷底更新为 d150 |
| d170–d179 | 连续 10 日 D\_eval < 3 | 暂定结束 d179 |
| d180–d199 | 未再次触发 | d199 确认：E = 开始 d100、峰值 d90、谷底 d150、结束 d179；匹配区间 \[d90, d150)；252 日上限截止于 d351 |

### 8.6 F：风险升级频次中位数上限（R2-33 最终规则、J-7）

名称为“登记统计口径下的风险升级频次中位数上限”，**不是每只股票的硬上限**。口径先定义，再由发起人填写 F。

| 项 | 定义 |
| --- | --- |
| 统计单元 | 证券 |
| 有效观察期 | 该证券样本纳入区间 ∩ 开发期 ∩ `calc_status = OK` 的交易日（不含窗口不足、缺价、历史断点后未满 W + N 条的日子） |
| 单证券频次 | RISK\_UP 业务事件数（升至关注与升至警戒都计）÷（有效观察日数 ÷ 252） |
| 不完整年度与短样本 | 不按自然年切分，按有效观察日折算；有效观察日 < 126 的证券不进入中位数，单独列出 |
| 零事件 | 计为 0，进入中位数 |
| 聚合 | 跨证券取中位数 |
| 与投递无关 | 统计信号事件，不因消息合并、推送分层或冷却而下降 |
| 必须同时报告 | 分布（p10、p25、p50、p75、p90、p95、最大值）、频次超过 F 的证券占比、升至警戒的单独频次 |
| 投递负担 | 另在演练中报告每日消息数，不与 F 混用 |

F 的取舍：较小的 F 可能使选出的参数提醒更少、更晚，较大的 F 可能相反；这种关系不保证单调，以评价报告为准。

### 8.7 次要描述：提醒后路径类别（R2-27 最终规则）

- 从 T+1 起 H 个交易日（H【待批准，候选 20、60】），以收盘价判断先触达 C\_T + b × A\_T 还是 C\_T − b × A\_T。
- \*\*R2-27 最终规则：A\_T = 第 8.5 节评价口径（N = 20，SMA）在 T 日的 ATR；边界在整个 H 日内固定，不随候选参数变化。\*\*b【待批准，候选 2、3】。
- 结果：先下、先上、同日双触达（顺序未知）、都未触达、截尾。只作描述，不参与选参，不称“正确率”。

### 8.8 基线（R2-28 最终规则）

| 基线 | 每日隐含状态与转换 |
| --- | --- |
| B1 固定百分比 | 隐含等级：距 63 日最高收盘回撤 ≥ 20% → 2，≥ 10% → 1，否则 0；经与本系统相同的风险状态机（即时升级、连续 d 天降级，d 取阶段一选定值） |
| B2 均线 | 隐含等级：C\_T < SMA50 → 1，否则 0；经同一状态机，因此连续 d 天站上 SMA50 后退出，退出后再次跌破即产生新的升级 |
| B3 随机日期 | 每只证券从可评价日期（纳入区间内、calc\_status OK）中无放回抽取，次数等于候选参数下该证券的 RISK\_UP 数，每个抽中日记为升至关注；重复 1000 次，种子登记；指标取各次平均 |
| B4 固定反弹 | 使用与本系统相同的风险链、锚点与失效规则，只把 RB2 条件换成 C\_T ≥ A × (1 + r)，r ∈ {5%, 10%} |

开发期结束时冻结比较基线：阶段一取 B1、B2 中开发期主指标更好的一个；阶段二取 B4 中更好的 r。B3 作为健全性检查：点估计必须优于 B3，否则规则作废。

### 8.9 选参（R2-29、R2-30 最终规则）

网格序号：风险网格按 (N: 14, 20)、(freeze: 否, 是)、(k₁: 2, 3)、(k₂: 4, 5)、(g: 2, 3)、(d: 3, 5) 的字典序编号 1–64；反弹网格按 (K: 3, 5)、(S: 10, 20) 编号 1–4。

| 步骤 | 阶段一（风险参数） | 阶段二（反弹参数，固定阶段一结果） |
| --- | --- | --- |
| 合格 | 频次中位数 ≤ F | 结果确定的 RB2 链数 ≥ 最小样本 |
| 排序元组 | (覆盖率降序, 滞后中位数升序, 网格序号升序) | (失效率升序, RB2 链数降序, 网格序号升序) |
| 并列集合 | 覆盖率 ≥ 全局最优 − 0.01 的合格候选，相对全局最优一次确定，再按元组后两项排序 | 失效率 ≤ 全局最优 + 0.01，同理 |
| 稳健性 | 所选点的每个一步相邻点覆盖率 ≥ 所选 − Δ₁ | 每个一步相邻点失效率 ≤ 所选 + Δ₂ |
| 不满足稳健性 | 按排序元组取下一个合格且稳健的候选 | 同左 |
| 无合格候选 | 停止，请发起人裁决，不放宽 F | 停止，请发起人裁决 |

0.01、Δ₁、Δ₂【待批准，候选 0.05】。

**改进量方向（R2-30）**：阶段一 Δ = 候选覆盖率 − 基线覆盖率；阶段二 Δ = 基线失效率 − 候选失效率。两者都是越大越好；“优于基线”指 Δ 的 95% 置信区间下限 > 0。开发期不优于基线 → 结论记为“未优于基线”，停止并请发起人裁决，不自动改规则。

### 8.10 确认性检验（R2-31 最终规则）

- 只有两个确认性检验，均在验证期只做一次：阶段一选定参数对冻结基线的覆盖率改进、阶段二对冻结基线的失效率改进。
- 原假设 Δ ≤ 0；单侧；统计量为配对的 Δ；p 值 = 同步块自助分布中 Δ\* ≤ 0 的比例；两个 p 值用 Holm 法在 α = 0.05 下校正。
- 验证期不得更换比较基线或选择其他候选；其余比较一律标为探索性。

### 8.11 同步块自助法（R2-32 最终规则）

- 重采样对象是已算好的记录，不拼接价格：阶段一为事件记录，按事件开始日归块；阶段二为 RB2 链记录，按 RB2 日归块。
- 块：从期间首个交易日起每 63 个交易日一块，末块不足 63 日也保留；开发期与验证期分别切块。
- 每次重复有放回抽取与原始块数相同的块，抽中块内全部记录都计入（重复抽中则重复计入）；候选与基线使用同一组抽样索引。
- 2000 次，种子登记，百分位法 95% 区间。

### 8.12 最小样本（R2-34 最终规则）与数据不足（R2-35 最终规则）

| 指标 | 样本单位 | 最低要求【待批准，候选】 |
| --- | --- | --- |
| 阶段一覆盖率 | 结果确定的合并后大跌事件 | ≥ 30 个事件，来自 ≥ 10 只证券，分布在 ≥ 8 个块 |
| 阶段二失效率 | 结果确定的 RB2 链（按所属大跌事件聚类） | ≥ 30 条链，来自 ≥ 15 个不同的大跌事件，分布在 ≥ 8 个块 |

不称“独立事件”，相关性由自助法处理。**R2-35 最终规则**：开发期与验证期日期不因数据覆盖移动；单只证券数据不全的，在其可得范围内评价并列入排除报告；总样本达不到最低要求时停止，请发起人裁决，不移动已裁决的期间，也不放宽门槛补出结论。删除“按约 2:1 切分”。

### 8.13 登记纪律与结论表述（J-8）

- 同一轮研究不得在看结果后修改登记标准。后续修订另立版本，并披露原验证期已使用，不得再称为未见数据。
- 报告首页写明：样本、期间、数据来源与版本、覆盖不足（第 8.2 节）、幸存者偏差处理、固定版本复算的限制。
- 结论按登记指标表述，例如“在标普 500 历史成分股、2020 年至冻结月的验证期内，覆盖率相对基线 B1 的改进为……”，不笼统宣称“信号有效”。

## 3. 步进流程与第 1.2 节的对应

`step(state, day, src, params, replay_start)`：`src` 是 T01 的指标接口（`ComputedIndicators` 或 `TableIndicators`），只覆盖当前历史段。

| 规格 | 实现 | 转移 |
| --- | --- | --- |
| A1 缺价，m ≤ G | `engine._missing_day`：有预警时冻结、观察重置、三计数清零；prev\_confirm 为真时 RECOVERY\_REVOKED（DATA\_GAP，身份取重置前的周期与次数）；DATA\_ISSUE；日末 prev\_confirm = 假 | T1 |
| A1 m = G + 1 | 有预警时 DATA\_BREAK 并清空；清空 last\_release；显示"数据中断"；DATA\_ISSUE | T2 |
| A1 m > G + 1 | 保持"数据中断"，无事件 | T3 |
| A2 有日线 | 此前 m ≥ G + 1 时 seg\_start = T；m = 0 | T4 |
| A3 历史段不足 W + N | 由 `src.valid_bar_count(T)` 判定，显示"不可计算" | T5 |
| B4 | `engine._no_episode`：受限窗口最高与峰值日、A\_start（PEAK / MIN）、D\_T、R2（`compute_r2`） | |
| B5 启动 | D\_T ≥ k₂ → 警戒；D\_T ≥ k₁ 或 R2 → 关注；ATR\_ep = A\_start；L\_ep = [p\_ep, T] 最低收盘（并列取最早）；obs\_start = T、cycle\_no = 1 | T6、T7（否则 T8） |
| C6 | `_transition_evidence`：新低（C < L\_ep − ε\_p）、D\_ep；关注且已降级时更新 H\_d、计算回吐比率 | |
| C7 | 新低：更新 L\_ep、l\_ep，观察重置 | |
| C8 | `_escalation`、`_escalate`：T9 → T10 → T11 取首条；命中则警戒、观察重置（同日已重置则不再重置）、三计数清零、H\_d 清空，跳到第 11 步 | T9–T11 |
| C9 | `_observation_evidence`：since\_obs、企稳、长期稳定、恢复确认、U、强恢复、E\_down / E\_rel；新低日一律为假或空 | |
| C10 | `_counters`、`_counters_watch`：计数四阶段与降级、解除 | T12–T16 |
| C11 | `_progress_events`：恢复进度事件，然后写入 prev\_confirm | |
| 12 观察标签 | **不实现**（I8） | |

- **回放区间（I2）**：`replay_start` 之前只运行 A（缺价计数、历史段），不运行 B、C，不产生任何事件，包括 DATA\_ISSUE；回放起点当日以"无预警"开始。诊断记录的 `in_replay` 为假。
- **观察终点（I3）**：`finalize(state, reason)` 或 `run_bars(..., end_reason=...)`。到达终点时若有进行中的预警，标为截尾，终止原因 `LISTING_END` 或 `EXPLORATION_END`，写在最后一天诊断记录的 `end_reason` 中。截尾不是事件，不产生 RELEASE 或 DATA\_BREAK。
- **历史段**：`split_segments(presence, G)` 与引擎 A 段采用同一规则；`run_bars` 为每个历史段建一个 `ComputedIndicators`，新历史段的指标从该日重新积累。

## 4. 计数四阶段（E-01）与解除原因（E-03）

1. 取昨日日末计数（`Episode.dc / rc / xc`）。
2. 今日候选计数：警戒时 dc\_cand = E\_down 非空 ? dc + 1 : 0；关注时 rc\_cand = E\_rel 非空 ? rc + 1 : 0；DIRECT 时 xc\_cand = 强恢复 ? xc + 1 : 0，TWO\_STAGE 恒为 0。
3. 转移只比较候选计数是否等于 d：
   - 警戒：xc\_cand = d（DIRECT）→ RELEASE（T14）；否则 dc\_cand = d → DOWNGRADE（T15）；
   - 关注：xc\_cand = d 或 rc\_cand = d → RELEASE（T12）。
4. 写入日末计数：降级时 dc、rc 清零，**xc 保留**；T13、T16 写入候选值；加重、观察重置时三计数清零。

事件依据记录候选计数（`dc_cand / rc_cand / xc_cand`），状态保存日末计数，两者在转移日不同（不变量 9）。

解除原因：只有 xc 达到 d → `DIRECT_STRONG_RECOVERY`；只有 rc 达到 d → 该 rc 计数段证据的并集，按 a′、b′ 排序；两者都达到 → 都记，DIRECT 在前。当日证据另存为 `today_evidence`，计数段内每日的证据集合存为 `segment`。降级原因为当日证据（12 号 S4："DOWNGRADE（b；计数段 {a}、{a}、{b}）"），计数段同样存为 `segment`。

## 5. 业务身份（12 号第 1.7 节；I19）

| 事件 | identity（`Event.identity`，与类型一起唯一，见 `Event.key`） |
| --- | --- |
| START、ESCALATE、DOWNGRADE、RELEASE、DATA\_BREAK | (episode\_id, 类型, 信号日) |
| STABILIZED | (episode\_id, cycle\_no) |
| RECOVERY\_OBS | (episode\_id, cycle\_no, 本周期第 n 次) |
| RECOVERY\_REVOKED | (episode\_id, cycle\_no, 对应的第 n 次)；DATA\_GAP 与 ESCALATED 取观察重置前的周期与次数 |
| RECOVERY\_FAIL | (episode\_id, 被终止的 cycle\_no) |
| DATA\_ISSUE | (代码, DATA\_ISSUE, 信号日)（I19） |

episode\_id = "代码:START 信号日"（I19），重跑不变。观察重置前的周期快照取自昨日日末的预警（`_Day.snapshot`）。

每个事件带结构化依据 `basis`（原因、D\_T / D\_ep、候选计数、收盘等）和转移编号 `transition`（T1–T16；恢复进度事件中只有 DATA\_GAP 撤销记 T1，其余不对应等级转移，记为空）。不生成文案。

## 6. 诊断记录（`DailyRecord`）

每天一条，覆盖 03 计划 T04b `daily.csv` 的固定字段：

| 组 | 字段 |
| --- | --- |
| 数据 | `data_status`（HAS\_BAR / MISSING / DATA\_BREAK / INSUFFICIENT）、`m`、`seg_start`、`in_replay` |
| 状态 | `display`、`level`、`episode_id` |
| 基准 | `p_ep`、`p_ep_day`、`atr_ep`、`l_ep`、`l_ep_day` |
| 严重度 | `d_t`、`a_start`（无预警时）、`d_ep`（有预警时）、`r2_status`、`r2_score`、`r2_triggered` |
| 观察 | `cycle_no`、`obs_start`、`since_obs`、`stable`、`long_stable`、`new_low` |
| 确认 | `confirm_method`、`confirm_line`（SMA10 / box\_high / 前 K 日最高）、`confirmed` |
| 强恢复 | `u`、`strong_threshold`（价格门槛 L\_ep + min(u\_rel × ATR\_ep, φ × (P\_ep − L\_ep))）、`strong` |
| 证据与计数 | `evidence`（警戒时 E\_down，关注时 E\_rel）、`dc_cand / rc_cand / xc_cand`、`dc / rc / xc`（日末） |
| 降级以来 | `h_d`、`giveback` |
| 其他状态 | `box_high`、`downgraded`、`obs_issued`、`prev_confirm`、`last_release` |
| 重置与终止 | `reset`、`reset_reasons`（NEW\_LOW / ESCALATE / DATA\_GAP）、`transition`、`end_reason`（RELEASE / DATA\_BREAK / LISTING\_END / EXPLORATION\_END） |

约定：启动日不判断降级、解除或恢复进度，相应字段记为空（未计算）。解除日记录被解除预警的冻结字段（P\_ep、L\_ep 等），等级、计数、H\_d 为空，`end_reason = RELEASE`。断点日 `episode_id` 记被结束的预警，`end_reason = DATA_BREAK`。

## 7. 不变量（13 号第 4 节）

`check_invariants(results, params)` 返回违反项列表，夹具测试与以后的真实回放都调用：

1. 每个交易日 cycle\_no 至多加一；每天至多一次等级变化。
2. （BOX）box\_high 只在本周期 since\_obs = K 当天写入，此后直到观察重置不变。
3. H\_d 只在"关注且 downgraded"时有值；加重当日清空。
4. TWO\_STAGE 时 xc 恒为 0。
5. 解除当日没有恢复进度事件。
6. 缺价日末尾 prev\_confirm 为假；每次 RECOVERY\_OBS 开启的确认至多以一个事件结束（撤销或恢复失败）；确认已撤销时，恢复失败只终止周期。
7. 新低日 E\_down、E\_rel 为空，强恢复不成立。
8. 每个观察周期至多一次 RECOVERY\_FAIL，只在该周期发出过恢复观察时出现。
9. DOWNGRADE、RELEASE 依据中的计数等于当日候选计数。

## 8. 验收（T03）

测试在 `tests/unit/lifecycle/`。期望值全部来自 10、12、13 号文档，没有用引擎输出回填。

- S 组用按表给定的指标（`TableIndicators`）。每个夹具前置一个峰值日（收盘 100、ATR 2），开盘取前一日收盘，使 R2 不触发；历史长度视为充足。表中没有列出的输入（S9 中间日的 ATR、S12 的 d2–d39）在测试中注明"推导"。
- F 组按 13 号第 2 节构造完整日线，用 `run_bars` 端到端运行，不跳过历史长度检查、不注入前态；F1–F5 × 3 种确认方法 × 2 种解除路径 × 2 种 atr\_basis。
- 每个夹具运行不变量检查器；F 组做 I17 第 ① 项无前视检查（每条路径 3 个日期）。

## 9. 已知限制

- 第 1.2 节第 12 步观察标签、第 1.6 节状态修正与衔接、投递、冷却、文案均不实现。
- **BOX\_ROLL 的撤销原因代码规格未给出**，暂用 `BELOW_ROLLING_HIGH`（待产品经理裁定）。
- 缺价日且无进行中的预警时，显示状态保持前一日（正常或不可计算），数据状态记 MISSING。规格没有专门规定。
- 性能：每日工作量与历史长度无关。窗口量的计算量为 O(W)，ATR 为 O(N)，L\_ep、H\_d、计数、since\_obs、box\_high 增量更新。本机单个候选、单只股票约 11 年日线约 0.2–0.3 秒；27 只 × 768 组单进程约 1.5–2 小时，T04 需要多进程。

## 1. 目标与边界

**探索期要回答的问题**：v0.7 生命周期规则在真实日线上能否做到"及时预警、及时降级与解除、每次变化说明依据"；哪些规则在真实行情中出现规格没有预料到的行为。

**产出**：

1. 一个严格按 v0.7 实现、通过全部构造夹具的生命周期引擎（domain 层，纯函数）；
2. 在 41 个代码上逐日回放（2009-01-01 至 2019-12-31）得到的事件表、每日状态表和交互图；
3. 产品经理据此写出的"探索中发现"，作为规格 v0.8 的修订依据。

**不做**：

- 评价协议（第 5 节：事件集 E\_atr / E\_pct、S1 / S2、门槛、选参、基线、重采样）。这部分依赖 SR-M1 登记的数值，下一份计划再做。
- 数据库、推送、API、前端、每日调度。
- 任何 2020-01-01 及以后的数据。

**已知偏差（如实记录，不回避）**：探索期在开发期数据（2010–2019）上看结果，SR-M1 登记的数值会受到这次观察的影响。这削弱的是开发期结论，不影响验证期：验证期在冻结前一直封存，这正是封存方式 A 的作用。审阅方请评估这一安排是否可以接受（第 7 节 Q1）。

## 3. 关键实现决定（规格未写明之处，产品经理裁定，探索期适用）

这些决定先按下表执行，在规格 v0.8 中正式写入。Claude Code 不得自行另做选择。

| 编号 | 问题 | 决定 | 理由 |
| --- | --- | --- | --- |
| I1 | 交易日历 | 以 SPY 的交易日作为 NYSE 交易日历的代理 | SPY 每个 NYSE 交易日都有成交；v0.4 要求的正式日历版本留到 SR-M4 |
| I2 | "缺价"的判定 | 在证券的上市期间内，日历上的交易日没有日线即为缺价；首条日线之前和退市日之后不算缺价 | 与 v0.7 第 1.2 节 A 一致；避免把上市前和退市后误报成数据中断 |
| I3 | 退市或数据结束时有进行中的预警 | 回放到最后一个有效日为止；该预警标为"截尾（数据结束）"，不生成 DATA\_BREAK | 规格未覆盖退市；评价中退市事件另行处理（v0.4 第 8.1 节） |
| I4 | 价格口径 | 全部信号用复权价（adj\_\*）；原始价只用于审计 | v0.4 第 2.1 节 |
| I5 | 指标输入方式 | 生命周期引擎不自己算指标，通过 domain 内的指标接口取 ATR\_N、SMA10 与收盘序列；两种实现：由日线计算（回放用）、按表给定（夹具用） | v0.7 夹具里 ATR、SMA10 是"给定输入"；同一引擎必须同时通过夹具和真实回放 |
| I6 | 探索期临时值 | K\_stab = 8；G = 10；φ = 0.5；ε\_p = 1e-9；ε\_r = 1e-10 | K\_stab、G 待 SR-M1 登记；8 与夹具一致且满足 ≥ 5；G 取较短的候选，数据中断更早暴露。全部标注"探索期临时值" |
| I7 | 回放候选 | 参考组合 N = 20、k₁ = 2、k₂ = 4、K = 3、d = 3、u\_rel = 3，乘以全部 12 种结构组合（confirm × release\_path × atr\_basis），共 12 组出图；768 组全部回放只出汇总统计 | 12 组足以看出结构维度的差异；看图不需要 768 组 |
| I8 | 观察标签与大盘背景 | 引擎不处理（v0.7 第 1.2 节第 12 步只改文案）；图上另画 SPY、QQQ 的 63 日回撤，只作参照 | 与 market-risk 的约定一致：不复算它的规则 |
| I9 | 数值类型 | 探索期用 float，比较一律用 ε 辅助函数，求和用 `math.fsum`；v0.4 第 2.0 节的 Decimal 入库量化留到 SR-M4 | 探索期没有数据库；ε 比较已能保证离散结果稳定 |

## 4. 任务拆分

每个任务一张任务卡（`docs/tasks/Txx-*.md`），由 Claude Code 执行。每个任务结束都要满足：测试、分层契约、代码检查全部通过；文档已同步；按任务卡格式写回执。

### T00 仓库卫生与数据审计（立即执行）

- 修正 Git：`.env` 撤出暂存区；`.idea/` 整个忽略；确认已推送的历史里没有密钥。
- 研究样本支持多代码分段拼接（D1）；新增上市期间配置 `config/listing_periods.csv`（D2、D3），每条写明来源。
- 新命令 `stock-risk audit-raw`：运行第 2 节的检查，输出 `output/audit/` 下的明细，以及 `docs/develop_docs/04-数据审计报告.md`。
- **验收**：VRX 拼接后连续到 2019-12-31；SHLD、WFT、SMH 的有效区间来自可查证的来源；审计报告列出 D1–D5 的结论和全部"明确失败"项。

### T01 数值规范与指标（domain）

- `domain/numeric.py`：ε 比较（≥、>、≤、<，比率与价格两套）、fsum 求和。
- `domain/calendar.py`：交易日历与历史段（I1、I2）；按日历产出"有日线 / 缺价"的逐日序列。
- `domain/indicators.py`：TR、ATR\_N（简单平均，v0.4 第 2.1 节）、SMA\_M、受限窗口最高收盘与峰值日（并列取最近）、区间最低收盘（并列取最早）、R2 跳空（前一交易日必须有日线，v0.4 第 2.3 节）。
- 指标接口（I5）及两种实现。
- **验收**：v0.4 第 2.0 节的复算判据示例；手算小样本；输入非法时抛 `InvalidInputError`。

### T02 生命周期引擎（domain）

- `domain/lifecycle/`：状态与字段（v0.7 第 1.1 节）、参数对象（9 个候选维度 + 固定值 + 临时值，临时值单独标记）、每日步进函数（第 1.2 节 A/B/C 共 12 步）、计数规则（第 1.4 节）、恢复进度事件（第 1.5 节）、事件业务身份（v0.6 第 1.7 节）。
- 每个转移带上 v0.7 第 2 节的编号（T1–T16），写入事件依据，便于逐条对照。
- 第 1.6 节（状态修正与衔接）属于投递层，探索期不实现，在代码中留接口说明。
- **验收**：T03 全部通过。

### T03 验收夹具（tests）

- 把 v0.6 第 7.1 节 S1、S3、S4、S6–S9，v0.7 第 7.1 节 S2 说明与 S5 扩展、第 7.2 节 S10–S15，逐条写成测试；F1–F5 用 v0.6 第 7.2 节的价格路径，按 3 种确认方法 × 2 种解除路径，对照 v0.7 第 7.3 节的结果。
- 测试名带夹具编号（如 `test_S11_half_recovery_release`）；每张表逐日比较等级、计数、事件。
- **规格与实现不一致时，停止并报告**：不得为了通过测试而改规格表、改测试或调整实现去迎合某一方；在回执中列出"夹具编号、日期、规格值、实现值、对应规则条款"，由产品经理裁定。
- **验收**：全部夹具通过，或全部不一致项已列入回执。

### T04 回放与输出（application + infrastructure + interfaces）

- 用例 `ReplayService`：读取原始 CSV（含上市期间与拼接），按日历逐日调用引擎，2009-01-01 至 2019-12-31（受封存约束）。
- 输出到 `output/replay/<候选编号>/`：每只股票一份 `events.csv`（日期、事件、等级前后、依据、转移编号）、`daily.csv`（每日状态与关键字段）、`chart.html`（收盘价、状态色带、事件标记、L\_ep、确认线，下方副图为 D\_T / D\_ep 与 SPY、QQQ 回撤）。
- 汇总 `output/replay/summary.csv`：每个候选、每只股票的预警次数、平均持续交易日、占用率、恢复观察次数、恢复撤销次数、恢复失败次数、解除后再次启动的间隔分布。只描述，不设门槛，不排名。
- 命令：`stock-risk replay --candidates reference12|all [--symbols ...]`。768 组全量回放允许多进程。
- **验收**：12 组参考候选 × 41 个代码出图；全量 768 组汇总生成；回放过程中任何封存越界都直接报错。

### T05 探索复盘（产品经理）

- 产品经理逐只查看图表和汇总，重点看：大跌是否及时启动；谷底后多久发出恢复观察与解除；解除后多久再次启动；长期挂着的关注；各结构维度的差异。
- 写成 `docs/develop_docs/05-探索中发现.md`，每条注明代码、日期、候选和图表文件；据此起草规格 v0.8。
- 不在此阶段做"哪个候选更好"的结论。

## 5. 依赖与顺序

T00 → T01 → T02 → T03 → T04 → T05。T02 与 T03 可以交替推进，但 T03 全部通过（或不一致项已被裁定）之前，不开始 T04。

## 6. 执行规则

1. **审阅先行**：本计划经 ChatGPT、Gemini 审阅，阻断项全部解除后，产品经理逐张签发任务卡。T00 只涉及仓库与数据卫生，不依赖任何待审的算法内容，产品经理裁定立即签发；发起人可以否决。
2. **一卡一提交**：Claude Code 每张任务卡在本地提交一次（可以多次中间提交，最后一次提交说明写任务编号），不推送；推送由发起人决定。
3. **回执**：每张任务卡结束时，按 `docs/tasks/README.md` 的格式输出回执，由发起人转给产品经理。
4. **不擅自决定**：遇到规格歧义、规格与夹具矛盾、需要业务数值时，停止该部分并写进回执，不自行假设。

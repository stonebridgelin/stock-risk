## 2. 输入与返回值

`EvalSeries(calendar, bars, gap_break, mask_min, end_reason)` 的日历仅含观察区间；`bars` 是与日历逐日对齐的元组，有日线为 `DailyBar`，缺价为 `None`。`gap_break` 必须与引擎回放时的 G 一致，`mask_min` 由调用方按比较方法集合传入。终止原因为 `DATA_END`、`DELISTED`、`REQUIRED_END`、`PERIOD_END`。

派生的 `segment_ids`、`segment_counts`、`valid_ordinals`、`mask`、`closes`、`atr20` 均与日历对齐。短缺价日保留段编号与段内计数，但掩码为假、价格与 ATR 为 `None`；连续缺价第 G+1 日记录断点，并清空段编号与计数。恢复首条日线另起历史段。`valid_days` 只含有效日，序号从 0 起。ATR20 必须有同段 21 条有效日线，前收取同段上一条有效日线的收盘，ATR 本身不量化。

`build_events(series, spec, params)` 返回 `EventChain`。`spec` 显式给出种类 `PCT` / `ATR`、Decimal 阈值与名称；`params` 显式给出 Decimal `rho_end` 和有效日窗口 `w_q`。E_pct10 使用 PCT 种类与 0.10 阈值。开始后的 E_atr 比率始终使用冻结的 `a_s`。

`SevereEvent` 的全部对外日期均为 `date`；比率 / 价格为 Decimal；原因集合为 `frozenset`。`e` 对应夹具的 `end`，`c_p` 对应 `C_p`，`is_main` 对应 `main`。已确认事件有 `report_trough` 和 `label_determinable`；右端截尾事件有 `k_star`，处于待确认状态时保留暂定 `e` 和原因 b，并记录 `(e, 数据终点]` 的依赖未决区间及有效日数。报告谷底并列取最早，恢复锚并列取最近。

### 截尾与前缀完整（D-11；T09-E1R R2）

- 已确认的事件：[p, 确认日] 内有缺价日（m ≤ G）记截尾 `MISSING`。
- **未确认的事件（右端截尾，包括进行中与待确认）**：若 [p, 数据终点] 内有缺价日（包括数据终点前的尾部缺价），在 `RIGHT_<原因>` 之外另记 `MISSING`（夹具 A\_M1–A\_M3）。
- 断点截尾（`DATA_BREAK`）的事件不另记 `MISSING`：构成断点的连续缺价本身就是断点。
- **前缀完整**：只有右端截尾一项，且 [p, k\*] 内每一日都在掩码内。未确认事件在观察终点前有缺价时截尾多出 `MISSING`，因而**为假**。
- 数值输入（`domain/numeric.py`，T09-E1R R3）：`quantize_price` 在固定上下文 `PARSE_CONTEXT` 中解析与量化，量化失败（如超出精度）抛 `InvalidInputError`；`parse_finite` 转换成 float 后不是有限值时抛 `InvalidInputError`。默认环境下的结果不变（生命周期全部夹具不变）。

`EventChain.events` 按开始日排序；`dependency_pending` 返回未决区间元组；`counts` 返回事件总数、主口径数、前缀完整数、各截尾 / 不可评估原因的事件数与未决有效日数，各原因可以重叠。

调用示例（构造 `calendar`、`bars` 的 I/O 由应用层负责）：

```python
from decimal import Decimal

from stock_risk.domain.evaluation.event_model import EventKind, EventParameters, EventSetSpec
from stock_risk.domain.evaluation.events import build_events
from stock_risk.domain.evaluation.params import PROPOSED_EXPLORATION
from stock_risk.domain.evaluation.series import EndReason, EvalSeries

values = PROPOSED_EXPLORATION  # 拟定，待 SR-M1′ 批准；仅探索使用
series = EvalSeries(calendar, bars, gap_break, values.mask_min, EndReason.DATA_END)
spec = EventSetSpec(EventKind.PCT, Decimal("0.20"), "E_pct")
events = build_events(series, spec, EventParameters(values.rho_end, values.w_q))
```

D-31 的临时值为 X_pct=0.20、X_pct10=0.10、X_atr 候选集合=(6,8,10,12)、rho_end=0.5、w_q=20、rho=0.5、y_max=252、y_cap=60、q=20、q_l=60、n_min=10、mask_min=83。均为拟定，待 SR-M1′ 批准。门槛、y_pct、y_atr、ε、Δ 没有提供默认值。固定事件规则仍是 63 日峰值窗口、252 日上限、10 日安静计数、20 日确认期。

## 7. E5：重采样（T09-E5）

`resampling.py` 严格按 T09 卡 E5 的 7 步程序实现，不做预聚合等优化（夹具 E17 依赖它逐位复现）。

| 函数或对象 | 作用 | 依据 |
| --- | --- | --- |
| `CalendarBlocks` | 期间的市场交易日历自首个交易日起每 63 日一块，末尾不足 63 日的并入前一块（全期不足 63 日为 1 块）；`block_of` 给出某日所在块。事件按峰值日、RELEASE 与 RECOVERY\_OBS 按信号日取块 | 第 7 步；17 §9 |
| `draw` | 一次重复的 w、v：先抽证券 `[rng.randrange(I) for _ in range(I)]`，再抽块（L\_b = 1 逐块；L\_b > 1 先抽 ⌈J / L\_b⌉ 个起点、各展开 L\_b 个相邻块、拼接后截取前 J 个） | 第 2、3 步 |
| `Observation`、`weighted_mean` | 评价单位（证券、块、各方法的值，不纳入为 None）；Σ w\_i v\_b × 值 ÷ Σ w\_i v\_b，十进制、不量化，分母为 0 为 None | 第 4 步 |
| `bootstrap` | `random.Random(seed)`，B 次重复；同一次重复所有方法共用同一组权重；均值另存 12 位量化值供报告；`Replicate.valid`（全部方法都有值）只作诊断，不控制任何一对方法的检验（T09-E5F） | 第 1–4 步 |
| `improvement_test` | 只用配对有效重复（基线与候选的均值都不为空），B\_v、Δ\*、p、适用性与下界都用这同一组重复，与其他方法是否有值无关（T09-E5F，FR-01）；Δ\* = 基线 − 候选（不量化的均值相减后量化）；p = (1 + #{Δ\* ≤ 0}) ÷ (B\_v + 1)；B\_v < 0.99 B 时方法判为不适用；单侧 95% 下界 = Δ\* 的第 5 百分位（第 7 型） | 第 5、6 步 |
| `holm` | 标准逐步向下：p 升序（并列按名称），第 k 个乘以 m − k + 1，累计最大值，上限 1 | 第 6 步 |

- B、种子、L\_b 由调用方传入（登记值），代码中没有默认值。证券等权均值（17 §9"另报"）与附录 S 的模拟不在本阶段。

**测试**（`test_e5_resampling.py`）：E17 在 L\_b = 1 与 2 下逐次比较 w、v、两个方法的均值、Δ\*、有效重复数与 p；抽取顺序；B\_v 阈值（恰等于 0.99 B 时适用）；Holm 校正（含累计最大与上限 1）；块划分的末尾并入；输入检查。

**待确认 E5-01**：E17 的 L\_b = 2 情形 B\_v = 7，小于 0.99 × B = 7.92，按第 5 步方法判为不适用；夹具同时给出 p = 0.125。实现为：p 照算照报，另以 `applicable = False` 标出不适用（判定时不使用）。

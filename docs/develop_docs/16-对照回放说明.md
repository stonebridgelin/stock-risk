## 1. 命令

```
uv run stock-risk compare [--workers 7]                         正式对照回放：636 套 × 27 只个股
uv run stock-risk compare --sets <套,...> --symbols <代码,...>   调试：只跑部分套（自动加上基准），运行标为 debug
uv run stock-risk regress-v0 --baseline 20261014T015654-dc5b14c  V0 真实数据回归（T06a）
```

- 回放对象：27 只个股，SHLD 只用更正口径。
- 只有干净工作区上运行**全部套与全部个股**时，运行才标 `formal`。指定了 `--sets` 或 `--symbols` 时一律为 `debug`。
- 按（结构组合, N）分组多进程（T08a D-04），每个子进程初始化时接收一次全部回放对象的数据。组内先运行 V0 基准，再按变体全集的顺序运行其余各套（r2\_floor OFF 排在对应的 ON 之前）；V0 基准与 OFF 配对的逐日视图按对象缓存，最后一个使用者用完即释放，所以**每组只算一次**（此前每套各自重算一遍基准与配对）。只请求部分套时，所需的基准与配对作为辅助运行，不输出。套数多的组先提交。

## 4. 统一口径

- **统计期间**：全部对照表（第 1–6 项）都只取 2010-01-01 至 2019-12-31，与 15 号第 5 节相同；2009 年为预热期。
- **状态**（6 种）：正常、关注、警戒、不可计算、缺价冻结（当日缺价；T08a B-04 起写作"缺价冻结（正常）""缺价冻结（关注）""缺价冻结（警戒）"，保留冻结时的等级）、数据中断。解除日日末为正常。
- **可计算日**：有日线、历史段充足、在回放区间内。
- **有效交易日**：有日线的交易日。"随后 n 个有效交易日"不含事件当日；观察终点之前不足 n 日，或窗口内出现数据中断，记为"窗口不完整"。
- **重叠**：双方日末等级为关注或警戒的同一日。
- 价格为复权收盘；跌幅、涨幅为相对比例（−0.05 = −5%）。

### 4.1 运行清单中的 I17 ② 字段（T10-M0b 第 2 节）

- 预期检查键在运行开始时由 I17\_SETS（3 套）× I17\_TARGETS（5 个对象）生成，共 15 个（套, 对象），写入 `i17_expected_keys`。
- 每个检查键比较"单进程不缓存"与"多进程缓存"两种方式：`i17_check` 每条记录含 key、set\_id、target、equal（离散摘要，原有）、semantic\_equal（全语义摘要，新增）、days。
- 套不在结果中、对象未回放或多进程未返回摘要的键记入 `i17_missing_keys`（原写法为跳过）。
- `i17_ok` 要求每条记录两项都为真、没有缺项与重复、检查不为空。清单字段顺序：`i17_expected_keys`、`i17_missing_keys` 紧跟 `i17_ok`。
- 正式回放为固定抽样的三模式检查；正式对照回放为固定抽样的两模式检查；四模式与倒序提交由专用合成测试检查（`tests/unit/application/test_i17_modes.py`）。

## 5. 各表字段

### 5.1 逐日覆盖

- `coverage_daily_<套>.csv.gz`：每行一个（证券, 交易日），只取双方都可计算的日子；字段为双方的 display、level（0 无 / 1 关注 / 2 警戒）、episode\_id。
- `coverage_summary.csv`：按套、按证券的四格 `both / only_v0 / only_new / neither` 与 `common_days`。程序检查四格之和等于共同可计算日数。
- `excluded_days.csv`：被排除的日子及双方状态。

### 5.2 事件对照 `event_compare_<套>.csv`

| 列 | 含义 |
| --- | --- |
| direction | `V0→新`：对 V0 的事件看新变体；`新→V0`：反向 |
| event\_type / date / episode\_id / close | 事件 |
| other\_status / other\_episode\_id | 对方当日状态与当日的预警 |
| first\_20 / wait\_20 | START：对方当日无预警时，随后 20 个有效交易日内对方首次 START 的日期与等待日数。ESCALATE：对方首次进入警戒 |
| min\_close\_rel\_20 / end\_close\_rel\_20 | 事件日之后至对方首次通知（或窗口末）的最低收盘、窗口末收盘，相对本方事件收盘 |
| first\_60 … end\_close\_rel\_60 | 同上，60 日 |
| partner\_episode\_id / partner\_end\_date / partner\_end\_reason / release\_day\_diff | RELEASE：双方预警互为唯一重叠时，对方预警的终止日与原因；双方都以解除结束时，给出解除日期差（对方 − 本方，有效交易日） |
| tags | 多个标签以分号分隔，不互斥：`20 日内无通知`、`60 日内无通知`、`窗口不完整（20 日）`、`对方当日已在预警（关注/警戒）`、`对方当日为警戒`、`20 日内未进入警戒`、`多对多`、`无重叠` |

- 覆盖范围：每个 V0 START（`V0→新`）与每个新变体 START（`新→V0`）各一行，每个 V0 ESCALATE 一行，双方的每个 RELEASE 各一行。程序检查 START 全部覆盖。
- 不称为"延迟"。

### 5.3 重叠映射 `overlap_<套>.csv`

全部（V0 预警, 新变体预警）重叠关系，允许多对多：重叠日数、首末重叠日。

### 5.4 单开关配对 `pairs_summary.csv`

| 配对 | 范围 | 对数 |
| --- | --- | --- |
| r2\_floor OFF / ON；long\_path X1 / X2；x₁ 8% / 10%；x₂ 15% / 20% | V1、V3、V4 内，其余设置相同 | 各 288 |
| release\_hyst | V1 与 V3 中设置相同的两套（192）；V0 与 V2（12） | 204 |
| rec\_scale | V3 与 V4 中设置相同的两套 | 192 |
| N 14 / 20 | N14 组与对应的 N20 套 | 24 |
| long\_path\_off | V3\_LOFF 与 V3 参考取值（N = 20）中结构组合相同的两套（T08a C-05） | 12 |

合计 1584 对。每对给出 `burden_by_set.csv` 中负担指标的 a、b 值与差（b − a；a 为 OFF、X1、8%、15%、OLD、OFF、N20、long\_path = OFF 一侧），以及两套之间的逐日覆盖四格（`cov_both / cov_only_a / cov_only_b / cov_neither / cov_common_days`）。

### 5.5 专项清单

- `special_r2_filtered.csv`（r2\_floor ON 套，与其 OFF 配对比较）：ON 中每个被过滤的 R2 日（R2 触发但 DD\_T < x₁）一行。标签：`(i) 其他路径启动`（同日）或 `(i) 随后由其他路径启动`（记 `on_next_start`、`on_start_gap_days`）；`(ii) OFF 的 START 在 ON 中被取消`，若此后没有任何启动，另记 `至观察终点无后续通知`。被过滤的 R2 **日数**单列在 `special_r2_filtered_days.csv`，不把标签数量相加。
- `special_cancelled_escalations.csv`：V0 有、新变体当日没有的进入警戒。记当时 V0 的 D\_ep、DD\_ep、新变体状态，以及此后 20、60 日内新变体是否进入警戒和期间路径。
- `special_l_path_starts.csv`：新变体中只有 L 路径成立的 START（原因只有 `R1L_CUMULATIVE`）。记 dd\_l、此后 20、60 日的路径、V0 当日状态。
- `special_v1_l_release_without_rise.csv`：V1 中以 L 路径启动、解除收盘不高于启动收盘的预警（10 号第 1A.5 节已知副作用）。单列，不计入 L 路径的效果。

### 5.6 通知负担

- `burden.csv`（每套每证券）：
  - 有效证券年：期间有日线的交易日数 / 252；
  - 次数与每年次数：`n_start`（= 首次 `n_start_first` + 短期再启动 `n_start_short_restart`，即紧邻的前一次预警以解除结束、且距其解除 ≤ 20 个有日线的交易日；口径与 episodes.csv 的 days\_since\_prev\_release 相同，T08a C-06）、ESCALATE、DOWNGRADE、RELEASE、RECOVERY\_OBS、RECOVERY\_REVOKED、RECOVERY\_FAIL；
  - 占用率；
  - 持续 ≥ 200 个交易日的开发期预警个数与天数；
  - 解除后 20、60 日窗口完整与不完整的个数、跌破 L\_ep 的个数、跌幅中位数；
  - 未解除的预警个数。
- `burden_by_set.csv`：按套合并，每年次数 = 次数之和 ÷ 有效证券年之和；占用率两种口径：`occupancy_pooled`（合并证券日）、`occupancy_median_across_securities`（跨证券中位数）。
- `release_followups.csv`：每次解除的 20、60 日最低收盘、相对解除收盘的跌幅、是否跌破所解除预警的 L\_ep、窗口是否完整。
- `unreleased.csv`：截尾或至观察终点仍未解除的预警。

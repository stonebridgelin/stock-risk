## 1. 数据封存

- 探索与开发用的行情严格截至 2019-12-31。2020 年起的数据（个股、指数、ETF、大盘信号都算）一律不下载、不读取、不展示，也不改封存常量。
- 封存期只在登记冻结后做一次确认性检验，结果不得回头改规则。
- （澄清，2026-10-17）这次检验经发起人批准后执行，届时才解除读取限制、修改封存常量；在此之前，上一条没有例外。

## 2. 只用决策当时可得的信息

- 日线信号只能用决策当时已经可得的信息。事后的事件标签、最终谷底、回放确认和 F_ref 不得回流到信号引擎。
- 股票池按当时成分取：含后来退市、被并购的股票，不能用今天的名单回看过去。
- 复权不能借用未来：不得用只有事后才知道的复权因子生成历史信号。
- 时点统一：所有外部输入（含大盘信号）都按"第 t 日收盘后可得、第 t+1 日生效"这一条统一口径。
- （澄清，2026-10-17）公司行动（拆股、分红）例外：按除权日生效，因为除权日的价格本身已经反映了这次行动；并且只使用除权日之前已经公告的行动。
- （澄清，2026-10-17）"复权不能借用未来"按字面执行：第 t 日的信号只能使用除权日不晚于 t 的公司行动。以 2019-12-31 为锚、一次性向前复权的序列，含有 t 之后的行动，不得用于生成 t 日的信号。

## 3. H1 协议

- 按 17 号协议执行，违反次数必须为零。
- 不能用降低负担、提高平均指标或新增理论来替代。
- 未知分为甲、乙两类，归类按 17 号协议第 4 节逐项写明；有疑义的归乙类。
  - **甲类**：检查点因价格数据本身（退市、缺价、预热、右截尾）无法建立，对全部候选（含 B1、B2、R0）逐件相同，以测试断言。
    - 甲类按原因分别计数，逐件列出，不计入违反。
    - 甲类比例超过登记的上限（退市类另设单项上限）的，该期间的评价记为"证据不足"，不能记为通过。
    - 上限在 T08c 登记时由发起人批准；批准前不得查看选参集的甲类比例。
    - 另做敏感性报告（甲类全部按违反计），只作描述，不改变资格。
  - **乙类**及其他一切未知、缺数据、无法计算：一律记为未通过，不能记为通过，也不能剔除不计。

## 4. 输出边界

- 系统只陈述风险与恢复的证据。不给买卖或仓位建议，不说"已触底""底部确认"，不声称有预测能力或胜率，也不做"最可能反弹"之类的排序推荐。
- （澄清，2026-10-17）"不做排序推荐"约束的是对个股的输出；17 号协议中对候选方法的资格判定与排序是选参流程，不在此列。
- 大语言模型不进入信号计算，只能用于文字说明，而且说明不得超出信号本身的结论。

## 5. 领域层纯净

- 领域层只做纯计算：不读写文件，不联网，不读系统时钟，用到随机数必须给定种子。
- 遵守数值协议和确定性要求：同一输入必须得到逐字节相同的输出。
- （澄清，2026-10-17）"逐字节相同"指：同一输入、同一环境（同一 Python 版本、平台与依赖锁定）下，业务输出逐字节相同；事先列明的运行元数据（运行编号、时间等）除外，清单写在相应的规格或任务卡中，不得事后补列。

## 6. 治理

- 业务阈值、预算、采购和范围变更都由发起人裁决。
- 研究暂定值要明确标出，不得变成未经批准的默认值。
- 每一项检验先登记口径、后看结果。比较的方案数要登记，不得边看结果边加方案。
- （澄清，2026-10-17）探索集上的规则研究属于探索，可以反复查看结果，但须如实记录尝试过的全部方案数。"先登记、后看结果"约束的是选参集、验证集与封存期的检验。

## 7. 与 market-risk 的关系

1. 不修改 market-risk，也不依赖它的代码。
   - 不导入，也不在运行时调用。
   - 只通过一份有版本的"大盘状态数据"文件交接，内容包括：日期、风险状态（正常／一级／二级）、通道有效性、生效时点、生成版本，以及 market-risk 锁定记录的哈希。
   - 这份文件由 market-risk 已锁定的版本生成，每次交接都要核对哈希。
2. 只用锁定版（K=3、θ_P=2.5%、h=3）。
   - 不得为了 stock-risk 的效果去调整 market-risk 的任何参数。
   - market-risk 需要改动时，走它自己的登记与批准流程。
3. 按 market-risk 的检验进度分段放开：
   - 现在：大盘状态只能用到 2016-12-30。
   - market-risk 验证期正式跑完、结论登记之后：才可以用 2017—2019 年的大盘状态。
   - 2020 年起：仍按第 1 条封存。
   - 在此之前，stock-risk 的个股核心逻辑照常用到 2019 年，只是不带大盘参数。
4. 大盘只作为参数，不替代个股判断。
   - 只能用作事先登记好的条件（例如按大盘状态区分阈值，或把预警归因为"系统性"还是"个股特有"）。
   - 个股预警必须保留不依赖大盘、可以单独成立的证据，不能出现"大盘一转差，所有个股一起报警"。
   - 报告中两类证据要分开写。
5. 必须证明有增量价值：带大盘参数与不带大盘参数两个版本，在同一份登记口径下比较；有增量才并入，没有增量就不加。
6. 缺失时明确降级：大盘数据缺失、过期或哈希不符时，系统明确标为"大盘上下文不可用"，退回只看个股的模式，不得默认按"正常"处理。
7. 结论措辞：
   - market-risk 目前只是锁定，还没有通过验证。
   - stock-risk 在通过登记的增量检验之前，只能把大盘状态称为"未经验证的上下文信号"，不能当作已证实的依据。
   - stock-risk 的结果不得反过来用于调整或评价 market-risk。

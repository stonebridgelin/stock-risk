# 02 数据获取

## 1. 封存纪律（封存方式 A，发起人 2026-10-13 批准）

- 探索期 / 开发期：数据截至 **2019-12-31**（含）。
- 验证期：**2020-01-01 起封存**。探索阶段任何代码都不得下载、读取或展示。
- 实现：`domain/seal.py` 中的常量 `EXPLORATION_END`，三处把关：
  1. 用例拒绝结束日期晚于截止日的请求；
  2. 数据源返回后截断（`truncate_to_exploration`）；
  3. 写盘前检查（`assert_sealed`），仍有越界数据就抛 `SealViolation` 并停止。
- 修改截止日需要发起人批准，并记入变更记录。

## 2. 数据源：Tiingo EOD

- 接口：`GET https://api.tiingo.com/tiingo/daily/<ticker>/prices?startDate=&endDate=&format=json&resampleFreq=daily`，请求头为 `Authorization: Token <key>`。
- 返回字段对应：

| Tiingo | 本项目 | 说明 |
| --- | --- | --- |
| open / high / low / close / volume | open … volume | 不复权（NR） |
| adjOpen / adjHigh / adjLow / adjClose | adj_open … adj_close | 复权（BR），拆股加分红，信号用这一组 |
| divCash | dividend 行动 | 每股现金分红，非 0 时记录 |
| splitFactor | split 行动 | 不等于 1 时记录 |

- 限频：免费档约 50 次/小时，适配器默认两次请求间隔 75 秒；遇到 429 退避重试（600 秒 × 次数），最多 3 次。
- 不存在的代码：返回 404 或"not found"时视为无数据，接着试下一个候选代码。
- 已知局限：数据是一次性取得的最终值，不是严格意义上的 point-in-time；复权价是事后计算的；ADR 比例变化不提供。这些局限要写进评估报告。
- 授权：免费档仅限个人使用，数据不提交到仓库。

## 3. 研究样本

文件 `config/universe_exploration.csv`，共 41 个代码：14 个 ETF（大盘、行业），27 只个股，分布在 low_vol、large_drawdown、high_vol、event、cyclical、delisted、ipo、adr 八类。

- `symbol`：保存用的代码，即当时的代码（例如 FB、VRX）。
- `role`（I15）：`signal_target`（27 只个股，回放、图表、汇总只针对它们）或 `reference_only`（14 个 ETF，只提供背景，不运行生命周期）。只允许这两个值，缺失或其他值读取时报错。
- `source_candidates`：在数据源依次尝试的代码，用 `|` 分隔（例如 `FB|META`）。
- 改名的股票按旧名保存，实际命中的数据源代码记入 README。

### 3.1 多代码分段拼接（T00 / D1）

文件 `config/symbol_segments.csv`：`symbol,source_ticker,from,to,note`。同一 `symbol` 的各行按顺序组成分段，`from` / `to` 为空表示不设该端边界。

- 有分段配置的代码忽略 `source_candidates`，按各段的代码与区间分别下载，拼接后仍保存为 `data/raw/<SYMBOL>.csv`；任何一段失败或无数据，该代码整体失败，不保存部分结果。
- 规则（domain/segments.py）：各段区间不重叠、按日期排序，只有首段可以没有起始日、末段可以没有结束日；拼接结果按日期升序且无重复日期。
- `_fetch_status.json` 的 `segments` 与 `README.txt` 记录各段实际取得的代码、首末日期和行数；`source_ticker` 记为 `VRX+BHC` 这种形式。
- 拼接点检查（后段首开 / 前段末收、复权系数 adj_close / close 的变化）由 `audit-raw` 输出到 `junctions.csv`。
- 现有分段：VRX（VRX 到 2018-07-13，BHC 自 2018-07-16 起）。

### 3.2 上市期间（T00 / D2、D3）

文件 `config/listing_periods.csv`：`symbol,listed_from,listed_until,venue,source_url,verified_on,note`。

- 只登记需要截断的代码；登记了日期就必须有 `source_url`（读取时检查）。找不到可靠来源时日期留空，在 `note` 说明。
- **`listed_until` = 在 NYSE / Nasdaq 的最后一个正常交易日（停牌前一交易日），不用 Form 25 摘牌生效日**（产品经理裁定 PM-01）。理由：产品范围只含交易所上市证券，停牌后的报价来自场外。之后的日线不进入回放，按 I3 处理。
- **`listed_from` 是一个新历史段的起点**（I10）：指标从这一天重新积累，满 W + N 条之前为"不可计算"，不借用之前的价格历史。
- 依据等级写在 `note` 中，例如 SMH 为"公告 + 数据旁证"（PM-02）。
- **原始数据不截断**：`data/raw` 保持数据源原样；上市期间只在审计和回放中使用（domain/listing.py 的 `clip_history_to_listing`）。
- 现有登记：SHLD 到 2018-10-23；WFT 到 2019-05-10；SMH 自 2011-12-21 起；GMCR 见 04 报告。来源与结论见 [04 数据审计报告](04-数据审计报告.md)。
- **配置只保留到 2019 年的事实与依据**（T08a D-02，产品经理裁定）：`config/` 中不写 2020 年及以后的信息。已删去 WFT 备注中的"Form 25-NSE 预定 2020-04-28 摘牌"及其链接、`universe_exploration.csv` 中 TWTR 备注的"2022 退市"。
- **构造时的封存检查**（T08a D-02）：`ListingPeriod` 的 `listed_from` / `listed_until`、`SymbolSegment` 的 `start` / `end`、`PriceCorrection` 的区间、`TradingCalendar` 的交易日，晚于 2019-12-31 即抛 `SealViolation`（`verified_on` 是核对日期，不检查）。

### 3.3 复权价更正（I11，T00a）

文件 `config/price_corrections.csv`：`symbol,from,to,method,ruling,evidence`。

- 数据源复权价有已证实的错误时登记。每条必须有产品经理裁定编号（`ruling`）和数据依据（`evidence`）；`data/raw` 原始文件不改。
- `method` 目前只有 `use_raw`：区间 [from, to] 内每条日线的 adj\_open / adj\_high / adj\_low / adj\_close 用对应的原始价替代。未知方法报错。
- 校验（domain/corrections.py）：`from`、`to` 必须落在该代码的上市期间内；`use_raw` 的区间内有公司行动（拆股、分红）则报错。
- **应用位置**：下游一律通过 `application/market_data_loader.py` 的 `MarketDataLoader` 读取原始数据，它在读取时统一应用更正（组装入口 `bootstrap.build_market_data_loader`）。不要绕过它直接读 `RawDataReader`。
- 现有登记：SHLD 2018-03-28 至 2018-10-23，`use_raw`，PM-03（数据源复权错误）。

## 4. 原始数据格式（`data/raw/`）

| 文件 | 内容 |
| --- | --- |
| `<SYMBOL>.csv` | `date,open,high,low,close,volume,adj_open,adj_high,adj_low,adj_close`，UTF-8，日期升序，无重复 |
| `<SYMBOL>.actions.csv` | `date,type,value`，type 取 dividend / split / adr_ratio |
| `corporate_actions.csv` | 所有代码的公司行动合并，多一列 `symbol` |
| `_fetch_status.json` | 每个代码的下载状态，断点续传依据 |
| `README.txt` | 来源、时间、口径、成功和缺失清单、质量提示数 |
| `MANIFEST.sha256` | 各日线文件的 SHA-256；清单文件本身的哈希作为审计报告中的数据版本 |

质量检查只报告不修改：非正价格、高低点与开收盘不一致。异常价格可能正是要测试的场景，原样保留。

## 5. 运行

```
uv run stock-risk fetch-raw              断点续传，跳过已完成的代码
uv run stock-risk fetch-raw --force      全部重新下载
uv run stock-risk fetch-raw --force --symbols VRX   只重新下载指定代码（逗号分隔，须在研究样本中）
uv run stock-risk audit-raw              审计 data/raw，输出到 output/audit/<运行日期>/
```

`TIINGO_API_KEY` 从项目根目录的 `.env` 读取，环境变量优先。

## 6. 审计（`audit-raw`）

只报告，不修改数据。检查规则在 `domain/audit.py`：

| 检查 | 规则 |
| --- | --- |
| 明确失败（v0.4 §2.0） | 非有限值；高 < 低；收盘不在 [低, 高]；价格 ≤ 0。原始价与复权价分别检查，成交量只查非有限值 |
| 复权系数跳变 | adj_close / close 相对前一根日线变化超过 2%（任务卡 T00 给定），且当天没有公司行动 |
| 交易日缺口 | 以 SPY 交易日为日历（I1）。区间默认取首条至末条日线；登记了上市期间的一端以上市期间为界（I2） |
| 零成交量 | 成交量为 0 的日期 |
| 拼接点 | 见 3.1 |
| 封存 | 晚于 2019-12-31 的行数（应为 0）；读取器只计数，不解析这些行 |
| MANIFEST 校验 | 按 `MANIFEST.sha256` 逐个比较日线文件的 SHA-256；列出哈希不一致、清单有但文件缺失、文件有但不在清单中的情况（T00a） |
| 已登记的更正 | 以上检查都针对**未更正**的原始数据；另列出已登记的更正，并对更正后的数据重新做复权系数跳变检查（T00a） |

**退出码**（T08a D-02）：发现明确失败、封存越界、MANIFEST 哈希不符、清单中有而文件缺失，或研究样本中有而 `data/raw` 中没有的代码时，打印"未通过：…"并返回 1；否则返回 0。`MANIFEST.sha256` 缺失或为空、被审计证券的 CSV 不在清单中，同样返回 1（Gemini 第二阶段 B-02）；不属于被审计证券的文件不在清单中只报告，不影响退出码。

输出：`symbols.csv`（各代码概览）、`explicit_failures.csv`、`adj_factor_jumps.csv`、`calendar_gaps.csv`、`zero_volume.csv`、`junctions.csv`、`price_corrections.csv`、`corrected_adj_factor_jumps.csv`、`manifest_check.csv`、`summary.md`。同一天重复运行会覆盖当天目录。明细带 `in_listing` 列，标明该行是否在上市期间内。

## 7. 统一取数入口（I12，T01）

下游（回放、图表、汇总、以后的评价）一律经 `application/market_data_loader.py` 的 `MarketDataLoader.load` 取数（组装入口 `bootstrap.build_market_data_loader`），不得自行读取 `data/raw`。处理顺序固定：

1. **封存检查**：日线文件与公司行动文件中任何日期晚于 2019-12-31 的行 → 立即抛 `SealViolation`。这一步只看日期，不解析该行价格，也不先过滤后继续。
2. **解析与量化**（I9）：价格字段从 CSV 文本直接按 `Decimal` 解析，`ROUND_HALF_EVEN` 量化到 6 位小数，再转为 float，不经过 float 再转换。**量化后** ≤ 0 或非有限值 → `InvalidInputError`；例如 "0.0000004" 量化为 0，判为非法。同时执行 v0.4 第 2.0 节的明确失败检查（高 < 低、收盘不在 [低, 高]），原始价与复权价分别检查。成交量与公司行动数值只要求有限，不量化。
3. **复权更正**（I11，第 3.3 节）。`use_raw` 用的是已量化的原始价，所以更正后的复权价同样是量化值。
4. **按观察区间截取**（第 8 节）。
5. **第二次封存检查**。

审计（`audit-raw`）走另一条路径 `audit_view`：越界行只计数、不报错，数值不量化。两条路径分开。

## 8. 三个区间、端点类型与缺价（I2、I3、I10）

| 区间 | 定义 |
| --- | --- |
| 数据覆盖区间 | 文件首日至末日 |
| 观察区间 | 起点 = max(登记的 `listed_from`, 数据首日)；终点 = min(2019-12-31, 登记的 `listed_until`)，**不取文件末日** |
| 回放区间 | 起点 = max(2009-01-01, 观察起点)；终点 = 观察终点 |

各起点落在非交易日时取其后第一个交易日（例如 2009-01-01 → 2009-01-02），终点取其前最后一个交易日。

| 端点类型 | 含义 |
| --- | --- |
| `listing_start` | 登记了 `listed_from`，且它就是观察起点的来源（`listed_from` ≥ 数据首日） |
| `request_start` | 数据首日等于下载请求起点（2008-01-01）后的首个交易日 2008-01-02 |
| `first_available` | 其余情况，标"左端覆盖未核实" |
| `LISTING_END` | 终点由 `listed_until` 决定（`listed_until` 早于 2019-12-31） |
| `EXPLORATION_END` | 终点由 2019-12-31 决定 |

逐日序列：观察区间内按交易日历逐日给出"有日线 / 缺价"。观察起点不早于数据首日，所以首条日线之前的日子不算缺价；**观察终点之前文件提前结束的，其后各交易日都是缺价**，不截掉。观察区间内出现日历以外日期的日线 → `InvalidInputError`。`listed_from` 是新历史段的起点（I10）：截取后不带入此前的价格。按连续缺价天数（G）切分历史段属于生命周期（T02）。

命令 `uv run stock-risk show-ranges` 输出到 `output/ranges/<日期>/`：`ranges.csv`（三个区间、端点类型、观察区间内日线数与缺价日数）、`missing_days.csv`、`summary.md`。

## 10. 数值规范与指标口径（I9、I18；v0.4 第 2.0–2.3 节）

- **ε 比较**（`domain/numeric.py`）：`x ≥ k` 判为 x ≥ k − ε；`x > k` 判为 x > k + ε；`x ≤ k` 判为 x ≤ k + ε；`x < k` 判为 x < k − ε。比率类 ε\_r = 1e-10，价格类 ε\_p = 1e-9。
- **复算判据**：|a − b| ≤ abs\_tol + 1e-9 × max(|a|, |b|)，比率类 abs\_tol = 1e-12，价格类 1e-9。
- 以上容差集中在 `Tolerances` 中定义，属于"数值容差，待登记"（I6 (b)）。
- 求和一律用 `math.fsum`，按交易日升序传入。
- **指标的计数口径（I18，产品经理签发 T01 时补充，下一轮审阅时复核）**：TR 中的 C\_{t−1} 取**同一历史段内上一条有效日线**的收盘；ATR、SMA、窗口一律按"有效日线"计数，缺价日不占位。R2 例外：按 v0.4 R2-06，prev 必须是交易日历上 T 的前一个交易日，且该日有日线，否则 `MISSING_DATA`；prev 的 ATR 不可计算时为 `INSUFFICIENT_HISTORY`。
- 全部指标使用复权价（I4）。并列规则：窗口最高收盘并列取最近，区间最低收盘并列取最早，并列按量化后的数值精确比较。
- 历史长度：当前历史段有效日线不足 W + N 条 → 不可计算（N = 20 时第 82 条不可计算、第 83 条可计算）。

### 11.1 代码清单探查：`probe-tickers`

```
uv run stock-risk probe-tickers [--check names.csv] [--out data/universe_probe]
```

- 来源：Tiingo 公开的代码清单 `supported_tickers.zip`（字段 ticker、exchange、assetType、priceCurrency、startDate、endDate）。只发**一个请求**，不带密钥，**不下载任何价格**（`infrastructure/tiingo/ticker_list.py`）。
- **封存处理**在内存中逐行完成，压缩包不写盘（`domain/universe_probe.py`）：
  - startDate 晚于 2019-12-31 的行丢弃，不计数、不输出；
  - endDate 晚于 2019-12-31 或为空的行，endDate 写为 2019-12-31，另记 `active_after_2019 = true`，不保留真实结束日期；
  - endDate 早于 2008-01-02 的行丢弃（只计数）；startDate 为空的行丢弃（只计数）。
  - 字段不符或日期无法解析时报 `ProbeFormatError` 并停止。
- **筛选**：exchange 为 NYSE 或 NASDAQ、assetType 为 Stock、priceCurrency 为 USD。其他交易所取值只计数（`summary.json` 的 `stock_usd_other_exchanges`），是否纳入由产品经理裁定。
- **输出**（`data/` 不入库）：
  - `tickers_2008_2019.csv`：`ticker,exchange,start_date,end_date,active_after_2019`；
  - `summary.json`：总数与代码数；按交易所、按开始年份的计数；`ended_by_2019` / `active_after_2019`；代码复用（同一 ticker 多行）的个数与示例；封存处理后全部行的交易所与资产类型取值；丢弃计数。
  - 给了 `--check`（CSV，一列 `ticker`，可附 `from,to`；`to` 不得晚于 2019-12-31）时另写 `coverage_check.csv`：是否在筛选后的清单中、清单区间是否覆盖所需区间、在筛选范围外的登记。

### 11.2 批量下载：`fetch-batch`

```
uv run stock-risk fetch-batch --list list.csv [--out data/raw_selection]
      [--per-hour 50] [--per-day 1000] [--unique-per-month 500] [--max-symbols N]
```

- **清单**：CSV `symbol,source_ticker,from,to`（ISO 日期）。`to` 晚于 2019-12-31 时拒绝执行；`symbol` 不得重复。
- **复用**：与 `fetch-raw` 同一个 Tiingo 适配器、同样的封存三道关（第 1 节）、断点续传与 MANIFEST；默认输出到 `data/raw_selection/`，与探索集的 `data/raw/` 分开，文件格式同第 4 节。每个代码一次请求取全区间。
- **额度保护**（命令行 > `.env` / 环境变量 `TIINGO_PER_HOUR`、`TIINGO_PER_DAY`、`TIINGO_UNIQUE_PER_MONTH` > 默认免费档）：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--per-hour` | 50 | 换算为请求间隔（3600 / 上限 秒） |
| `--per-day` | 1000 | 每日请求数（含重试）达到即正常退出 |
| `--unique-per-month` | 500 | 本月请求过的不同代码数达到即正常退出 |
| `--max-symbols` | 不限 | 本次最多处理的代码数 |

- 额度计数在 `<out>/_quota_state.json`，按 UTC 日期、月份记账，每个代码完成后保存。只有确实发出了请求，才把该代码计入当月新代码（Gemini 第二阶段 B-04：在限频等待中中断不消耗额度）。
- 遇 429 按适配器原有方式退避（600 秒 × 次数）；**连续 3 次 429** 抛 `RateLimitError`，保存进度后退出，退出码 1，提示"额度已用尽，稍后再运行"；该代码不记为失败，下次重试。
- **可随时中断**（Ctrl+C，退出码 130）：已完成的代码已落盘、额度已记账；再次运行跳过已完成的代码（成功或无数据），失败的代码重试。
- `_fetch_status.json` 每个代码一条：成功（`ok: true`）、无数据（`state: "no_data"`，404 / not found）、失败（`ok: false` 与 `error`）。跳过的代码在本次输出中计数。
- 运行结束打印：本次完成数、累计完成数、剩余数、今日与本月已用额度、预计还需运行的次数。不打印密钥；密钥只取 `.env` 中的 `TIINGO_API_KEY`（`Secret` 类型），不支持多密钥。
- 审计：`uv run stock-risk audit-raw --dir data/raw_selection --list list.csv`，规则同第 6 节；被审计的代码取自下载清单，日历代理仍用 `data/raw/SPY.csv`，上市期间沿用配置，不应用探索集的更正与分段；输出到 `output/audit/raw_selection/<日期>/`。`_fetch_status.json` 中已确认无数据（`state: "no_data"`）而没有文件的代码单列为"下载状态已确认无数据"，不算缺少原始文件（B-04）；其余没有文件的代码仍算缺失并返回 1。

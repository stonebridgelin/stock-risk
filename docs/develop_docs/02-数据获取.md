# 02 数据获取

## 1. 封存纪律（封存方式 A，发起人 2026-10-13 批准）

- 探索期 / 开发期：数据截至 **2019-12-31**（含）。
- 验证期：**2020-01-01 起封存**。探索阶段任何代码都不得下载、读取或展示。
- 实现：`domain/seal.py` 中的常量 `EXPLORATION_END`，三处把关：
  1. 用例拒绝结束日期晚于截止日的请求；
  2. 数据源返回后截断（`truncate_to_exploration`）；
  3. 写盘前检查（`assert_sealed`），仍有越界数据就抛 `SealViolation` 并停止。
- 修改截止日需要发起人批准，并记入变更记录。

## 2. 数据源：Tiingo EOD

- 接口：`GET https://api.tiingo.com/tiingo/daily/<ticker>/prices?startDate=&endDate=&format=json&resampleFreq=daily`，请求头为 `Authorization: Token <key>`。
- 返回字段对应：

| Tiingo | 本项目 | 说明 |
| --- | --- | --- |
| open / high / low / close / volume | open … volume | 不复权（NR） |
| adjOpen / adjHigh / adjLow / adjClose | adj_open … adj_close | 复权（BR），拆股加分红，信号用这一组 |
| divCash | dividend 行动 | 每股现金分红，非 0 时记录 |
| splitFactor | split 行动 | 不等于 1 时记录 |

- 限频：免费档约 50 次/小时，适配器默认两次请求间隔 75 秒；遇到 429 退避重试（600 秒 × 次数），最多 3 次。
- 不存在的代码：返回 404 或"not found"时视为无数据，接着试下一个候选代码。
- 已知局限：数据是一次性取得的最终值，不是严格意义上的 point-in-time；复权价是事后计算的；ADR 比例变化不提供。这些局限要写进评估报告。
- 授权：免费档仅限个人使用，数据不提交到仓库。

## 3. 研究样本

文件 `config/universe_exploration.csv`，共 41 个代码：14 个 ETF（大盘、行业），27 只个股，分布在 low_vol、large_drawdown、high_vol、event、cyclical、delisted、ipo、adr 八类。

- `symbol`：保存用的代码，即当时的代码（例如 FB、VRX）。
- `source_candidates`：在数据源依次尝试的代码，用 `|` 分隔（例如 `FB|META`）。
- 改名的股票按旧名保存，实际命中的数据源代码记入 README。

### 3.1 多代码分段拼接（T00 / D1）

文件 `config/symbol_segments.csv`：`symbol,source_ticker,from,to,note`。同一 `symbol` 的各行按顺序组成分段，`from` / `to` 为空表示不设该端边界。

- 有分段配置的代码忽略 `source_candidates`，按各段的代码与区间分别下载，拼接后仍保存为 `data/raw/<SYMBOL>.csv`；任何一段失败或无数据，该代码整体失败，不保存部分结果。
- 规则（domain/segments.py）：各段区间不重叠、按日期排序，只有首段可以没有起始日、末段可以没有结束日；拼接结果按日期升序且无重复日期。
- `_fetch_status.json` 的 `segments` 与 `README.txt` 记录各段实际取得的代码、首末日期和行数；`source_ticker` 记为 `VRX+BHC` 这种形式。
- 拼接点检查（后段首开 / 前段末收、复权系数 adj_close / close 的变化）由 `audit-raw` 输出到 `junctions.csv`。
- 现有分段：VRX（VRX 到 2018-07-13，BHC 自 2018-07-16 起）。

### 3.2 上市期间（T00 / D2、D3）

文件 `config/listing_periods.csv`：`symbol,listed_from,listed_until,venue,source_url,verified_on,note`。

- 只登记需要截断的代码；登记了日期就必须有 `source_url`（读取时检查）。找不到可靠来源时日期留空，在 `note` 说明。
- `listed_until` 为在交易所的最后交易日（停牌前一交易日），不是 Form 25 摘牌生效日（探索期口径，待产品经理确认）。
- **原始数据不截断**：`data/raw` 保持数据源原样；上市期间只在审计和回放中使用（domain/listing.py 的 `clip_history_to_listing`）。
- 现有登记：SHLD 到 2018-10-23；WFT 到 2019-05-10；SMH 自 2011-12-21 起。来源与结论见 [04 数据审计报告](04-数据审计报告.md)。

## 4. 原始数据格式（`data/raw/`）

| 文件 | 内容 |
| --- | --- |
| `<SYMBOL>.csv` | `date,open,high,low,close,volume,adj_open,adj_high,adj_low,adj_close`，UTF-8，日期升序，无重复 |
| `<SYMBOL>.actions.csv` | `date,type,value`，type 取 dividend / split / adr_ratio |
| `corporate_actions.csv` | 所有代码的公司行动合并，多一列 `symbol` |
| `_fetch_status.json` | 每个代码的下载状态，断点续传依据 |
| `README.txt` | 来源、时间、口径、成功和缺失清单、质量提示数 |
| `MANIFEST.sha256` | 各日线文件的 SHA-256；清单文件本身的哈希作为审计报告中的数据版本 |

质量检查只报告不修改：非正价格、高低点与开收盘不一致。异常价格可能正是要测试的场景，原样保留。

## 5. 运行

```
uv run stock-risk fetch-raw              断点续传，跳过已完成的代码
uv run stock-risk fetch-raw --force      全部重新下载
uv run stock-risk fetch-raw --force --symbols VRX   只重新下载指定代码（逗号分隔，须在研究样本中）
uv run stock-risk audit-raw              审计 data/raw，输出到 output/audit/<运行日期>/
```

## 6. 审计（`audit-raw`）

只报告，不修改数据。检查规则在 `domain/audit.py`：

| 检查 | 规则 |
| --- | --- |
| 明确失败（v0.4 §2.0） | 非有限值；高 < 低；收盘不在 [低, 高]；价格 ≤ 0。原始价与复权价分别检查，成交量只查非有限值 |
| 复权系数跳变 | adj_close / close 相对前一根日线变化超过 2%（任务卡 T00 给定），且当天没有公司行动 |
| 交易日缺口 | 以 SPY 交易日为日历（I1）。区间默认取首条至末条日线；登记了上市期间的一端以上市期间为界（I2） |
| 零成交量 | 成交量为 0 的日期 |
| 拼接点 | 见 3.1 |
| 封存 | 晚于 2019-12-31 的行数（应为 0）；读取器只计数，不解析这些行 |

输出：`symbols.csv`（各代码概览）、`explicit_failures.csv`、`adj_factor_jumps.csv`、`calendar_gaps.csv`、`zero_volume.csv`、`junctions.csv`、`summary.md`。同一天重复运行覆盖当天目录。明细带 `in_listing` 列，标明该行是否在上市期间内。

`TIINGO_API_KEY` 从项目根目录的 `.env` 读取，环境变量优先。

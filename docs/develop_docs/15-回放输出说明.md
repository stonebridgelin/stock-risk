# 15 回放输出说明

编写：Claude Code（任务卡 T04）· 2026-10-14 · 依据：03 计划第 3 节 I2、I3、I7、I8、I11、I12、I15–I17，第 4 节 T04a–c；[14 生命周期引擎实现说明](14-生命周期引擎实现说明.md)。

本目录下的输出只陈述回放结果，不含评价、门槛、排名或结论（结论由产品经理在 05 号文档中写）。

## 1. 命令

```
uv run stock-risk replay --candidates reference12 [--symbols AAPL,SHLD]   12 组参考候选，四种输出 + 汇总
uv run stock-risk replay --candidates all [--symbols ...] [--workers 7]    768 组全量，只输出汇总（多进程）
```

- 只回放研究样本中 `role = signal_target` 的 27 只个股（I15）。登记了复权价更正的代码（SHLD）同时回放更正口径与原口径，对象名分别为 `SHLD_corrected`、`SHLD_uncorrected`（I11）。
- 取数一律经 `MarketDataLoader`（I12）。引擎从回放起点开始运行，2008 年只作指标预热；到观察终点时截尾（I3）。
- 退出码：不变量违反、候选失败、一致性问题或 I17 ② 不通过时为 1。
- 正式运行必须在干净工作区进行（I16、P-26）。git 可执行文件取环境变量 `GIT_EXECUTABLE`，没有设置时在 PATH 中查找；找不到 git 或工作区不干净时，运行标为 `debug`，不得在 05 号文档中引用。

## 2. 目录结构

```
output/replay/<run_id>/
├── run_manifest.json          运行清单（第 6 节）
├── index.html                 个股 × 候选的图表链接与预警次数（reference12）
├── summary.csv                每行一个（候选, 对象）（第 5 节）
├── summary_by_candidate.csv   按候选汇总（SHLD 只计更正口径）
├── plotly.min.js              图表共用的 plotly 脚本（reference12）
└── c<候选编号>/<对象>/         （reference12）
    ├── events.csv
    ├── daily.csv
    ├── episodes.csv
    └── chart.html
```

- `run_id` = `开始时间（本地，YYYYMMDDTHHMMSS）-提交号前 7 位`；同名目录已存在时加 `-2`、`-3`……，不覆盖。
- 候选编号为 10 号第 4.1 节的网格编号（1–768）。12 组参考候选（I7）为 385–396：N = 20、k₁ = 2、k₂ = 4、K = 3、d = 3、u\_rel = 3 × {SMA, BOX, BOX\_ROLL} × {TWO\_STAGE, DIRECT} × {PEAK, MIN}，其中 385 = SMA / TWO\_STAGE / PEAK。
- 每个 CSV 都带 `run_id`、`candidate_id`、`target` 列；图表标题带 run\_id 与候选定义。

## 3. 各文件字段

价格一律为复权价（I4；SHLD 更正口径中 2018-03-28 至 2018-10-23 为原始价，见 I11），单位为美元；D\_T、D\_ep、U、回吐比率以 ATR 为单位；日期为 ISO 格式；集合与列表写成 JSON。

### 3.1 events.csv（每个事件一行）

| 列 | 含义 |
| --- | --- |
| date | 信号日 |
| event\_type | START、ESCALATE、DOWNGRADE、RELEASE、DATA\_BREAK、DATA\_ISSUE、STABILIZED、RECOVERY\_OBS、RECOVERY\_REVOKED、RECOVERY\_FAIL |
| identity | 业务身份（14 号第 5 节） |
| episode\_id | 所属预警（DATA\_ISSUE 为空） |
| level\_before / level\_after | 前一交易日日末等级 / 当日日末等级（WATCH = 关注，ALERT = 警戒，空 = 无预警） |
| transition | 转移编号 T1–T16（恢复进度事件除 DATA\_GAP 撤销外为空） |
| reasons | 原因：START 的 R1\_GE\_K2 / R1\_GE\_K1 / GAP；ESCALATE 的 D\_EP\_GE\_K2 / NEW\_LOW / GIVEBACK；DOWNGRADE、RELEASE 的证据代码与 DIRECT\_STRONG\_RECOVERY；撤销的 BELOW\_SMA / BACK\_INTO\_BOX / BELOW\_ROLLING\_HIGH / ESCALATED / DATA\_GAP；恢复失败的 NEW\_LOW |
| evidence | 当日证据集合（警戒 E\_down：a、b、c；关注 E\_rel：a′、b′） |
| segment | DOWNGRADE、RELEASE：计数段内每日的证据集合 |
| values | 其余依据（D\_T、A\_start、P\_ep、候选计数、收盘、确认线等） |

### 3.2 daily.csv（每个交易日一行）

直接写出引擎的诊断记录（14 号第 6 节），另加 `close`（当日复权收盘，缺价日为空）。主要字段：`data_status`（HAS\_BAR / MISSING / DATA\_BREAK / INSUFFICIENT）与 `m`；`display`、`level`、`episode_id`；`p_ep`、`p_ep_day`、`atr_ep`、`l_ep`、`l_ep_day`；`d_t`、`a_start`（无预警时）、`d_ep`（有预警时）；`r2_status`、`r2_score`；`cycle_no`、`obs_start`、`since_obs`；`confirm_method`、`confirm_line`、`confirmed`；`u`、`strong_threshold`、`strong`；`evidence`；`dc_cand / rc_cand / xc_cand`（今日候选）与 `dc / rc / xc`（日末）；`h_d`、`giveback`；`reset_reasons`（NEW\_LOW / ESCALATE / DATA\_GAP）；`transition`；`end_reason`。`in_replay` 为假的行是回放起点之前的预热期。

### 3.3 episodes.csv（每次预警一行）

| 列 | 含义 |
| --- | --- |
| start\_date / start\_close / start\_reasons / initial\_level | 启动 |
| low\_date / low\_close | 本次预警的最低收盘（L\_ep 的最终值） |
| first\_stabilized\_\*、first\_obs\_\*、downgrade\_\* | 首次企稳、首次恢复观察、（首次）降级的日期与收盘 |
| end\_date / end\_close / end\_reason | 解除（RELEASE）、数据中断（DATA\_BREAK）或截尾（LISTING\_END、EXPLORATION\_END）。截尾日为观察终点，当日缺价时收盘为空 |
| n\_recovery\_obs / n\_revoked / n\_recovery\_fail / n\_escalate | 次数 |
| duration\_trading\_days | 自启动日到终止日（含两端）的交易日数 |
| observed\_valid\_days | 其中有日线的交易日数 |

### 3.4 chart.html

- 主图：复权收盘；状态色带（黄 = 关注，红 = 警戒，深灰 = 数据中断，浅灰 = 不可计算）；事件标记（悬停显示事件、转移编号与依据）；L\_ep、确认线、强恢复门槛线；更正区间（顶部蓝条与标注）；缺价日（竖虚线）。
- 副图：D\_T（无预警时）与 D\_ep（有预警时）；SPY、QQQ 的 63 日回撤（右轴，%，自取数入口读取）。图下方注明"大盘背景只作参照，未应用背景标签（I8）"。
- 查看方法：直接用浏览器打开 `index.html` 或任一 `chart.html`。图表通过相对路径 `../../plotly.min.js` 引用 run 目录根下的同一个本地 plotly 脚本，离线可看，不依赖网络。

## 4. 一致性与检查

reference12 运行中，每个（候选, 对象）写出后立即读回四种输出，由程序检查（`replay_outputs.check_consistency`）：

- 图表中读回的事件标记（日期, 类型）与 events.csv 完全相同；
- 每个事件在 daily.csv 当日有对应记录：START 对应 T6 / T7，ESCALATE 对应 T9–T11，DOWNGRADE 对应 T15，RELEASE、DATA\_BREAK 对应 `end_reason`，DATA\_ISSUE 对应缺价或数据中断；episode\_id 一致；反过来，daily 中的启动转移都有 START；
- episodes.csv 的启动日、降级日、终止日与 events.csv 一致，截尾日与 daily.csv 的 `end_reason` 一致。

另外，每次回放都运行不变量检查器（14 号第 7 节）。检查结果写入运行清单。

## 5. summary.csv 的统计口径（03 计划 T04c，P-16、P-25）

| 列 | 口径 |
| --- | --- |
| 时间范围 | 2010-01-01 至 2019-12-31；2009 年只作预热 |
| episodes\_dev | 开发期预警数：启动日 ≥ 2010-01-01 |
| release\_n、release\_duration\_\* | 开发期中以 RELEASE 结束的预警数与持续交易日数的个数、均值、p25、p50、p75、p90、最小、最大（分位数为线性插值，`statistics.quantiles(method="inclusive")`） |
| data\_break\_n、data\_break\_observed\_days | 以 DATA\_BREAK 结束的个数与已观察的有效交易日数（合计） |
| censored\_listing\_end\_n、censored\_exploration\_end\_n、censored\_observed\_days | 截尾的个数与已观察的有效交易日数（合计） |
| warmup\_started\_n、warmup\_started\_durations | 2009 年启动、延续到 2010 年的预警个数与各自的持续交易日数（分号分隔；未以 RELEASE 结束的加"+"）。不混入开发期的持续时间统计；2009 年内启动并结束的不计入 |
| computable\_days | 可计算日：2010-01-01 起有日线且历史段充足的交易日 |
| warning\_days、occupancy | 可计算日中处于关注或警戒的日数；占用率 = warning\_days ÷ computable\_days（≤ 100%）。解除日按日末状态计为无预警 |
| missing\_days、missing\_days\_frozen\_warning | 缺价日（不进分子也不进分母），其中等级冻结为关注 / 警戒的日数 |
| data\_break\_days、insufficient\_days | 数据中断日数、不可计算日数 |
| n\_start … n\_data\_issue | 2010-01-01 起各类事件的次数（按事件日期） |
| restart\_gap\_\* | 解除后再次启动的间隔（交易日）：解除日在汇总期内、其后有下一次启动的 |

`summary_by_candidate.csv`：按候选把各对象的计数相加（SHLD 只计更正口径），占用率为合并后的分子 ÷ 分母，持续时间与再次启动间隔为合并后的分布。

## 7. 性能与缓存

- 768 组按回放对象拆分到多个进程，每个进程用同一组历史段指标运行全部候选。
- 指标缓存：`ComputedIndicators` 记住 ATR、SMA 的结果（同一公式、同一输入）。缓存与不缓存结果相同，由 I17 ② 检查与单元测试保证。

## 1. 配置：付费档的主机

- **新增设置** `MASSIVE_ADVANCED_BASE_URL`，只对付费档命令生效。
  - 允许的取值**只有两个**：`https://relaynex.vip` 与 `https://api.massive.com`。
  - 未设置或为空白时，取 `https://api.massive.com`。
  - 其他任何值，在命令入口报错停止。
- **发起人在 `.env` 中加一行** `MASSIVE_ADVANCED_BASE_URL=https://relaynex.vip`。执行者不改 `.env`；如果这一项不存在，停止并请发起人添加。
- **免费档命令**（T08d-2a）不变：仍然只连 `api.massive.com`，仍然只用 `MASSIVE_API_KEY`。
- **密钥不交叉**：
  - `MASSIVE_ADVANCED_API_KEY` 只发往上面配置的那一个主机；
  - `MASSIVE_API_KEY` 只发往 `api.massive.com`；
  - 一次运行中不得出现两个主机。
- **认证**：仍用请求头 `Authorization: Bearer <key>`，密钥不进 URL。
- **翻页地址**（`next_url`）：只接受与配置主机相同的 https 地址，并去掉其中的 apiKey 参数。主机不同的，停止。
- **来源记录**：
  - 付费档每个输出文件和 `_progress.json` 都要记录 `source_host`；
  - 同一输出目录中已有其他主机的记录时，拒绝运行，不混写。
- **测试**（假传输层，不访问网络）：
  - 默认取官方主机；
  - 两个允许值各一条；
  - 非法值报错；
  - 翻页地址主机不同时停止；
  - 免费档命令不受影响；
  - 两把密钥各自只发往自己的主机；
  - 已有其他主机记录的目录拒绝运行。

## 2. 接口覆盖试探（真实运行，约 10 次请求）

先各发一次最小请求，记录状态码、返回字段名与条数，**不记录密钥**。

| 接口 | 请求 |
| --- | --- |
| 日线 | MSFT，2019-01-02 至 2019-01-31，`adjusted=false` 与 `adjusted=true` 各一次 |
| 拆股 | AAPL，执行日不晚于 2019-12-31 |
| 分红 | KO，除息日不晚于 2019-12-31 |
| 证券清单 | 2019-06-03，`market=stocks`，`active=true`，只取第一页 |
| 证券清单（已退市） | 2019-06-03，`active=false`，只取第一页 |
| 证券详情 | MSFT，`date=2019-06-03` |

处理规则：
- 返回 401 或 403 的，停止全部运行并报告原文，不换密钥重试。
- 返回 404 或"不支持"的，记为该接口**不可用**，第 3 节与 T08d-2b 中依赖它的部分跳过，并在回执中列出。
- 封存规则同 T08d-2b：请求的 `to` 不得晚于 2019-12-31；响应中晚于截止日的行在内存中丢弃并计数。

## 3. 数据核验（核验通过前不入库）

### 3.1 价格：与 Tiingo 逐日对账

- **对象**：`data/raw/` 中 27 只探索股（SHLD 取已登记的那一份），2010-01-01 至 2019-12-31。
- **请求**：中转服务的未复权日线（`adjusted=false`）。
- **每只股票报告**：
  - 两边日期集合的差异，列出只在一边出现的日期；
  - 共同日中，未复权收盘价之差的绝对值：最大值、超过 0.01 的天数及占比、前 5 个最大的日期；
  - 差值的中位数（检查有没有系统性偏移）；
  - 成交量相对差的中位数与 95% 分位（只报告，不作为判定标准；不同数据源的成交量口径本来就可能不同）。
- **输出**：`data/massive_probe/paid/verify/prices_<代码>.csv` 与汇总表 `verify_prices_summary.csv`。

### 3.2 参考数据：与官方免费档的历史快照比对

- T08d-2a 已用官方免费档在 `data/massive_probe/` 下保存了证券清单快照，**不再调用官方接口**。
- 取同样的日期与参数，从中转服务取一份，逐条比对白名单字段：ticker、primary\_exchange、type、active、cik、composite\_figi、list\_date、delisted\_utc。
- **报告**：
  - 两边的条数；
  - 只在一边出现的代码数，各列 20 个例子；
  - 字段取值不同的条数，按字段分列，各列 10 个例子。

## 4. 判定标准（产品经理预先登记，执行者不判定）

全部满足，才判定"数据没有问题"：

1. **价格**：27 只股票中每一只，共同日的未复权收盘价之差的绝对值超过 0.01 的天数不超过 0.5%，并且差值的中位数为 0。
2. **日期**：每只股票只在一边出现的日期合计不超过 3 天，并且每一天都有可以解释的原因（例如节假日、停牌、上市首日）。
3. **参考数据**：每个快照日期，只在一边出现的代码数不超过 0.5%；白名单字段取值不同的条数不超过 0.5%。
4. **覆盖**：第 2 节中，日线、拆股、分红、证券清单（含已退市）四类接口都可用。
5. **封存**：输出中没有 2020-01-01 及以后的日期。用 grep 核对。

任何一条不满足，产品经理写明理由，提交发起人决定改用选项 A（Massive 官方 Stocks Advanced），或者接受该偏差。**执行者不得调整标准，也不得为了满足标准而筛选数据。**

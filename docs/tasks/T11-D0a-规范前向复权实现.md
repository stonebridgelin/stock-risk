## 2. `adj_volume` 的完整读写链（规格第 4 节；D0R-02）

### 2.1 字段

- `DailyBar` 末尾增加 `adj_volume: float | None = None`；
- `RawBarText` 末尾增加 `adj_volume: str | None = None`。

现有按位置构造的代码不必改动。

### 2.2 读法（每个入口都要按这张表实现，并分别测试）

| 输入 | `load_text` 得到的文本 | 解析后 `DailyBar.adj_volume` |
| --- | --- | --- |
| 文件没有 `adj_volume` 列（旧文件） | None | None（未知） |
| 有列，单元格为空 | None | None（未知） |
| `0` 或 `0.0` | 原文 | 0.0（真实的零） |
| 正数，如 `1100` | 原文 | 1100.0 |
| 负数、`nan`、`inf`、无法解析 | 原文 | **报 `InvalidInputError`**，不当作缺失 |

入口有三个，都要实现：
- `raw_text.parse_bar`：用 `parse_finite`，并另外检查非负；
- `csv_raw_reader.load`：审计用，现在直接 `float()`。它也要按上表处理：None 保持 None，非法值报错；
- `csv_raw_reader.load_text`：只取文本，缺列时为 None。

### 2.3 写法

- `csv_raw_repository.BAR_COLUMNS` 末尾加 `adj_volume`。
- None 写为空单元格，0.0 写为 `0`（与现有数值写法一致）。
- 往返测试：None、0、正数三种值写出再读入，保持区别。
- Tiingo 的 `mapper` 构造的 `DailyBar` 不给 `adj_volume`（保持 None）：供应商没有提供调整量，不得用 `volume` 填充。

### 2.4 使用约束

- 原始成交额门槛仍只读 `volume`。
- 任何模块遇到 `adj_volume` 为 None，记未知，**不得回退到 `volume`**。本卡没有读取 `adj_volume` 的业务模块；写一个测试，扫描 `src/` 中所有读取 `adj_volume` 的地方，断言没有 `or volume` 或类似的回退写法。如果这个扫描不可靠，改为在回执中逐处列出读取点。

## 3. 行动输入：从文本到十进制（规格第 8 节）

### 3.1 领域类型（`domain/adjustment/inputs.py`）

- `SplitInput`：
  - `ex_date`（即 Massive 的 `execution_date`）；
  - `split_from`、`split_to`（Decimal）；
  - `declaration_date`（恒为 None：数据中没有）；
  - `source`（来源标识，如 `massive:actions/<T>_splits.csv`）。
  - `row`（数据行号，表头之后从 1 起）、`source_sha256`（来源文件内容的哈希）。
- `DividendInput`：
  - `ex_date`、`cash_amount`（Decimal）、`dividend_type`；
  - `declaration_date`，以及 `declaration_masked`（布尔，见 3.3）；
  - `currency`（None 表示数据中没有币种字段）；
  - `share_unit`：来源有单位列时取原文；现有来源没有，固定为 `PER_SHARE`（G-T11-02）；
  - `source`、`row`、`source_sha256`，含义与拆股相同。
- **原始行动身份**（T11-04）：`action_id = <source>#<row>`。同一来源文件、同一日期的多笔分红因行号不同而可区分。来源文件内容改变（哈希不同）的，旧的身份作废。
- 解析一律用 `numeric.PARSE_CONTEXT`，从 CSV 原文构造 `Decimal`，**不经过 float**。

### 3.2 Massive 行动文件的文本读取（基础设施）

新增只读函数，读 `actions/<T>_splits.csv`、`actions/<T>_dividends.csv` 的**原文**，列名按 `massive_paid_files.SPLIT_COLUMNS`、`DIVIDEND_COLUMNS`。

- 不调用现有的 `load_actions`：它产出的是 float。
- 现有文件的数值文本来自写入时的 float 表示。在回执中说明这一点；它是 D0b 要核对的数据事项，本卡不处理。
- 除权日晚于 2019-12-31 的行只计数，不解析数值（与现有封存做法一致）。封存期的行分两类处理，**都先判日期、再解析数值**，同行的数值不解析，封存常量不改（T11-08、G-T11-04）：
  - **行情、行动与日历文件**（日线、拆股、分红、交易日历）：日期晚于 2019-12-31 的行只计数并跳过，计数写入 `_dataset.json`。**这只适用于本卡的新构建入口**；现有正式读取入口（`MarketDataLoader` 等）遇到封存行即拒绝的行为不改（T11R-04）；
  - **人工配置文件**（原始价更正、核实登记）：日期晚于 2019-12-31 的行用 `assert_dates_not_sealed` 报封存越界错误，构建停止。人工登记不应出现封存期日期，不静默跳过。
- 本卡只用测试中构造的临时文件验证这些函数，**不读真实目录**。

### 3.3 公告日被遮蔽

`masked_after_2019` 含 `declaration_date` 时，表示公告日晚于 2019-12-31。而除权日不晚于 2019-12-31，所以**公告日晚于除权日**：
- 按 `DECL_NOT_PRIOR` 处理（规格第 3 节）；
- **不得**当作 `DECL_DATE_MISSING`（公告日为空）。

### 3.4 币种

现有分红文件没有币种列，`currency` 一律为 None：
- 按裁决 A-3 记 `CURRENCY_ASSUMED_USD`；
- 将来有币种列且明确不是 USD 的，记未解决问题 `CURRENCY_NOT_USD`，不计算。

## 4. 复权计算（领域纯函数，`domain/adjustment/`）

### 4.1 入口

`compute_canonical(security, bars_text, splits, dividends, calendar_days, verifications, raw_corrections, params) -> AdjustmentResult`

| 参数 | 含义 |
| --- | --- |
| `bars_text` | 原始日线文本，日期升序，已按现行 `segments` 拼接为一个证券身份 |
| `calendar_days` | XNYS 交易日序列，由应用层传入；领域层不读文件 |
| `verifications` | 核实登记（第 5 节） |
| `raw_corrections` | 原始价更正（第 6 节） |
| `params` | 见 4.2 |

`AdjustmentResult` 包括：
- 锚日；
- 逐日的 F（开高低收）、F\_V；
- 复权日志（每次行动一条）；
- 数据假设清单、未解决问题清单；
- 可表示性检查与 ATR 预检结果；
- 使用资格（`USABLE` / `NOT_USABLE`，附原因代码）。

### 4.2 参数（全部在一个冻结的数据类中，写入数据版本）

| 参数 | 值 | 依据 |
| --- | --- | --- |
| `price_lower`、`price_upper` | 0.01、10⁹，**包含两端** | 裁决 A-6 |
| `abnormal_dividend_factor` | 0.5，判异常的条件为 b\_div **< 0.5** | 裁决 A-4 |
| `fallback_max_missing_days` | 5 | 裁决 A-5（计数基准见 4.5） |
| `atr_windows` | 由应用层传入，不在领域层写死 | 4.7 |
| `gap_breaks` | 实际用于历史段与 ATR 预检的 G 取值集合；G 未登记时为 {10, 20}，**两个取值的结果分别报告** | 4.7；这不是对 G 的批准 |
| `spec_version` | `D0a-v4` | 规格 |

所有影响结果的参数都在这个数据类中，并全部写入 `_dataset.json`（7.2）。

### 4.3 规则

按规格逐节实现：
- 锚日：第 2 节；
- 可得性：第 3 节，并按裁决 A-1；
- 拆股：第 4 节；
- 分红：第 5.1 节的分组、参考价、同日口径三支、缺价区间内依次递推；
- 类型与币种：第 5.3 节，并按裁决 A-2、A-3；
- 异常：第 5.4 节，并按裁决 A-4；
- 平移：第 5.5 节；
- 资格：第 6 节；
- 数值：第 7 节。

裁决新增或明确的要点：

1. **A-1**：
   - 拆股（全部）与公告日为空的分红，记 `DECL_DATE_MISSING`，作为获批假设，可以正式使用；
   - 报告中这一类标为"获批假设，未经历史验证"（第 7 节）；
   - `DECL_NOT_PRIOR`：不可正式使用。核实登记中有 `DECL_RECORD_CORRECTED` 的，**用更正后的公告日重新判定**（T11-05）：更正日早于原始除权日的，按通过处理，日志记登记编号；等于或晚于原始除权日的，仍为 `DECL_NOT_PRIOR`。有登记编号本身不构成放行条件。
2. **A-2**：`SC` 计入，前提是金额、币种、每股单位、生效日都能按规格处理。任一不能的，按对应的未解决问题处理，**不因类型为 SC 放行**。
3. **A-4**：
   - b\_div = 0.5 不判异常；
   - 0 < b\_div < 0.5 记 `ABNORMAL_FACTOR`，不可正式使用；核实登记中有 `ABNORMAL_CONFIRMED` 的，按登记确认的金额正常计算（登记金额与输入金额不一致的，报错，不按登记值改写输入），日志记登记的裁定编号与依据；
   - b\_div ≤ 0 记 `ILLEGAL_FACTOR`，**任何登记都不能放行**；
   - 异常行动**不得跳过**、再把其余序列当作正常结果：只要有未解决的异常，该证券整体不可正式使用。
4. **A-5**：缺价替代见 4.5。
5. **A-6**：可表示性见 4.6。

### 4.4 复权日志：原始行动与计算组（T11-03、T11-04）

日志分两张表。**因子只记在计算组上**，原始行动不带因子，避免同一因子被乘两次。

**原始行动**（每条输入记录一条）：

| 字段 | 内容 |
| --- | --- |
| 身份 | `action_id`、`security`、`action_kind`、`source`、`row`、`source_sha256` |
| 原值 | `original_ex_date`、原始数值（十进制文本）、`dividend_type`、`declaration_date`、`currency` |
| 归属 | `group_id`（所属计算组；被拒绝而没有组的为空） |
| 标记 | 只属于这条记录本身的代码，例如 `DECL_DATE_MISSING`、`CURRENCY_ASSUMED_USD`、`DECL_NOT_PRIOR`；`verification_ids`（作用于这条记录的登记编号，如 `DECL_RECORD_CORRECTED`）与更正后的公告日。这些都由记录本身与登记决定，不带 e′ |

**计算组**（每个组一条）：

| 字段 | 内容 |
| --- | --- |
| 身份 | `group_id`：拆股为 `<security>|SPLIT|<原始除权日>|<row>`；分红为 `<security>|DIV|<原始除权日>|<share_unit>|<币种或 NONE>`。由输入确定，不依赖处理顺序，也不随核实登记改变（G-T11-02） |
| 成员 | 成员 `action_id` 的列表（按 `action_id` 排序） |
| 日期 | `original_ex_date`、`effective_day`（e′）。只要输入日线中存在不早于原始除权日的有效日，e′ 就有定义并照记，**被拒绝的组也照记**；只有待处理的组为空（G-T11-01） |
| 状态 | `APPLIED` / `ANCHOR_NOT_APPLIED` / `PENDING` / `REJECTED` |
| 推导 | `b`（十进制文本）；分红另记 `p`、`R_p`、k、参考价推导中乘过的组的 `group_id` 与因子、`C_ref`、`reference_is_theoretical` |
| 标记 | 组的假设代码与问题代码；所用核实登记的编号 |

- `reference_is_theoretical` 为真表示参考价不是观察值，包括缺价替代与依次递推的情形（裁决 A-5）。
- 两张表各按身份排序，用 `semantic_digest.canonical` 序列化为规范 JSON，写盘时末尾加一个换行（T11-10）。文件的哈希另用 SHA-256 计算；`semantic_digest()` 返回的是摘要值，不作为日志正文。
- **理论参考价只出现在日志中，不写入任何日线字段。**

### 4.5 缺价替代的计数基准（裁决 A-5）

**定义**：对一组分红，设 p 为 e′ 之前最近的有效日，k 为 XNYS 交易日中**严格位于 p 与 e′ 之间**的天数（这些交易日本证券都没有日线）。

| k | 处理 |
| --- | --- |
| 0 | p 是 e′ 的前一个交易日。参考价是观察值的，不记 `DIV_PREV_FALLBACK`；参考价是依次递推的理论价的（同一 e′ 上较晚的一组），**仍记** `DIV_PREV_FALLBACK`（G-T11-08） |
| 1 至 5 | 记 `DIV_PREV_FALLBACK`，日志记 k 与完整推导；获批假设，可以正式使用 |
| 大于 5 | 记 `FALLBACK_TOO_FAR`，未解决问题，不可正式使用 |
| 同一历史段内找不到 p | 记 `NO_REFERENCE_CLOSE`，未解决问题。**先判这一条**：跨历史段的，记 `NO_REFERENCE_CLOSE`，不再记 `FALLBACK_TOO_FAR`。历史段按 `gap_breaks` 中的每个 G 分别判断，结果分别报告 |

- k = 0 且参考价为**观察值**的，不记 `DIV_PREV_FALLBACK`；发生日期平移的另记 `ACTION_DATE_SHIFTED`。参考价为理论价的，按上表 k = 0 一行与下一条记 `DIV_PREV_FALLBACK`，两种标记可以并存（T11R-03）。
- 期间的拆股与更早的分红，按规格第 5.1 节换算进参考价；任何一步换算不了的，记 `UNIT_CONVERSION_FAILED`，不可正式使用。
- 依次递推产生的较晚各笔参考价，同样属于缺价替代，记 `DIV_PREV_FALLBACK`，日志中 `reference_is_theoretical` 为真；k 照实记录（可以为 0）。

**边界例子**（2015 年 3 月，期间没有节假日）：

| 编号 | 输入 | k | 结果 |
| --- | --- | --- | --- |
| B1 | p = 3 月 2 日（周一），收盘 50；3 月 3、4、5、6、9 日缺价；3 月 10 日除息 D = 1，收盘 49 | 5（3、4、5、6、9 日） | 允许：b = 0.98，F = 50.000000，记 `DIV_PREV_FALLBACK`（k = 5） |
| B2 | 同 B1，但 3 月 10 日也缺价；除权日仍为 3 月 10 日；3 月 11 日收盘 49 | 6 | `FALLBACK_TOO_FAR`，不可正式使用 |
| B3 | p = 3 月 6 日（周五），收盘 50；原始除权日为 3 月 7 日（周六），除息 D = 1.00；3 月 9 日收盘 49 | 0 | 只记 `ACTION_DATE_SHIFTED`；b = 0.98，F = 50.000000 |
| B27 | p = 3 月 6 日（周五），收盘 100；原始除权日 3 月 7 日（周六）除息 1.00，3 月 9 日（周一）除息 2.00；3 月 9 日收盘 97 | 0 | 两组都作用于 3 月 9 日：b₁ = 0.99；第二组 C\_ref = 99（理论价），b₂ = 97/99；累计 0.97，F = 100.000000。第一组只记 `ACTION_DATE_SHIFTED`；第二组记 `DIV_PREV_FALLBACK`（k = 0，理论价） |

### 4.6 可表示性检查（规格第 7 节第 4 项，裁决 A-6）

- 每根有效日线的四个 F 价，量化到 6 位之后，都必须满足 0.01 ≤ P ≤ 10⁹（**包含两端**）；
- 高低开收的关系由本卡**自行完整检查**：高 ≥ 低、低 ≤ 开 ≤ 高、低 ≤ 收 ≤ 高。现有 `audit.explicit_failures` 不查开盘（T11-07），不能直接调用了事；不改它；
- 振幅坍缩只计数。

不通过的日子记入问题清单：证券、日期、字段、值。**该证券仍保留在审计清单中**。

### 4.7 ATR 预检（规格第 7 节第 4 项）

- **窗口集合**由应用层提供，包括：
  - 生命周期参数网格中 `n` 的全部取值；
  - 当前冻结配置的 `n`；
  - `evaluation.params.ATR_PERIOD`。
  
  应用层从这些来源取值，不手写数字；测试断言该集合与这些来源一致。
- 每个历史段（按 `lifecycle.history_segments.split_segments`，G 取冻结配置），对每个窗口长度、每个历史足够的位置，用 `indicators.true_range` 的同一计算方式（`math.fsum`，同一组 float F 值）算 ATR。
- ATR ≤ 0 的，记 `ATR_NONPOSITIVE`（证券、日期、窗口长度），不可正式使用。
- **不改** `indicators.atr` 的异常保护，不补极小正数，不删日线。
- 预检若需要 G 的取值而它尚未登记（SR-M1），对 {10, 20} 两个取值都做预检，任一不通过即不可正式使用；在回执中报告。

### 4.8 截至 T 的视图与前缀不变性（规格第 10 节第 1 项，D0R-05、D0R-06）

- 新增 `view_as_of(result, T)`：从全量结果还原截至 T 的视图。**原则：每个字段都按"截至 T 能否确定"投影，不能确定的一律为空**（T11-01）。
  - **原始行动表**：原始除权日 > T 的不出现；其余保留。它的标记只含由记录本身决定的代码，截至 T 已能确定。
  - **计算组表**：
    - 原始除权日 > T 的组不出现；
    - e′ ≤ T 的组照原样；
    - 原始除权日 ≤ T 而 e′ > T（或全量中 e′ 也不存在）的组：状态为 `PENDING`，只保留身份、成员与 `original_ex_date`；`effective_day`、k、`b`、推导、组的假设代码、问题代码、登记引用一律为空。全量运行在 T 之后才得出的结论（例如 `FALLBACK_TOO_FAR`、`DIV_PREV_FALLBACK`、`ACTION_DATE_SHIFTED`）**不得**出现在截至 T 的视图中。
  - **问题清单与假设清单**：只与原始记录有关的条目本身不带 e′（4.4），所以不需要清空字段，也不会泄漏 T 之后的生效日（G-T11-01）。每条都有"决定日"。与日线有关的（可表示性、ATR 预检）是该日线的日期；与计算组有关的是 e′；只与原始记录有关的是原始除权日。视图只保留决定日 ≤ T 的条目。
  - **使用资格**是整段历史的结论，不进入前缀比较。
- **终点待处理**：原始除权日之后，这个证券再也没有有效日线的（例如除权日后退市），全量结果中该组也是 `PENDING`，按上一条的方式投影。它不作用于任何日线，不构成问题；计数单独报告。
- **前缀测试**：用 `compute_canonical` 只算截至 T 的输入（日线 ≤ T、行动的原始除权日 ≤ T），把结果整体投影为截至 T 的视图，与全量结果的截至 T 视图比较：
  - F、F\_V 的前缀逐字节相同（规范 JSON）；
  - 两张日志表、问题清单、假设清单的视图逐字节相同。
- **截断日**只取锚日及以后（G-T11-06；例如 A17 中早于锚日的候选截断日跳过），包括：
  - 每个原始除权日及其前后各一个交易日；
  - 每月最后一个交易日；
  - 缺价区间的中间日；
  - 历史断点前后；
  - 存在待处理行动的日子。
- 回执中的表述：**"在所测输入与截断日上验证了前缀不变性"**，不写"证明没有前视"。

## 8. 区间审计（规格第 9.2 节）

新增 `audit.canonical_factor_checks(bars, log)`：
- 对前后两根有效日线 (prev\_day, day]，取**计算组表**中 e′ 落在区间内的 `APPLIED` 组，各乘一次，得到预期累计因子（不按原始行动相乘，T11-03）；
- **方向**（G-T11-03）：F = R ÷ B，所以 R/F = B。核对的是 (R\_day/F\_day) ÷ (R\_prev/F\_prev) 应等于 ΔB（区间内没有 `APPLIED` 组时 ΔB = 1）。注意它与现有 `adj_factor_jumps` 的 adj/close 方向**相反**，不得照搬。
- **误差界**：R 是原始价，F 量化到 6 位，误差 ε = 5 × 10⁻⁷。允许区间为

  [(F\_prev − ε) · R\_day ÷ ((F\_day + ε) · R\_prev)，(F\_prev + ε) · R\_day ÷ ((F\_day − ε) · R\_prev)]

  ΔB 落在区间外的报告。不另加相对容差。
- **精确比较**（T11R-01）：把 F、R、ΔB、ε 都转成精确有理数（`fractions.Fraction`，由十进制文本或 `Decimal` 构造，不经过 float），用交叉乘法判断，例如下界条件写成 (F\_prev − ε) · R\_day ≤ ΔB · (F\_day + ε) · R\_prev。**不得**在 28 位或任何有限精度上下文中先算出区间端点再比较。ΔB 本身来自日志中的十进制因子，同样精确转换。

夹具 A14 必须通过。

- 只给收盘的，开、高、低都等于收盘（ATR 预检对这类短夹具不适用，因为历史不够任何窗口）。

夹具结果涉及以上默认的代码（例如拆股的 `DECL_DATE_MISSING`），按默认断言。

每个夹具除了数值，还要断言：
- 日志状态；
- 假设代码与问题代码；
- 资格。

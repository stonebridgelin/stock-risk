## 范围

### 1. 数值规范（I9；v0.4 第 2.0 节）

- `domain/numeric.py`：
  - 价格量化：输入为**文本**，按 `Decimal` 解析，`ROUND_HALF_EVEN` 量化到 6 位小数，再转为 float。非有限值、≤ 0 → `InvalidInputError`。
  - ε 比较辅助函数：≥、>、≤、< 四种，比率类（ε\_r = 1e-10）与价格类（ε\_p = 1e-9）两套，定义按 v0.4 第 2.0 节"比较定义"。
  - 复算判据函数（v0.4 第 2.0 节"复算验收判据"，比率与价格两套 abs\_tol），供以后的一致性测试使用。
  - 求和统一用 `math.fsum`，按交易日升序传入。
- ε 与容差值放在一个集中定义的参数对象中，标注"数值容差，待登记"（I6 (b)）。

### 2. 统一取数入口的处理顺序（I12）

改造 `MarketDataLoader`，供下游使用的读取路径固定为：

1. **封存检查**：文件中出现任何日期晚于 2019-12-31 的行 → 立即抛 `SealViolation`；不解析该行价格，也不先过滤后再继续。
2. 解析与量化（第 1 节）：价格字段从 CSV 文本直接量化，不经过 float 再转换。
3. 复权更正（I11，现有机制）。
4. 按观察区间截取（第 4 节）。
5. 第二次封存检查。

- `audit-raw` 保持"只报告不报错"：审计对越界行仍只计数（应为 0），不受第 1 步影响。两条路径分开，不要让审计调用会报错的读取方式。
- 更正后的复权价同样经过量化。

### 3. 交易日历（I1、I13）

- `domain/calendar.py`：由 SPY 的交易日构造交易日历（代理）；提供"前一交易日""区间内交易日"等查询。
- 独立核对：开发依赖增加 `exchange_calendars`（固定版本，写入 `pyproject.toml` 的 dev 组），取 XNYS 2008-01-02 至 2019-12-31 的交易日，与 SPY 日期集合比较。
  - 新命令 `stock-risk check-calendar`：输出两边各自多出的日期、比较的区间、SPY 文件哈希、库名与版本。
  - **有任何差异即停止**，列入回执的停止项，由产品经理裁定；不得自行改用其中一方。
- 核对代码属于验证工具，不进入 domain；domain 只使用代理日历。

### 4. 三个区间与逐日序列（I2、I3、I10）

- 每个代码计算并输出三个区间及端点类型：
  - **数据覆盖区间**：文件首日至末日。
  - **观察区间**：起点 = max(登记的 `listed_from`, 数据首日)；终点 = min(2019-12-31, 登记的 `listed_until`)。
  - **回放区间**：起点 = max(2009-01-01, 观察起点)；终点 = 观察终点。
  - 左端类型：`listing_start`（登记了上市起点且为起点来源）、`request_start`（数据首日等于下载起点 2008-01-02）、`first_available`（其余情况，标"左端覆盖未核实"）。
  - 右端类型：`LISTING_END`（由 `listed_until` 决定）、`EXPLORATION_END`（由 2019-12-31 决定）。
- 逐日序列：在观察区间内，按交易日历逐日给出"有日线 / 缺价"。首条日线之前不算缺价；**观察终点之前文件提前结束的，其后各交易日为缺价**，不得截掉。
- `listed_from` 是一个新历史段的起点（I10）：序列从这一天开始，不带入此前的价格。
- 按连续缺价天数切分历史段（G）属于生命周期第 1.2 节 A 的逻辑，**留给 T02**；本卡只提供序列。
- 研究样本角色（I15）：`config/universe_exploration.csv` 增加 `role` 列，27 只个股为 `signal_target`，14 个 ETF 为 `reference_only`；读取与校验同步更新（角色只允许这两个值）。
- 新命令 `stock-risk show-ranges`（或并入现有命令的子功能均可）：输出全部 41 个代码的三个区间、端点类型、观察区间内的缺价日数与日期，写入 `output/ranges/`，并在 04 号报告中增加一节摘要。

### 5. 指标（v0.4 第 2.1–2.3 节；I5）

- `domain/indicators.py`，全部基于复权价（I4），输入为一个历史段内按日期升序的有效日线：
  - TR、ATR\_N（简单平均，`fsum`）；ATR ≤ 0 → `InvalidInputError`。
  - SMA\_M（最近 M 个收盘，含当日）。
  - 受限窗口最高收盘与峰值日（最近 W 条有效日线，可另给起始日限制以支持 last\_release；并列取最近）。
  - 区间最低收盘及其日期（并列取最早）。
  - 最近 K 个有效交易日（不含当日）的最高收盘（BOX\_ROLL 用）。
  - R2 跳空分数：G\_t = (O\_t − C\_prev) / ATR\_N(prev)。prev 必须是交易日历上 T 的前一个交易日，且该日有日线；否则返回 `MISSING_DATA`。prev 的 ATR 不可计算时返回 `INSUFFICIENT_HISTORY`。结果对象含状态、分数、是否触发（G\_t ≤ −g 且 C\_T < C\_prev，用 ε 比较）。
  - 历史长度判定：当前历史段有效日线不足 W + N 条 → 不可计算（S21a、S21b）。
- **产品经理补充裁定 I18（签发本卡时补充，下一轮审阅时复核）**：TR 中的 C\_{t−1} 取**同一历史段内上一条有效日线**的收盘；ATR、SMA、窗口一律按"有效日线"计数，缺价日不占位。理由：规格中 W、N 都按"有效日线"计数（v0.7 第 1.3 节、v0.4 第 2.2 节）；R2 是唯一明确要求"前一交易日"的指标（v0.4 R2-06），按其规定单独处理。请把这一裁定写进 02 号或 01 号文档的指标说明。
- 指标接口（I5）：在 domain 定义生命周期引擎取数用的接口（某日的开盘、收盘、ATR\_N、SMA\_M、窗口最高与峰值日、区间最低、前一交易日状态等），两种实现：
  - 由日线计算（回放与 F 组用）；
  - 按表给定（S 组夹具用，13 号文档 S 组的"给定 ATR、给定 SMA10"）。
  - 接口的具体方法由你设计，但必须能覆盖 v0.7 第 1.2–1.3 节需要的全部量；在回执中列出接口定义。

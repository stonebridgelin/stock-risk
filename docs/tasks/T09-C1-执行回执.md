### C-02 h 窗口截短与可确定日

- **h 窗口**（`windows.py`）：`truncated_by_next` 按实际情况设置。条件是存在下一事件，且下一峰值 − 1 < k + Y\_max；恰好相等不算截短。
- **归段**（`membership.attribute`）：可确定日为空时一律返回 NEITHER（R2-03）。
- **S2 窗口的核对**：S2 不存在"实际被截短、却不是 D 类"的情形，不触发停止条件。理由如下：
  - 下一事件的峰值日是不晚于数据终点的有效日，所以下一事件界 b = 下一峰值 − 1 ≤ 数据终点 − 1；
  - 实际被截短即 b < Ω\* 终点。这时观察终点 = min(Ω\*, 数据终点, b) = b，而数据终点 > b，所以按 D-24 判为 D 类；
  - C 类（数据终点 ≤ b）只在没有下一事件时出现。

  测试 `test_s2_truncated_windows_are_class_d` 在 B15、B15e、B35、B36、B22 上逐个核对：被截短的 S2 窗口都是 D 类，且 `truncated_by_next` 为真。
- **可确定日为空的表达**：可以用现有的 NEITHER 表达，不触发停止条件。
- **测试**（`tests/unit/evaluation/test_c1_windows.py`）：
  - 归段的五种情形，期望值按卡上的表；
  - **A04 回归**：
    - 本事件的标签可确定日为第 354 日；
    - 下一事件的峰值为第 354 日，所以 t\_h = 353，小于 109 + 252，窗口被截短；
    - 下一事件的标签不可确定，所以 h 指标的可确定日为空，归段为 NEITHER。
  - **构造用例**：
    - **构造方法**：在 A04 的 381 条日线之后接第 381 日，开 40、高 50.5、低 39.5、收 50。
    - **T 的推导**：下一事件（峰值第 354 日，C\_p = 50）进行中。第 381 日 C = 50 ≥ C\_p，按 17 号第 2.2 节 (a) 回到峰值结束，并当日确认，所以 **T = 381**。
    - **前序事件**：事件 0 在第 354 日确认，不晚于 T。
    - **期望**：h 指标的可确定日 = max(354, 381) = **381**，按公式计算；测试同时断言下一事件确认日为 381，确认构造的前提成立。

**复用规则，按请求类别分别判断**：

| 类别 | 是否可复用 |
| --- | --- |
| 原始日线 | 可以，须同时满足下列七项条件 |
| 拆股 | 可以，须同时满足下列七项条件 |

| 复权日线（诊断） | 可以，条件同原始日线；只作诊断，不进入构建 |

**七项条件**：
1. 代码与 2.1 的分段一致；
2. 请求范围覆盖 2.1 的 `range`，以进度文件中记录的请求参数为准，不以文件首末行推断；
3. **请求成功，所有分页都已取完**：以进度文件中该请求的状态为准，状态不是成功且完整的（包括 `incomplete`），不复用（DB-01）；
4. 每行 `source_host` 为 `relaynex.vip`（T08d-2c 判定通过的主机）；
5. 日线为 `adjusted=false` 的原始价（诊断用的复权日线为 `adjusted=true`）；
6. 文件哈希与进度文件、运行记录一致，没有事后改动的迹象；
7. 文件中没有晚于 2019-12-31 的行（有的话停止，按封存冲突报告）。

**空的行动**：拆股为零条，只有在进度文件中有"成功、完整、零条记录"的请求，且文件为合法表头时，才算"确实没有拆股"。文件缺失、请求失败或未完成，一律列入缺口。

### 2.3 补取工具

新增命令 `fetch-massive-d0b`：

- **输入**：`identity.csv` 与缺口清单；只请求缺口。
- **请求**：都经中转服务 `relaynex.vip`，用 `MASSIVE_ADVANCED_API_KEY`，按现有 `massive_source_host` 规则。

  | 类别 | 路径与参数 | 用途 |
  | --- | --- | --- |
  | 原始日线 | aggs，`adjusted=false`，范围为该段的 `range` | 构建输入 |
  | 复权日线 | aggs，`adjusted=true`，同一范围 | **只作诊断**（规格第 1.3 节），存在单独的子目录 |
  | 拆股 | `/v3/reference/splits` | 构建输入 |
  | 分红 | `/v3/reference/dividends` | 构建输入 |

  拆股与分红用旧路径，因为 T08d-2c 判定：`/stocks/v1/` 路径在中转服务上返回 404。
- **请求身份与账本**（DB-02）：
  - 请求身份 = (主机, 类别, 源代码, 请求起止日, `adjusted`)；
  - 每个请求分别记：状态（成功 / 失败 / 未完成）、页数、行数、封存过滤数、输出文件哈希；
  - "完成"指成功且分页取完；跳过、已完成数、剩余数共用这一个判定；
  - 账本格式新建，不直接套用 `fetch_batch` 的按代码记录方式。
- **保留原文**（DB-06、G-D0b-01）：
  - 数据路径：响应 → 新模块中的原文记录（数值字段为字符串）→ 文件。全程不构造 `massive_paid` 的对象，不调用 `float()`；
  - **在首次解码 HTTP 响应正文时**就保留数字原文（例如 `json.loads(text, parse_float=str, parse_int=str)` 一类的专用解析），不得先用默认解析得到 float 再转字符串（DBr-01）。理由：原文 `1.00000050000000001` 经默认解析变成 `1.0000005`，量化到 6 位后分别是 `1.000001` 与 `1.000000`；
  - **日期遮蔽**（DBr-03）：拆股按执行日、分红按除息日判断整行是否保留；保留的分红中，公告日、登记日、派息日晚于 2019-12-31 的，写为空，并在 `masked_after_2019` 中记字段名，与现有 `seal_dividend` 的规则相同；
  - 解析响应时，数值保留**原文文本**（例如 JSON 解析时以字符串保留小数），写入文件的就是原文，不经过 float；
  - 分红文件增加 `currency` 列：响应中有币种字段的，写原值；**响应中确实没有这个字段的，写空**，并在账本中记"来源无币种字段"。规范读取器据此区分"明确 USD""明确非 USD""来源缺失"三种情形。
- **封存**（DB-10）：
  - 请求的结束日期晚于 2019-12-31 的，**拒绝发出**（沿用 `check_price_range`）；
  - 响应中出现晚于截止日的行，在写文件之前过滤，计入账本，**不进入文件**。
- **运行前**：打印主机、代码清单、每类请求的次数与预计总次数，要求输入 `yes`。`--dry-run` 只打印计划，不联网。
- **断点续传**：已完成的请求不重发。
- **输出格式**：
  - 日线、拆股：与 `massive_paid_files` 相同；
  - 分红：在 `massive_paid_files` 的列之后加 `currency`。
- **测试**（只用假传输）：
  - 只请求缺口；结束日不晚于 2019-12-31；响应中的封存行被过滤并计数；
  - `yes` 确认；`--dry-run` 不联网；断点续传；错误主机拒绝；
  - "原始日线完成而复权日线未完成""拆股完成而分红失败"时的续传；
  - 分红币种为 USD、非 USD、字段缺失三种响应，**端到端**到规范读取器，分别得到：正常、`CURRENCY_NOT_USD`、`CURRENCY_ASSUMED_USD`；
  - 数值原文保留：从**原始 JSON 响应文本**开始，经下载文件到规范读取器，端到端测试 `1.00000050000000001` 与科学计数法（如 `1e-7`、`2.5E+3`）的原文不变（DBr-01）；
  - 日期遮蔽：2019 年除息、2020 年派息的分红保留，派息日遮蔽并记标记；公告日越界的分红记 `DECL_NOT_PRIOR`，不得记成 `DECL_DATE_MISSING`（DBr-03）。

### 2.6 规范输入层的三项补充

这三项都在应用层与存储层完成，**不改** `domain/adjustment/`。

1. **完整性**（DB-01）：
   - 输入快照中有 `INPUTS_STATUS.json`：每个代码、每类请求（原始日线、拆股、分红）的状态与文件哈希。
   - `build-canonical` 读入它。任何一个证券的任何一类不是"成功且完整"，或文件缺失、哈希不符的，**停止构建**（`CanonicalBuildError`），不得把缺失读成空。
   - 测试：不完整的行动文件（即使哈希正确）、行动文件缺失、合法的空行动，三种情形分别得到：停止、停止、正常。
2. **上市期间**（DB-04）：
   - 构建输入按"上市期间 ∩ 请求范围"截取。日线与行动都截取：行动按原始除权日，早于首根日线的按锚日行动规则处理，晚于上市止日的不进入输入；
   - **截取区间**（G-D0b-02）：`effective_range = [max(2008-01-01, 上市起), min(2019-12-31, 上市止)]`。
   - **顺序**：先按代码分段（`seg.contains`）过滤各段的源文件，再对合并后的日线与行动按 `effective_range` 截取。截取数在分段过滤之后统计，不把分段之外的行与区间之外的行混在一起。
   - 早于区间起点或晚于区间止点的日线与行动，**不进入**复权计算，分别计数。例如 `/v3/reference/splits` 返回的 KO 1987 年拆股，属于区间之前，直接截掉。
   - 落在区间之内、原始除权日不晚于锚日的行动（例如 2008-01-01 节假日除权、锚日为 2008-01-02），保留，按既有的锚日与平移规则处理。
   - **记录**（G-D0b-04）：`_dataset.json` 的 `config` 下增加 `listing_periods_sha256`、`inputs_status_sha256`；`securities[<代码>]` 下增加 `listing_clipped: {"bars": n, "splits": n, "dividends": n}`。
   - **与下游一致**（G-D0b-03、DBr-02），分两项核对，不一致的，停止：
     - **日线**：规范数据经 `MarketDataLoader.load` 读取后，日线的日期与全部字段与规范数据完全一致，没有被二次截掉；
     - **行动**：现有规范读取路径返回空的行动序列（行动只在 `.adjlog.json` 中），这是既定契约，**不得**为通过检查往信号读取路径补行动。改由独立的审计路径读取输入行动与复权日志，核对原始行动、计算组、生效日与待处理状态。原始除权日早于观察区间起点、已按锚日规则处理的行动，不计入这项比较。
3. **日历**（DB-05）：
   - `build-canonical` 把 `--calendar` 文件复制到版本目录，文件名 `_calendar.csv`，列入 `MANIFEST.sha256`；
   - 规范模式的读取器从 `_calendar.csv` 取交易日历，不从 SPY 日线生成；
   - 旧数据模式不变，仍用 SPY 代理；
   - **不得**为满足旧接口伪造 SPY 文件，也不得为此扩大 ETF 的构建范围。

### 2.7 映射一致性（DB-03）

P1 结束前，用构建器的映射逻辑（`symbol_segments.csv` 加默认规则）对 27 只证券各打印一次实际使用的源代码与区间，与 `identity.csv` 逐行比较：

- **不得**用改文件名的方式绕过（例如把 `SNE_raw.csv` 改名为 `SONY_raw.csv`）。

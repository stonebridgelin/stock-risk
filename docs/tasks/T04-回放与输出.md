## T04b 12 组参考候选的输出

- 参考候选：N = 20、k₁ = 2、k₂ = 4、K = 3、d = 3、u\_rel = 3 × 12 种结构组合（I7），用 T02 的网格编号标识。
- 命令：`stock-risk replay --candidates reference12|all [--symbols ...]`。
- **运行清单（I16）**：每次运行生成唯一 run\_id 与 `run_manifest.json`，内容按 I16 全部字段。由 infrastructure 读取 git 提交号并检查工作区是否干净；**工作区不干净时，运行清单标 `run_kind = debug`**；干净时标 `formal`。
- 输出目录 `output/replay/<run_id>/`，按 run\_id 分开，不覆盖。每个候选、每只个股一套：
  - `events.csv`：日期、事件类型、业务身份、等级前后、转移编号、原因、证据集合（含计数段每日证据）、当日数值。
  - `daily.csv`：直接写出引擎的诊断记录（03 计划 T04b 的固定字段），加 run\_id、候选编号列。
  - `episodes.csv`：每次预警一行，字段按 03 计划 T04b（启动、最低收盘、首次企稳、首次恢复观察、降级、解除或截尾的日期与价格；恢复观察、撤销、恢复失败、加重次数；终止原因；持续交易日数）。
  - `chart.html`：收盘价（复权）、状态色带（关注、警戒、数据中断、不可计算）、事件标记（悬停显示事件与依据）、L\_ep、确认线、强恢复门槛线、更正与缺价标注；副图为 D\_T / D\_ep，以及 SPY、QQQ 的 63 日回撤（从取数入口读 SPY、QQQ，注明"大盘背景只作参照，未应用背景标签"）。
- 图表用 plotly 生成（新增运行依赖，固定版本）。plotly 脚本以 `include_plotlyjs="directory"` 方式在 run 目录下共用一个本地文件，图表离线可看，不依赖网络，也不在每个文件里重复内嵌。
- `index.html`：按个股 × 候选列出全部图表链接，并附每只个股的预警次数，便于浏览。
- **验收**：
  - [ ] 12 组 × 27 只个股的四种输出全部生成（SHLD 两套口径）
  - [ ] 一致性：同一事件在 events、daily、episodes 与图表中的日期一致（程序检查，不靠人工）
  - [ ] 不变量检查器 0 违反
  - [ ] 正式运行（`run_kind = formal`）一次，在回执中给出 run\_id

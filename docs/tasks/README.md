# 任务卡与回执约定

任务卡由产品经理签发，编码助手（Claude Code）执行，发起人负责转发。一张任务卡对应一个可验收的工作单元。

## 编码助手执行一张任务卡时

1. 先读 `CLAUDE.md`、`docs/develop_docs/README.md`，以及任务卡"必读"中列出的文档。
2. 只做任务卡"范围"内的事。觉得范围外还有应该做的事，写进回执的"建议"，不要顺手做。
3. 遇到以下情况，**停止该部分**，写进回执，不自行决定：
   - 规格歧义，或规格条款之间矛盾；
   - 规格的夹具或示例与实现结果不一致；
   - 需要一个规格没有给出的业务数值；
   - 需要修改 `domain/seal.py` 的封存常量。
4. 完成后确保 `uv run pytest`、`uv run lint-imports`、`uv run ruff check .` 全部通过。
5. 同步更新 `docs/develop_docs` 中受影响的文档，并在 `00-变更记录.md` 加一条。
6. 在本地提交，提交说明以任务编号开头（例如 `T00: 仓库卫生与数据审计`）。**不推送。**
7. 输出回执（格式见下）。

## 回执格式

```
## 回执 Txx <任务名>

### 完成情况
- [x] / [ ] 逐条对应任务卡"验收"中的每一项

### 改动
- 新增 / 修改的文件，一行一个，附一句话说明

### 验证
- pytest：N 通过 / N 失败
- lint-imports：通过 / 不通过
- ruff：通过 / 不通过
- 其他验证（命令与结果摘要）

### 停止项（需要产品经理裁定）
| 编号 | 位置（规格条款 / 夹具 / 文件） | 问题 | 规格值 | 实现值或现状 | 我的理解（不作为决定） |

### 偏离任务卡之处
- 没有则写"无"

### 建议（范围外）
- 没有则写"无"

### 提交
- commit hash 与说明
```

## 范围

### 1. Git 卫生

- 如果 `.env` 仍在 Git 索引中，执行 `git rm --cached .env`（**只撤出索引，不删除文件**）。
- `.gitignore` 中把 `.idea/workspace.xml`、`.idea/shelf/` 两行改为整个 `.idea/`，并 `git rm -r --cached .idea`（如已被跟踪）。
- 检查全部提交历史，确认没有 `.env` 或任何密钥：`git log --all --oneline -- .env`，并用 `git grep` 在所有提交中搜索 `TIINGO_API_KEY=`、`FRED_API_KEY=`、`MYSQL_VERIFY_URL=` 后面跟着非空值的情况。**发现泄露时立即停止**，在回执中报告，不要尝试改写历史。

### 2. 多代码分段拼接（D1）

- 现状：`config/universe_exploration.csv` 的 `source_candidates` 只支持"依次尝试，取第一个有数据的代码"。
- 需求：一个证券可以由多个数据源代码按日期分段拼接，例如 VRX：`VRX` 到 2018-07-13，`BHC` 自 2018-07-16 起。
- 设计要求：
  - 分段信息放在配置文件中（建议新建 `config/symbol_segments.csv`：`symbol,source_ticker,from,to,note`）；没有分段配置的代码保持现有行为。
  - 拼接在 application 层用例中完成，拼接规则（日期不重叠、按日期排序、拼接后无重复日期）放在 domain 层并有单元测试。
  - 拼接处检查：前一段最后一个收盘与后一段第一个开盘的比值、复权系数（adj\_close / close）的变化，结果写入审计输出。
  - 保存文件仍为 `data/raw/VRX.csv`；`README.txt` 与 `_fetch_status.json` 记录各段的代码与区间。
- 执行：补下载 BHC 2018-07-16 至 2019-12-31，生成拼接后的 VRX。

### 3. 上市期间配置（D2、D3）

- 新建 `config/listing_periods.csv`：`symbol,listed_from,listed_until,venue,source_url,verified_on,note`。
- 只登记需要截断的代码：SHLD、WFT（交易所退市日）、SMH（新产品的起始日，如果核实为不同证券）。日期必须来自可查证的来源，优先使用 SEC 文件（Form 25、8-K）、交易所公告或发行人公告，`source_url` 填原始链接。
- **找不到可靠来源时，该行留空并在回执中列为停止项，不要估计日期。**
- 原始数据不做截断（`data/raw` 保持数据源原样）；上市期间只在审计和以后的回放中使用。domain 层提供"按上市期间截取"的纯函数和测试。

### 4. 审计命令 `stock-risk audit-raw`

对 `data/raw` 中每个代码检查并输出：

| 检查 | 规则 |
| --- | --- |
| 明确失败（v0.4 §2.0） | 非有限值；高 < 低；收盘不在 \[低, 高\]；价格 ≤ 0。原始价和复权价分别检查 |
| 复权系数跳变 | adj\_close / close 相对前一日变化超过 2%，且当天没有公司行动记录 |
| 交易日缺口 | 以 SPY 的交易日为日历，在该代码首条和末条日线之间缺少的交易日（上市期间配置生效时，以上市期间为界） |
| 零成交量 | 成交量为 0 的天数与日期 |
| 拼接点 | 第 2 项的拼接检查结果 |
| 封存 | 任何晚于 2019-12-31 的行（应为 0） |

- 输出：`output/audit/<日期>/` 下的明细 CSV 与 `summary.md`。
- 分层：检查规则在 domain（纯函数），文件读取在 infrastructure，编排在 application，命令在 interfaces。
- 审计只报告，不修改任何数据。

### 5. 核实 D3、D4

- D3：核实 SMH 在 2011 年前后是否为不同的证券（例如 HOLDRS 转为 ETF），写明来源；确认是不同证券的，在上市期间配置中登记新产品的起始日。
- D4：SHLD 2018-03-28 复权系数跳变。查找当天是否有公司行动（分拆、配股等），写明结论与来源；查不到就写"原因未明"，不修改数据。

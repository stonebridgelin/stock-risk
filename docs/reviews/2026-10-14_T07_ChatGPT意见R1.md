**总体结论：通知负担下降、部分事件通知变晚，都有数据支持；但当前摘要尚不宜用于正式裁决。** 需要先修正覆盖表述、解除质量的解释，以及两处专项统计。阻断针对T07定稿和据此作出的正式结论，不否定已验收的生命周期引擎。

### T7-Q1：有条件同意——分类和主要数字正确，名称需要收窄。【阻断：否】

独立核对得到：

| 类别 | 数量 |
| --- | ---: |
| 同日通知 | 76 |
| V3通知更晚，V0通知当日V3没有预警 | 83 |
| 通知更晚，但V0通知当日V3已有预警 | 6 |
| V3通知更早 | 18 |

83个事件的等待中位数5日、通知日收盘之间额外下跌中位数约4.317%、VRX最大约22.368%，均能复现。

需要修改三点：

1. **称为“示意事件内首条新通知更晚”，不要统称“首次预警推迟”。** 83个中，80个是START对START，另3个的V0通知是ESCALATE，V0此前已经有预警。
2. 这组统计以V0有新通知的183个事件为分母；其余7个事件另列。本次核对，两套有新通知的事件集合一致，没有因集合变化漏掉比较。
3. 83个中有3个属于上限或其他截尾事件，应同时报告完整事件子集的敏感性结果，避免将暂定谷底当成确定结果。

额外跌幅还应明确采用“两个通知日收盘之差”，并补充等待区间内的最低收盘，防止中途急跌后反弹被端点差掩盖。

### T7-Q2：有条件同意改善现象，反对直接宣称“解除更可靠”。【阻断：修正后方可定稿】

**① “190段大跌都覆盖到”不正确。**

实际结果是：

| 指标 | V0 | V3参考 |
| --- | ---: | ---: |
| 区间内有预警 | 189/190 | 189/190 |
| 有新通知 | 183/190 | 183/190 |
| 谷底日在场 | 188/190 | 189/190 |

FB 2012年上市初期仍未覆盖。06号表格基本正确，但转述摘要必须同步纠正。

此外，这190个包含截尾及上限事件。应分开呈现完整事件与全部示意事件，不能把结果推广为一般性的“大跌照样覆盖”。

**② 解除后跌破自身低点的比例可以描述，但不是同一条件下的质量比较。**

核对到的20日完整窗口为：

| 参考规则 | 跌破自身L_ep次数 | 完整窗口解除数 | 比例 |
| --- | ---: | ---: | ---: |
| V0 | 468 | 1501 | 31.2% |
| V3 | 176 | 841 | 20.9% |

数字正确。但变化同时包含：

- 解除事件集合不同；
- 预警切分不同；
- L_ep的位置不同；
- 解除时点和价格不同；
- 未解除、窗口不完整的数量不同。

特别是**新预警低点更低，本身就可能使“再次跌破自身低点”更难发生**。

建议改为：

> V3已解除预警中，20日内跌破各自预警低点的观察比例较低；尚不能将全部差异归因为解除规则更可靠。

同时补充相对解除收盘的后续跌幅分布、完整/不完整窗口数、未解除数量，并在共同事件或可配对预警子集上对照。配对子集的排除数量也要报告。

**③ “取消752次加重”包含20次仍在警戒。**

752条记录中，新规则当日状态为：

- 正常274次；
- 关注458次；
- **警戒20次。**

这20次没有新的升级事件，但已处于警戒，不能当作风险提示被取消。应将“缺少同日ESCALATE事件”与“当日没有警戒覆盖”分开；后者为732次。

### T7-Q3：有条件同意L路径提供了新增覆盖，反对当前延续性结论。【阻断：60日统计须修正】

103次L启动、其中93次V0当日正常，能够复现。但它们是**预警事件数，不是103段独立漏报**，同一股票可能反复出现。

更关键的是，L专项表丢失了窗口完整标记，把以下不足60日的结果也放进“60日最低收盘”分布：

| 股票与启动日 | 实际可观察后续有效交易日 |
| --- | ---: |
| WFT 2019-02-19 | 57 |
| WFT 2019-03-25 | 33 |
| WFT 2019-04-04 | 25 |
| BBBY 2019-11-01 | 40 |

仅保留99个完整60日窗口，中位数约为 **−12.7%**，不是当前的−15.8%。这不推翻方向，但必须修正。

建议为所有专项后续路径统一输出窗口完整性、已观察天数及终止原因。

“多数时候提醒的是仍在进行的下跌”也应收窄为：

> 在这些历史L启动样本中，随后观察到进一步下跌；完整60日窗口的最低收盘分布如下。

最低收盘只说明期间曾进一步下跌，不能单独说明走势持续下行、提醒净收益或误报程度。应同时报告期末收盘、途中最高收盘，以及V0后续何时提供预警。

若要估计**启用L本身的净贡献**，还需参考取值下、其他设置相同的L关闭对照。目前X1/X2配对回答的是门槛选择，不是有无L路径。

### T7-Q4：有条件同意部分探索方向，不建议直接批准全部正式取值

| 裁决项 | 我的意见 |
| --- | --- |
| B1：L采用X1 | **有条件同意保留为优先探索方向**。先修正窗口统计，并区分新增覆盖与独立补漏 |
| B2：跳空不加下限 | **同意**。现有配对显示负担收益小，存在较大等待损失 |
| B3-a：8%还是10% | **倾向8%**。但这是两档之间的取舍，不代表已证明8%相对V0的延迟可以接受 |
| B3-b：15%还是20% | **倾向15%**，作为待裁决业务取值保留 |
| B3-c：恢复缩放暂不采用 | **有条件同意**。整体副作用值得重视，但长期挂起仍是核心未解决问题 |
| B3-d：接受首次通知变晚 | **不建议整体批准**。先逐例看VRX、TSLA、BP等损失最大的路径，再与低波动股减负一起权衡 |
| B3-e：先分层再定所有门槛 | **反对作为统一前提**。投递负担和信号质量需要分别约束，见Q5 |

还有一处需要修正的事实判断：

**“V3、V4没有不涨即解除”的统计解释不成立。**

目前专项筛选使用“解除收盘≤启动收盘”。按这个条件，参考组合中：

- V3有28次L预警；
- V4有39次L预警。

这不自动表示算法错误。例如先继续下跌，再从更低位置恢复，解除价仍可能低于启动价，但恢复证据真实成立。

因此应区分：

1. 解除收盘不高于启动收盘；
2. 旧a′支持的、缺乏相应价格恢复证据的解除。

当前V1合计1400次的筛选条件只能证明第一件事，不能全部称为“不涨即解除缺陷”。应复核原因和路径后重新分类，也不能因此删除合法的b′解除结果。

### T7-Q5：有条件同意规划投递分层，但不应将问题全部交给投递层

恢复观察、撤销频繁发生，首先源于确认条件反复成立与失效。汇总可以减少打断，**不会改变信号反复本身**。

而且系统每天收盘后只计算一次：若不同日期各产生一次消息，改成“每日汇总”未必明显减少实际打扰。应先统计同批次合并后，究竟减少多少条送达消息。

建议下一步顺序为：

1. 修正本轮统计和过度结论，先完成重大损失案例复盘。
2. 分别定义信号负担与投递负担：F、占用率继续约束算法；送达条数、重复内容约束投递。
3. 再规划收盘批次合并、重要状态变化与进展信息的呈现方式。
4. 高波动股反复和长期挂起继续作为算法问题跟踪。

**当前可以认可的是“减负有改善，但及时性存在明确损失”；还不能认可“覆盖已全面保证、解除可靠性已证明”。** 建议先完成上述处置，再请你作正式参数裁决。

# D0b 裁定：SONY 的 Massive 源代码映射（PM-D0b-01）

产品经理 · 2026-10-18 · 依据：T12-D0b 第 2.1、2.7 节；Claude Code P1 停止报告（SONY 在中转服务上按 `SONY` 返回 0 行）

## 裁定性质

这是**同一证券的数据源代码映射**，不改变研究样本、不增删证券、不扩大范围，属于产品经理的技术裁定。发起人可以否决。

## 事实

- Sony 的美国存托凭证在 NYSE 的代码，2021-04-01 起由 `SNE` 改为 `SONY`（MIAX 公司行动通知，2021-03-31：https://www.miaxglobal.com/alerts/2021/03/31/miax-exchange-group-options-markets-corporate-action-alert-sony-corporation-sne ，产品经理 2026-10-18 访问）。本项目范围 2008-01-01 至 2019-12-31 全部早于这次改名。
- 本地证据：`verify/prices_SONY.csv` 中，中转服务按 `SONY` 返回 0 行；Tiingo 按 `SONY` 有 2516 行（Tiingo 按现代码回溯历史，Massive 按当时代码）。
- 研究样本 `source_candidates` 已列 `SONY|SNE`。

## 裁定

**PM-D0b-01**：SONY 在 Massive 上的源代码，2008-01-01 至 2019-12-31 整段为 `SNE`。

## 落实方式

1. Claude Code 先核对 `config/symbol_segments.csv` 是否也被旧数据（Tiingo，`data/raw/`）的读取路径使用。
   - **不被使用**：在 `symbol_segments.csv` 中加一行 `SONY,SNE,,,` 加说明（引用本裁定），单独提交。
   - **被使用**（改动会让旧数据去找 `SNE`，破坏旧结果的复现与确定性测试）：**不改** `symbol_segments.csv`。改为新增 `config/massive_source_tickers.csv`（列：`symbol,source_ticker,from,to,ruling,note`），只由 `fetch-massive-d0b` 与 `build-canonical` 读取；它的哈希进入 `_dataset.json`；旧数据路径不读它。这一项属于 T12-D0b 允许修改的输入与装配层。
2. 第 2.7 节的映射比较，以落实后构建器实际使用的映射为准，重新比较。
3. 不得用改文件名的方式代替（例如把 `SNE_raw.csv` 改名为 `SONY_raw.csv`）。

## 下载后的核验条件（P3）

- `SNE` 的原始日线应覆盖 2008-01-02 至 2019-12-31，交易日数与 XNYS 日历相符（缺价另报）；
- 双源对照中，`SNE`（Massive）与 `SONY`（Tiingo）的原始收盘在共同日期上一致（差异超过 0.01 的天数单独报告）。

任一项明显不符（例如行数为 0、只覆盖部分年份、价格系统性不同），停止并报告，不按本裁定继续构建。

### G-T8b-1：关于 C-01 与 C-02 的关闭核查

**结论：有条件同意。【阻断：是，限 C-01 的两处新结构陷阱与 C-02 的正式组合约束遗漏】**

1. **已解决的部分**：
* **C-01（旧三陷阱）**：第 2.1–2.2 节已将 `E_atr` 开始后的度量改为冻结 `A_s = ATR₂₀(s)`，结束条件 `R` 加入了相对谷底的真实价格收复比例 `(C_j − L_j) / (C_p − L_j) ≥ ρ_end`，受限窗口 `H_j` 包含了 `e_prev`，并规定了 252 日硬上限与“上限延续”单列报告。这解决了“底部横盘 73 日假结束”和“谷底恐慌 ATR 放大假结束”。
* **C-02**：第 1 节实现了探索集（27 只）与选参集（标普 500 全量历史成分剔除探索集同发行人）的隔离；第 6 节将全部门槛与 H1 纳入验证期必检项；第 5.2 节将 `x₁、x₂、h` 纳入相邻稳健性。


2. **尚未关闭的阻断项（C-01 的两处新陷阱 + C-02 的组合约束遗漏）**：
* **陷阱 1（第 2.1 节第 119 行、第 2.2 节第 148 行）：恢复高点 `M_j` 无滚动窗口限制，单日冲高回落后横盘会将事件永久锁死至 252 日上限 `(c)**`。
* **依据与反例**：第 2.1 节定义 `ℓ_j` 为达到最低收盘 `L_j` 的最近一日，`M_j = max{ C_k : ℓ_j ≤ k ≤ j }`（自谷底起的**无界运行最高价**），第 2.2 节要求连续 10 日同时满足 `R` 与 `Q（V_j = 1 − C_j / M_j < T / 2）`。
* 设 `E_pct`（`T = 20%`）：第 1 日峰值 `100` → 第 2 日跌至谷底 `50`（`L_2 = 50, ℓ_2 = 2`）→ 第 5 日反弹冲高至 `92`（仅 1 日，`q < 10` 未结束）→ 第 6 日至第 252 日回落并一直横盘在 `80`。
* 在第 6–252 日（整整 247 个交易日），股价已收复 `100 → 50` 跌幅的 **60%**（`R = (80 − 50)/(100 − 50) = 0.60 ≥ 0.50` 天天成立），且连续 247 日完全横盘无任何恶化；但因 `80 > 50`，`ℓ_j` 始终停在第 2 日，`M_j` 永久钉死在第 5 日的 `92`，导致 `V_j = 1 − 80 / 92 = 13.04% ≥ 10% = T / 2` 恒不成立！事件无法按 `(b)` 结束，被迫挂起满一年直至第 252 日以 `(c)` 结束。
* **修改建议**：`Q` 用于检验“近期未再恶化”，其高点锚应当同时受恢复锚 `ℓ_j` 和短期滚动窗口（如 20 日或 63 日）约束，即 `M_j^(Q) = max{ C_k : max(ℓ_j, j − W_Q + 1) ≤ k ≤ j }`（例如 `W_Q = 20` 或 `63`），而待确认期的并入或新事件搜索仍可用区间最高价。


* **陷阱 2（第 2.2 节第 154–158 行、第 170 行）：待确认期并入条件 ②（`V_j ≥ T`）在未跌破暂定谷底 `L_e` 时，会将独立的二次大跌彻底吞入评价盲区**（详见下条 **G-T8b-2 ①** 的反例证明）。
* **正式组合约束遗漏（第 5.2 节第 341–346 行 vs `src/stock_risk/domain/lifecycle/params.py` 第 124–133 行）**：
* **依据**：第 5.2 节第 1 条“正式组合约束”只列了 4 条（`long_path ≠ OFF ⇒ release_hyst = EFFECTIVE`、`x₂ > 0 ⇔ t11_full = ON`、`x₂ > 0 ⇒ x₁ > 0`、`0 < h < 1`），漏掉了 `10` 号第 1A.1 节及 `params.py` 已实现的另外 3 条硬约束：**`long_path = X1 ⇒ x₁ > 0`**、**`long_path = X2 ⇒ x₂ > 0`**、**`r2_floor = ON ⇒ x₁ > 0`** 以及 **`x₂ > 0 ⇒ x₂ > x₁ > 0`**（而不仅是 `x₁ > 0`）。
* **后果**：第 5.2 节第 5 条规定“违反正式组合约束的相邻候选跳过”。若不把上述约束完整写入第 5.2 节第 1 条，当候选取 `long_path = X1` 且 `x₁` 处于最小正网格值（相邻值为 `x₁ = 0`）时，其相邻候选 `(long_path = X1, x₁ = 0)` 不会被跳过，而是直接在引擎构造时抛出 `IllegalCombination` 或因语义退化导致稳健性判定失败。





### G-T8b-2：状态机、四类结果、S2 分母表与 H1 的严密性核查

**结论：反对直接定稿。【阻断：是，存在 4 处漏判、错判或口径冲突】**

1. **【阻断】第 2.2 节（第 154–158、170 行）：待确认期的并入条件 ②（`V_j ≥ T`）与统计区间 `[p, 报告谷底)` 不相容，会吞没未破前低的二次暴跌**
* **依据与反例**：第 2.2 节规定每个事件的统计区间为 `[p, 报告谷底)`（第 170 行），其中 `报告谷底` 是 `[p, e]` 内达到最终最低收盘 `L_e` 的最早一日（第 120 行）。在待确认期（`e` 之后 20 日内），只要触发条件 ② `V_j ≥ T`（从恢复高点 `M_j` 再跌满一个开始阈值 `T`），就并入原事件，峰值不变。
* 设 `E_pct`（`T = 20%`）价格路径：
* 第 1 日峰值 `100`（`p = 1`），第 2 日暴跌至 `50`（`s = 2, L = 50`）；
* 第 3–12 日反弹并横盘于 `90`（收复 80%，满 10 日安静计数，第 12 日暂定以 `(b)` 结束，`e = 12, M_12 = 90`）；
* 第 15 日（待确认期 `w = 3`）从 `90` 暴跌 **25%** 至 `67.5`：因 `V_15 = 1 − 67.5 / 90 = 25% ≥ 20%`，命中并入条件 ②，并入原事件；
* 第 16 日反弹至 `100`，原事件在第 16 日按 `(a)` 结束（`e = 16`）。


* **后果**：因为二次暴跌的低点 `67.5 > 50`（未跌破第一次谷底 `50`），并入原事件后，原事件的 `报告谷底` **仍然停在第 2 日（`50`）**，统计区间 `[p, 报告谷底)` 仍是 `[第 1 日, 第 2 日)`；同时原事件结束日被推迟到第 16 日（`e_prev = 16`），下一事件只能从第 16 日起搜索。结果是：**第 12–15 日发生的 `90 → 67.5`（跌幅 25% 的独立暴跌）既不在原事件的 `[p, 报告谷底)` 内，也无法形成第二个事件，在 S1 与 H1 评价中彻底消失！** 若某候选在第 12 日解除预警，并在 `90 → 67.5` 的 25% 暴跌中完全漏报，其 S1 仍为 0、H1 仍判不违反。
* **修改建议**：只要评价区间定义为 `[p, 报告谷底)`，**任何未刷新原谷底 `L_e` 的二次下跌都不能并入原事件**。应当将待确认期的并入条件只保留 **① `C_j < L_e`（跌破暂定谷底）**；若待确认期内未跌破 `L_e`，原事件在 `e` 的结束成立，且下一事件的搜索从 **`e + 1`（原事件结束日 `e` 的次日，而非确认日的次日）** 开始。这样若二次下跌最终跌破 `L_e`（在 20 日内）则并入原事件并更新谷底；若未跌破 `L_e` 但跌幅 `≥ T`，则自动从恢复高点 `M` 独立成为第二个事件。


2. **【阻断】第 3 节（第 195、205–207 行）：`C（持续覆盖）` 与 `N（新通知）` 的判定优先级及状态口径导致 `ESCALATE` 成为死分支，并产生“提前解除反而得分更高”的反向激励**
* **依据与数学证明**：
* 第 195 行定义 `在警` 为“关注或警戒”；第 205 行定义 `C` 为“同一预警的 `START < p`，且在 `[p, 报告谷底)` 的每一日都日末在警”，得 `S1 = 0`；第 206 行定义 `N` 为“**不属于 C**，且 `[p, 报告谷底)` 内有 `START` 或升至警戒的 `ESCALATE`；取第一个，日期记 `f`”。
* 问：什么时候 `[p, 报告谷底)` 内的第一个向上事件会是 `ESCALATE`？
只有当该次预警在 `p` 之前就已经 `START`（即 `START < p`），且在 `[p, f]` 期间一直处于 `关注` 状态，到第 `f` 日才升至 `警戒（ESCALATE）`！
* 但请注意：
* **情形甲（正常持续到谷底）**：若该预警在第 `f` 日 `ESCALATE` 后，一直持续到 `报告谷底` 未解除，则它满足“`START < p` 且在 `[p, 报告谷底)` 每一日都日末在警（前段关注、后段警戒）”，**直接命中第 205 行的 `C`（得 `S1 = 0`）**，根本不会进入第 206 行的 `N`！即便它在大跌 19.9% 的谷底前一天才从关注升为警戒（甚至整个 20% 暴跌期间一直挂着降级后的 `关注` 从未升至 `警戒`），也一律拿满分 `S1 = 0`！
* **情形乙（谷底前提前解除的劣质路径）**：若同一预警（`START < p`，在 `p` 日之后第 `f` 日 `ESCALATE`）**在谷底之前提前 `RELEASE` 且不再报警**，它因为没有持续到谷底而**不满足 `C**`，此时反而落入第 206 行的 `N`，憑借第 `f` 日的 `ESCALATE` 获得 `N` 类高分（例如 `f = p` 时 `S1 = 0`）！对比夹具 13（第 550 行）：“峰值日在警、谷底前终止、未再提醒记 `U`（`S1 = 1`）”——如果峰值日前已是 `警戒`、谷底前解除，记 `U（S1 = 1）`；但如果峰值日前是 `关注`、峰值日当天 `ESCALATE`、次日就在半山腰解除，却记 `N（S1 = 0）`！




* **修改建议**：
1. **严防“谷底前终止却拿 N 分”**：无论 `C` 还是 `N`，若触发 `f` 的那次预警在 `报告谷底` 之前终止（`RELEASE` 或 `DATA_BREAK`），且 `[f, 报告谷底)` 内没有再次进入在警状态并维持到谷底，不能直接按早期 `f` 给低 `S1`（更不能让 `START < p` 且半途解除的预警靠 `ESCALATE` 逃避夹具 13 的 `U` 判定）。至少应规定：**`START < p` 的同一预警若在 `[p, 报告谷底)` 内终止且未再启动新预警，一律记 `U`（不能靠终止前的 `ESCALATE` 记 `N`）**。
2. **区分持续 `警戒` 与仅维持 `关注**`：对于严重下跌事件（`E_pct` 20% 大跌），`C（S1 = 0）` 应要求同一预警 `START < p`、在 `[p, 报告谷底)` 每一日都在警，**且在 `p` 日之前已处于 `警戒`（或从未降级为仅 `关注` 跨越整个事件）**；若 `p` 日处于 `关注`，在 `[p, 报告谷底)` 内第 `f` 日才通过 `ESCALATE` 升至 `警戒` 并持续到谷底，应归入 `N`（按 `f` 计算 `S1`）或单独报告其 `ESCALATE` 延迟，而不能与峰值前就已处于 `警戒` 的情形无差别同记 `S1 = 0`。




3. **【阻断】第 3 节（第 208 行）与第 5.2 节（第 348 行）：将全部截尾事件在保守口径下一刀切记为 `U（未提醒）`，会导致即使 100% 及时预警的候选也无法通过保守口径门槛 `m**`
* **依据与反例**：第 208 行规定截尾事件“主口径不计；**保守口径记 U**（`S1 = 1`）”，第 348 行规定门槛“**主口径与保守口径都要满足**”。
* 事件是否截尾（如遇到 `2019-12-31` 期间终点、成分退出后第 252 日人为终点、退市或区间内有 1 天缺价）完全由行情数据决定，与候选无关。设某右端截尾事件在 `2019-10-15` 见顶、`2019-11-20` 跌至 `-25%`（暂定谷底 `k*`），因到 `2019-12-31` 尚未完成确认而标为截尾；某候选早在 `2019-10-18`（跌幅 3%）就已发出 `START` 并一直保持 `警戒` 到 `2019-12-31`。
* 尽管该候选**千真万确已经发出了预警**（且在 `[p, k*)` 内已确定覆盖），第 208 行在保守口径下仍将其强行记为 **`U（未提醒）`**！若选参集中因期间终点、人为终点（第 1.1 节第 81 行）、退市和缺价导致的截尾事件占总事件数的 5%，而探索集拟定的未提醒率门槛 `m = 3%`，则**哪怕一个每天都在报警的候选，其保守口径未提醒率也至少为 5% > m，全部候选 100% 不合格**。
* **修改建议**：对截尾事件的保守口径，应与第 4 节 H1 的右端截尾逻辑（第 298–300 行）对齐：

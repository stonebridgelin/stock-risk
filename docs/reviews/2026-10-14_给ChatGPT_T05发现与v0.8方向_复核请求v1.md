## 2. v0.8 改动草案（B）

### 设计目标

1. 预警对应的是**值得提醒的下跌**，而不只是"相对自身波动的异常"。
2. 一段持续的下跌**尽量是一次预警**，而不是多次"启动—解除"。
3. 解除表示风险**确实缓解**，不因下跌途中的一次反弹就解除。
4. 保持现有的生命周期结构、冻结基准、证据记录与无前视性质；夹具 S1–S22、F1–F5 尽量只需增补，不推翻。

### D-01 启动与警戒改为"双条件"（解决 F-01、F-02）

- 启动：D\_T ≥ k₁ **且** DD\_T ≥ x₁，其中 DD\_T = 1 − C / P^max（受限窗口最高收盘），x₁ 为百分比下限。
- 警戒：启动当日 D\_T ≥ k₂ 且 DD\_T ≥ x₂；关注期间的加重条件 T9 改为 D\_ep ≥ k₂ 且 DD\_ep ≥ x₂，DD\_ep = 1 − C / P\_ep。
- 含义可以对用户直接说清楚："跌幅既超过该股平时波动的 k₁ 倍，也达到了 x₁%"。对高波动股，ATR 条件更严，起作用的是 ATR 条件；对低波动股，起作用的是百分比条件。
- x₁、x₂ 作为新的候选维度，候选值暂拟 x₁ ∈ {8%, 10%}、x₂ ∈ {15%, 20%}。这几个数值目前只是起草方的初拟，请评论取值范围；正式数值在冻结前登记。
- R2（跳空）：单独触发启动时同样要求 DD\_T ≥ x₁。理由：R2 也以 ATR 为单位，低波动股 3 个 ATR 的跳空只有 3–4%。**请评论这一点是否会使 R2 失去意义**（它原本是为财报跳空等急跌准备的，那类跳空通常同时满足 x₁）。

考虑过、暂不采用的做法：

- 只提高 k₁：ATR 归一化的频率趋同仍在，只是整体变少；低波动股的大跌（若有）会更晚。
- 用长期波动率（如 252 日）代替 ATR₂₀：同样是相对自身波动，问题性质不变。
- 按个股历史回撤分位数设门槛：同样会把各股的预警频率拉平。

### D-02 解除的"回到原位"条件加回滞（解决 F-05 的一部分）

- a′ 改为：D\_ep < k₁ **且** DD\_ep < h × x₁，h 为回滞系数，初拟 h = 0.5（探索假设）。
- 理由：D-01 之后，启动要求 DD ≥ x₁；若解除只要求回到 x₁ 以内，价格在 x₁ 附近上下就会反复启动、解除。回滞是状态机里防抖动的标准做法。
- b′（强恢复）不变。

### D-03 解除后的再启动（解决 F-05 的另一部分）——两个备选，请评论

现状：解除后受限窗口只取 last\_release 及之后的日线（G-11），新的 P^max 就是反弹高点。

- **备选 1（不改规则，只改表达）**：保留 G-11。D-01 之后，再启动需要从反弹高点再跌 x₁，频率应已大幅下降；另外在事件依据中记录"距上次解除 n 个交易日"与"是否低于上次的 L\_ep"，投递层把"解除后 Q 日内再启动"标为"重新预警"。
- **备选 2（合并）**：解除后 M 个有效交易日内再次满足启动条件的，不新开预警，而是"重新打开"上一次预警：沿用原 P\_ep、ATR\_ep、L\_ep 与 episode\_id，发 REOPEN 事件，last\_release 恢复为上一次的值。这样一段下跌在数据上就是一次预警。代价是新增事件类型、身份规则与夹具，而且已经发出的"解除"无法撤回。

我的倾向是**先做备选 1**，在 D-01、D-02 落地后的回放中再看碎片化还剩多少；若仍严重，再做备选 2。请评论这个顺序是否合理，以及备选 2 是否有我没想到的问题（例如与 G-11 的原意冲突）。

### D-04 强恢复的尺度随价格缩放（解决 F-08）

- 现状：U = (C − L\_ep) / ATR\_ep，强恢复门槛为 C − L\_ep ≥ min(u\_rel × ATR\_ep, φ × (P\_ep − L\_ep))。ATR\_ep 以绝对价格计，冻结在峰值附近。
- 修改：恢复侧使用按价格缩放的 ATR：ATR\_rec = ATR\_ep × L\_ep / P\_ep（即启动时的"ATR 占价格比例"作用在当前低点上）。U 与强恢复门槛中的 ATR\_ep 改为 ATR\_rec；回撤侧（D\_ep、a′、加重）仍用 ATR\_ep。
- 影响：浅跌时 L\_ep / P\_ep 接近 1，几乎没有变化；只有大跌后才明显。以 VRX:2015-12-28 为例（P\_ep 118.47，ATR\_ep 6.99，L\_ep 8.51），u\_rel = 3 时门槛从低点上方 20.96（+246%）变为 1.51（+17.7%）。
- 请评论：这样会不会让崩盘后的解除过早？我的看法是，解除后若再跌 x₁ 就会重新启动（D-01），用户收到的是一条新的、有当前依据的预警，比一条挂了四年的预警更有信息量；但这一点需要回放验证。

### D-05 评价协议增加"不应报警"的约束（解决 Q-T05-6）

- 10 号第 5.9 节的占用率门槛（目前"是否作为门槛待批准"）建议改为**必须的门槛**。
- 新增描述指标"浅预警率"：最大跌幅（P\_ep 到 L\_ep）低于 y% 的预警占比；y 待登记。是否作为门槛，请评论。
- 现有的 F（向上事件频次）门槛保留，按个股分组报告（低波动 / 中 / 高，以开发期 ATR/价格的三分位划分），避免整体中位数掩盖低波动股的问题。
- 这些门槛的数值需要发起人从产品角度给出（例如"低波动股每年最多几次预警可以接受"），不由起草方决定。

### D-06 候选网格的调整（请评论）

D-01、D-02 新增 x₁、x₂（及 h 是否进网格）。如果全部加入，候选从 768 增加到 3072 组以上，选参的乐观偏差随之增大。可选做法：

- (a) 全部保留，接受更大的网格，靠门槛、稳健性和全量报告约束；
- (b) 把探索中影响很小的维度固定下来（例如 N：两个取值的占用率相差 0.001、次数相差 1%），腾出位置给新维度。

我的倾向是 (b)，只固定 N = 20，其余维度不动，因为 N 的固定理由是"对结果几乎没有影响"，而不是"某个取值表现更好"。请评论这是否构成看结果后删减的问题。

### D-07 不改动的部分

生命周期的状态、步进顺序、计数四阶段（E-01）、缺价处理（E-02）、解除原因口径（E-03 / I21）、冻结基准（除 D-04 的恢复侧缩放）、业务身份、无前视检查、封存，全部不变。

### 落地方式（供参考）

收敛后：10 号升为 v0.8；13 号新增覆盖 D-01、D-02、D-04（以及 D-03 备选 2，如果采用）的夹具，期望值由起草方手算并请你复算；签发 T06（实现与重新回放），回放结果再做一次复盘。

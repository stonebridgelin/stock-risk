## 2. 本轮复现与量化的证据

### 2.1 缺陷复现（容器副本，代码同设备工作区）

**建议 F-01**：前 100 日收盘 100，之后在第 101 日跌到 60，然后按下表收尾；G = 10，T = 20%。

| 情形 | 当前输出 | 结论 |
| --- | --- | --- |
| 第 103 日缺价（k\* = 101 之后），再收两日 70 | 截尾 {RIGHT\_DATA\_END}，不可评估 ∅，前缀完整 True | **错** |
| 最后两日缺价（尾部缺价 ≤ G） | 同上 | **错** |
| 缺价落在 k\* 之前 | 截尾含 RIGHT\_DATA\_END，不可评估 {MISSING}，前缀完整 False | 对 |

为什么错：k\* 是已观察有效日中的最低收盘。k\* 之后的缺价日可能有更低的收盘，所以暂定谷底不确定，不应进入 H1 的暂定谷底口径。

**建议 F-02**：A29b 在 t = 124 时，后继事件的确认日是 124，但它的标签可确定日是 140。按"确认日 ≤ t"比较必然失败；按"标签可确定日 ≤ t"比较是 D-14 的本意。

**建议 F-03**：在调用方精度 8 的上下文中，`quantize_price("123.456789")` 抛出 InvalidOperation。

**建议 F-04**：`parse_finite("1e10000")` 返回 inf。

**建议 F-05**：`decimal_price` 用 assert 校验。正常运行时抛出 AssertionError；在 `python -O` 下这项校验被关掉，函数静默返回 1.123457。

**建议 F-06**：`fetch_batch` 只按状态跳过已完成的代码，不记录请求区间和身份。复用旧目录扩大区间时，会漏下载。

**建议 F-07**：`discrete_digest` 只覆盖日期、展示、等级、episode\_id、cycle\_no 和事件键。

**建议 F-08 至 F-11**：已核实不成立：
- CLI 只经 bootstrap、config 导入；
- `blocking_problems` 覆盖缺失或空的 MANIFEST；
- `_finite` 与 `_positive_int` 拒绝 bool；
- `_box_high` 检查非 BOX 模式。

## 4. 核心判断

### 4.1 影响三个目标的前三个问题

**1. 评价可信度：评价模块尚未闭合。**

建议 F-01、F-02 使"前缀完整"与"可确定日期"这两个 H1 的基础都可能出错，而 H1 本身还从未被测量过。06 号的所有结论仍是描述性的。

处置：先完成 E1R，再完成 E2–E6，然后才谈规则效果。这一项排第一，因为后面每一项结论都依赖它。

**2. 及时预警：v0.8 的首条新通知变晚了，这是已经测到的代价。**

06 号显示：在示意事件中，有 83 个的首条新通知变晚，中位数晚 5 个交易日，两个通知日的收盘之间多跌 4.3%。

建议稿的 A 系列都不针对这一点。A-01 只影响 25 个 START，A-02 对参考候选没有影响。

真正决定及时性的是启动路径与 x₁、x₂（T08c 的阈值回溯），而这要用 E2 的 H1 与 S1 来衡量。

**3. 及时解除：下跌途中的解除与谷底后的滞后，二者是相互牵制的。**

- 05 号 F-05：52% 的事件在谷底前至少解除过一次。V3 下仍有 85 个。
- 05 号 F-06：谷底后的解除中位数在谷底后 16 个交易日。

建议稿的 A-05 处理的是进度消息的反复（负担），不是解除时点。A-02 在 d = 3 时也没有作用。

解除质量要等 E2 的 S2、h\_tail 和解除后不利变化测出来，再设计规则。现在改规则，没有判据。

### 4.2 证据不足的新增内容

以下各项目前没有项目内的证据支持，复杂度也没有被收益抵消：
- A1-c 双低点：1513 次中只有 3 次相关；
- A-02 分别计数：没有混合证据的解除；
- A-04 深跌尺度：只有个别崩盘；
- E-01 整体策略框架；
- 在没有 profile 的前提下做的 E-03、E-04 性能工作；
- R-02 至 R-05；
- 期权指标组合；
- G-05、G-06。

这些不算未完成任务。它们保留状态与理由，等证据出现再重开。
